## 一、后端必须新增或覆盖的内容

<mark>以下内容是本次新增/修改，旧部署没有，必须处理。</mark>

2. `ZCL_AI_SQL_EXECUTOR`
3. `ZCL_AI_DDIC_TOOLS`

### 2. 覆盖 8 个 ABAP 类

以下类使用仓库当前版本全量源码覆盖，不要只复制新增方法：

1. `ZCL_AI_TOOL_REGISTRY`
2. `ZCL_AI_AGENT_GUARD`
3. `ZCL_AI_DOMAIN_CARDS`

### 3. 激活顺序

<mark>必须按依赖顺序激活，激活失败不要跳过。</mark>


### 4. 新建审计表

SE11 新建 `ZAI_SQL_LOG`，字段见原有后端文档或 `功能计划书/OPUS计划/SE11对象与配置清单_20261005.md`：

```text
QUERY_ID     CHAR 40   主键
USERNAME     CHAR 12
SQL_TEXT     STRING
STATUS       CHAR 10   OK / ERROR / REJECTED
RESULT_ROWS  INT4
ERROR_MSG    STRING
SESSION_ID   CHAR 40
CREATED_AT   CHAR 14
```

技术设置：交付类 A、数据类 APPL0、大小分类 0，然后激活。

### 5. 用户表和配置表

建议给 `ZAI_CHAT_USER` 增加 `SQL_ALLOWED CHAR 1`，给允许动态 SQL 的 IT 用户填写 `X`。

<mark>用户登录字段是 `USERID`，不是 `USERNAME`。</mark>

在 `ZAI_CHAT_CFG` 维护：

```text
SQL_ANALYSIS_ENABLED = X
SQL_MAX_ROWS         = 5000
SQL_MAX_EXEC         = 5
AGENT_MAX_ROUNDS     = 10
AGENT_BUDGET_SEC     = 180
```

如果已有旧配置 `AGENT_MAX_ROUNDS=4` 或 `AGENT_BUDGET_SEC=60`，修改或删除。

### 6. Basis 需要确认

<mark>Agent 预算已是 180 秒，ICM、Web Dispatcher、反向代理的超时必须至少 200 秒。</mark>

## 二、前端必须重新构建和上传的内容

<mark>本次后端和前端代码都发生过变化，不能继续使用旧 dist 或旧 BSP 包。</mark>

### 1. 构建前检查

确认 `webapp/config.js`：

```js
mode: "backend",
host: "",
path: "/sap/opu/odata/sap/ZAI_CHAT_SRV/",
ui5Src: "./resources/sap-ui-core.js"
```

### 2. 重新构建

在项目根目录执行：

```bash
npm install
npm run build
```

确认以下文件存在：

```text
dist/index.html
dist/config.js
dist/resources/sap-ui-core.js
dist/Component-preload.js
```

### 3. 重新打包

```bash
cd dist
zip -qr ../zai_chat_dist_动态SQL_20261005.zip . -x "*.map"
```

打开 ZIP 后，第一层必须直接看到 `index.html`，不能多一层 `dist/`。

### 4. BSP 上传

按原 [04-前端实施文档](04-前端实施文档.md) 的 SE38 流程上传：

```text
报表：/UI5/UI5_REPOSITORY_LOAD
模式：Upload from ZIP
BSP：ZAI_CHAT_DEMO1（以目标系统实际名称为准）
Package：可传输开发包，不能使用 $TMP
```

上传完成后确认 SE09 请求包含 `R3TR WAPA <BSP应用名>`，并重新激活 BSP 的 SICF 节点。

## 三、部署后的新增验收

### 动态 SQL

- [ ] 关闭 `SQL_ANALYSIS_ENABLED` 时，动态 SQL 请求被提示“未开启”；
- [ ] `search_tables` 可以搜索业务表；
- [ ] `describe_table` 返回字段；
- [ ] `run_sql` 前先成功 `describe_table`；
- [ ] 已知表名可以跳过 `search_tables`，但不能跳过 `describe_table`；
- [ ] Trace 显示 `describe_table → run_sql → final`；
- [ ] `ZIDPPP_TEST01` 能按工厂统计工单数量；
- [ ] `DELETE`、`UPDATE`、敏感表 `USR02` 均被拒绝；
- [ ] `ZAI_SQL_LOG` 有成功和拒绝记录。

### 前端

- [ ] 页面打开不是演示模式；
- [ ] 普通聊天正常；
- [ ] Agent Trace 能看到 SQL 步骤；
- [ ] SQL 原文可以展开；
- [ ] 数据集表格能显示；
- [ ] 浏览器 Ctrl+F5 或无痕窗口确认没有旧缓存。

## 四、部署顺序（一句话版）

<mark>先后端，再前端；先激活，再验收；验收通过后再释放传输请求。</mark>

```text
SE11 ZAI_SQL_LOG
  → SM30 配置与用户授权
  → SE24 激活 11 个类
  → SICF/OData 验证
  → npm run build
  → /UI5/UI5_REPOSITORY_LOAD 上传 BSP
  → SICF 激活前端
  → 动态 SQL + 安全用例验收
  → SE09/STMS 传输
```

## 五、出现问题时的紧急处理

只关闭动态 SQL，不影响普通对话和库存功能：

```text
ZAI_CHAT_CFG
SQL_ANALYSIS_ENABLED = 空
```

前端问题回滚旧 BSP 包；后端问题恢复旧 ABAP 类源码后按依赖顺序重新激活。
