### 〇-A.5 管理员 Agent 测评部署与验收

本批前端新增 `webapp/utils/AgentEval.js`、`webapp/model/evalCases.json`、`webapp/view/EvalDialog.fragment.xml`，并在 `SettingsDialog.fragment.xml` 增加仅管理员可见的“测评”页签。它们必须随本次 `dist` 一起上传，不能只传场景条的几个 JS 文件。

1. 构建前确认题库文件在产物中：

   ```bash
   node --check webapp/utils/AgentEval.js
   test "$(node -e "const x=require('./webapp/model/evalCases.json'); console.log(x.cases.length)")" = "29"
   npm run build
   test -f dist/model/evalCases.json
   test -f dist/utils/AgentEval.js
   test -f dist/view/EvalDialog.fragment.xml
   ```

2. 上传并刷新后，用管理员登录“设置”。应看到“测评”页签和“打开 Agent 测评”按钮；普通用户用同一浏览器退出重登后不得看到该页签。测评窗口应显示场景下拉（全部/REPORT/DATA/INVENTORY/CODE/AUTO）、模型、每题次数、清理测试会话，以及开始/停止/导出/导入按钮。
3. 内置题库状态必须显示版本 `20261011`、29 题和各场景题数。后端 metadata 没有 `Scene` 时，状态栏必须明确说明 `requiresScene` 题会跳过；不能把这些题的“跳过”显示为“通过”。
4. 先用旧后端跑一遍并导出 Markdown/JSON 基线，再完成后端部署后重跑。相同题库/模型/次数下，比较通过率、跳过数、错误/超时/协议错误、平均轮数、平均/最长耗时和工具被拒次数。报告中必须能看到失败原因和失败回答前 600 字，JSON 中必须能追溯每轮工具状态。
5. 选择“测完删除测试会话”时，题目完成后历史会话不应残留测试会话；测评中点击停止应显示“当前题完成后结束”，不会并发启动下一题。导入题库只接受有有效 `turns` 的 JSON，格式为 `{cases:[{scene,turns,expect}]}`；非法 JSON/空题库必须提示并保持原题库。

前端测评只是验收工具：REPORT 题只走参数卡，不提交真实后台作业；DATA/CODE 的真实工具调用仍受 ABAP 端权限、对象白名单和 `USER_HIDE_SRC` 约束。演示模式的结果来自内置示例，不能作为 SAP 部署通过依据。

## 二、构建

```bash
npm install        # 仅首次/依赖变化（内网无外网：拷现成 node_modules）
npm run build      # ui5 build --all --clean-dest，产物 dist/，约 1.5~8 分钟
```

- `--all` 会把 UI5 1.130 运行时 + 双主题库整个打进 `dist/resources/`（ui5.yaml 已声明 framework）——**部署后不依赖公网 CDN、不依赖服务器内置 UI5 版本**；
- 内网构建机离线方案：把交付包 `02_部署产物/ui5框架缓存_复制到_C盘用户目录.zip` 解压到 `C:\Users\<用户>\.ui5\`（框架缓存，约 7600 文件）。

### 构建纪律（实踩过的坑）

1. **补丁晚于 dist 构建 = 服务器跑旧代码**（09-04 事故实锤）——改代码必须重跑 build 并校验 preload；
2. **并发构建互相覆盖 dist**：启动前 `pgrep -f "[u]i5 build"` 确认无存活进程（`[]` 防自匹配），等进程退出且日志出现 `Executing cleanup` 才算完成；杀进程用 `pkill -f "[u]i5 build"` 模式；
3. `pkill -f "ui5 build"` 不带 `[]` 会匹配到自己。

### 构建产物自检（3 检查点）

| # | 检查 | 方法 |
|---|---|---|
| 1 | UI5 运行时随包 | `dist/resources/sap-ui-core.js` 存在（缺了=构建没带 framework） |
| 2 | highlight.js 随包 | `dist/thirdparty/hljs/highlight.min.js`、`abap.min.js` 存在 |
| 3 | 配置正确 | 打开 `dist/config.js`：host 空、ui5Src=./resources/sap-ui-core.js |

### 补丁标记校验（改过前端代码必做）

UI5 实际优先加载 **dist/Component-preload.js**（不是 webapp 源码）。注释版本号会被压缩器剥掉，要用**值字符串/属性访问**当标记：

```bash
# V8.1 标记（_fetchCsrf 出现次数，期望 4）与 V8.3 标记（.Login 属性访问，期望 3）
rg -o "_fetchCsrf" dist/Component-preload.js | wc -l
rg -o "\.Login" dist/Component-preload.js | wc -l
```

⚠️ `rg -c` 是匹配行数（dist 单行文件恒为 1），必须 `rg -o | wc -l` 数出现次数。

## 九、备选部署方案与依赖说明（答疑）

- **方案 B（静态服务器 nginx/IIS）**：dist 放独立 VM，反代 `/sap` 到网关（保留路径前缀），config.js host 留空走同源反代；需额外申请 VM/域名/证书/端口放通。前端代码零改动，公司统一门户要求时再迁；
- **Node.js**：仅构建时需要，部署产物纯静态，服务器不装 Node；
- **UI5 运行时**：随包自带方案已与服务器版本彻底无关；唯一仍依赖服务器的是 ICF 登录；
- **浏览器**：Chrome/Edge 近两年版本（fetch/AbortController/CSS :has），不支持 IE11；
- **dist 瘦身**（传输受限时，删了没法本地调试）：删全部 `*.map` 与 `*-dbg.js`；删 `resources/sap/ui/test`、`sap/ui/commons`、`sap/ui/ux3`、`sap/tnt`、`sap/ux`；⚠️ 不要动 `sap/ui/core`、`sap/m`、`sap/ui/layout`、`sap/ui/unified`、`sap/base`、`thirdparty/` 与两套 theme 目录。
