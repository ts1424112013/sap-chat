## 〇、全链路总览（一张图记住整个流程）

### <mark>本次前端必须重新构建和上传</mark>

本次后端和前端代码都发生过变化，不能继续使用旧 `dist` 或旧 BSP 包。后端激活并验证 OData 后，再执行本节的前端构建。

构建前确认 `webapp/config.js`：

```js
mode: "backend",
host: "",
path: "/sap/opu/odata/sap/ZAI_CHAT_SRV/",
ui5Src: "./resources/sap-ui-core.js"
```

在项目根目录执行：

```bash
npm install
node --check webapp/controller/App.controller.js
node --check webapp/service/ChatService.js
node --check webapp/utils/Formatter.js
npm run build
```

确认以下文件存在：

```text
dist/index.html
dist/config.js
dist/resources/sap-ui-core.js
dist/Component-preload.js
```

打包时第一层必须直接是 `index.html`、`config.js`、`resources/`，不能多一层 `dist/`：

```bash
cd dist
zip -qr ../zai_chat_dist_动态SQL_20261005.zip . -x "*.map"
```

使用现有 SE38 `/UI5/UI5_REPOSITORY_LOAD` 流程上传到目标 BSP 应用，Package 使用可传输开发包，禁止 `$TMP`。上传后确认 SE09 包含 `R3TR WAPA <BSP应用名>`，并重新激活 BSP 的 SICF 节点。

```
【家里/有网机】                       【公司机(有 SAP GUI)】
改代码 → git commit → npm run build
              │             ├→ 自检 dist（3 检查点 + preload 补丁标记）
              │             └→ 打 zip（第一层 = 文件本身）
           git tag           │
              │              ▼
              └──拷 zip──→ SE38 /UI5/UI5_REPOSITORY_LOAD 上传
                            （弹工作台请求 → 填/建 SE09 请求号）
                              ▼
                            浏览器打开 URL 验证（Ctrl+F5）
                              ▼
                            SE09 释放 → STMS 导入测试/生产库
                              → 每环境 SICF 重新激活
```

一句话：**代码管在 git 里，部署只认 zip，SAP GUI 里只做"上传 + 激活 + 传输"三件事。**

两种部署节奏：

| | 全量部署 | 增量部署（日常改前端推荐） |
|---|---|---|
| 场景 | 首次 / 大版本 | 日常改几个文件（如只改 ChatService.js） |
| zip 内容 | 整个 dist（约 8600 文件 / 31MB） | 仅变更文件（保持相对路径） |
| 上传耗时 | 约 2 小时（⚠️ 耐心，别关窗口） | 12 个文件 ≈ 一两分钟 |
| 获取清单 | 直接打全量包 | `diff -rq` 新旧 dist 目录 → 变更文件清单 |

## 一、构建前配置自检（30 秒，防 90% 部署事故）

打开 `webapp/config.js`（构建后 dist/config.js 才是部署生效的那份），确认五个值：

```js
mode: "backend",                        // 后端模式（探测失败自动降级演示）
host: "",                               // ★ 部署进 SAP 同域必须留空！填了反而跨域
path: "/sap/opu/odata/sap/ZAI_CHAT_SRV/",
ui5Src: "./resources/sap-ui-core.js",  // ★ 随包自带 UI5（内网部署命根子）
ui5Theme: "sap_horizon"
```

⚠️ 最常见翻车点：`host` 填了开发机地址（如 `http://sapgls4dev...:8000`）。同源部署 host 必须空串。

## 二、构建

```bash
npm install        # 仅首次/依赖变化（内网无外网：拷现成 node_modules）
npm run build      # ui5 build --all --clean-dest，产物 dist/，约 1.5~8 分钟
```

- `--all` 会把 UI5 1.130 运行时 + 双主题库整个打进 `dist/resources/`（ui5.yaml 已声明 framework）——**部署后不依赖公网 CDN、不依赖服务器内置 UI5 版本**；
- 内网构建机离线方案：把交付包 `02_部署产物/ui5框架缓存_复制到_C盘用户目录.zip` 解压到 `C:\Users\<用户>\.ui5\`（框架缓存，约 7600 文件）。

### 构建纪律（实踩过的坑）

1. **补丁晚于 dist 构建 = 服务器跑旧代码**（09-04 事故实锤）——改代码必须重跑 build 并校验 preload；
2. **并发构建互相覆盖 dist**：启动前 `pgrep -f "[u]i5 build"` 确认无存活进程（`[]` 防自匹配），等进程退出且日志出现 `Executing cleanup` 才算完成；杀进程用 `pkill -f "[u]i5 build"` 模式；
3. `pkill -f "ui5 build"` 不带 `[]` 会匹配到自己。

### 构建产物自检（3 检查点）

| # | 检查 | 方法 |
|---|---|---|
| 1 | UI5 运行时随包 | `dist/resources/sap-ui-core.js` 存在（缺了=构建没带 framework） |
| 2 | highlight.js 随包 | `dist/thirdparty/hljs/highlight.min.js`、`abap.min.js` 存在 |
| 3 | 配置正确 | 打开 `dist/config.js`：host 空、ui5Src=./resources/sap-ui-core.js |

### 补丁标记校验（改过前端代码必做）

UI5 实际优先加载 **`dist/Component-preload.js`**（不是 webapp 源码）。注释版本号会被压缩器剥掉，要用**值字符串/属性访问**当标记：

```bash
# V8.1 标记（_fetchCsrf 出现次数，期望 4）与 V8.3 标记（.Login 属性访问，期望 3）
rg -o "_fetchCsrf" dist/Component-preload.js | wc -l
rg -o "\.Login" dist/Component-preload.js | wc -l
```

⚠️ `rg -c` 是匹配行数（dist 单行文件恒为 1），必须 `rg -o | wc -l` 数出现次数。

## 三、打包与搬运

### 3.1 打 zip（最容易做错的一步）

**要求：zip 打开后第一层直接是文件本身**（能看到 index.html、config.js、resources/…），**不能多套一层 dist/ 目录**——上传报表按 zip 内相对路径建 BSP 对象，多一层页面就 404。

```bash
cd dist && zip -qr zai_chat_dist_部署包_日期_Vx.x.zip . -x "*.map"
```

（PowerShell：`Compress-Archive -Path dist\* -DestinationPath xxx.zip -Force`；资源管理器：进 dist 内部 Ctrl+A 右键压缩。）
打完打开 zip 自检一眼：第一层是 index.html ✓ 才合格。

### 3.2 增量包制作

```bash
# 新旧两个 dist 解包目录对比，得到变更文件清单
diff -rq dist_old dist_new
# 只把变更文件按 dist 内相对路径打 zip（如 service/ChatService.js 在包内就是这个相对路径）
```

参考：V8.3 增量包共 12 个文件（Component-preload、controller、service 的正式/调试副本 + resources 若干），4MB。

## 四、SAP GUI 上传（SE38 报表 /UI5/UI5_REPOSITORY_LOAD）

1. SE38 → 输入 `/UI5/UI5_REPOSITORY_LOAD` → F8；
2. 选择界面：
   - **SAPUI5 Application** = 应用名。手册示例 `ZAI_CHAT`；**当前生产实际为 `ZAI_CHAT_DEMO1`**（⚠️ 结尾有 1）——按目标环境实际值填，首次会提示"应用不存在"→ 选**创建**，描述随意（如"AI 对话助手前端"）；
   - **Upload / Download** = **Upload from ZIP**（几千文件逐个传会慢死）；
   - **Zip file**：⚠️ **路径框直接手敲** `C:\xxx.zip`——**别用浏览按钮**（它只能选文件夹，选 zip 报"无法使用文件夹"）；文件放 C 盘英文短路径；
   - Package 选**可传输开发包**（⚠️ 绝不能 $TMP，否则进不了 SE09 请求）；
3. 执行 → 弹**工作台请求**：没有就 F5 创建（类型 K 工作台请求，描述如"AI 助手前端 V8.3"，Target=本开发库）；有未释放的旧请求可直接复用；
4. 等待：全量约 2 小时 / 增量 12 文件一两分钟，**别关窗口**；中途弹"对象已存在，是否覆盖" → 是（更新本来就要覆盖）；
5. 完成后 SE09 里该请求应包含 **`R3TR WAPA ZAI_CHAT_DEMO1`** 及一批 `LIMU O2 ...` 对象——看到它 = 前端已是 SAP 正式对象。

### 上传常见报错

| 报错 | 原因与处置 |
|---|---|
| ZIP 上传到一半失败/超时 | ICM 限制，让 Basis 查 `icm/HTTP/max_request_size_MB`（建议 ≥100）；或先瘦身 |
| "Object ... already exists" | 选覆盖（更新场景正常） |
| 提示无开发权限 | SU01 缺该包 S_DEVELOP → 找 Basis 开通或代传 |
| 传完 SE09 没有 WAPA 对象 | 上传时选了 $TMP → 删掉重传到可传输包 |
| 中文文件名选不中 | Big5 GUI 的坑：zip 用英文短名放 C 盘，路径手敲 |

## 五、SICF 激活与传输

1. SICF → 逐层展开 `default_host → sap → bc → ui5_ui5 → sap → zai_chat_demo1` → 右键**激活**（首次上层 `ui5_ui5` 未激活会提示连带激活，确认即可——标准节点不影响系统）；
2. 双击节点 → "登录数据处理"标签页 → **过程 = Standard**（首次打开弹 SAP 标准登录，SU01 账密）→ 保存；
3. **每个环境**（测试库/生产库）STMS 导入后都要**重新激活** ICF 节点——传输不会自动激活；
4. SE09 确认请求含 `R3TR WAPA …` → 释放（小货车图标，⚠️ 释放后锁定，确认内容齐了再放）→ STMS 导入目标系统（RC=0/4 正常，≥8 看日志）。

```js
fetch('/sap/bc/ui5_ui5/sap/zai_chat_demo1/Component-preload.js',{cache:'no-store'})
```

期望 `V8.1: 4  V8.3: 3`；**为 0 = 服务器还是旧文件**。然后 Ctrl+F5 强刷（BSP 缓存常让你看到旧页面，更新部署后页面没变化先怀疑缓存）。

## 七、回滚

- **代码级**：`git checkout <旧tag>` → `npm run build` → 重打 zip → 按第四章重新上传覆盖；
- **传输级**：STMS 不能"撤销导入"，回滚 = 上传旧版本内容的新请求（同代码级）；
- 所以**每次部署的 zip 都要留着——它们就是回滚包**（存档见仓库 `02_部署产物/`）。

## 八、Git 版本管理（第一次做一次）

```bash
git init && git add . && git commit -m "init: 基线"
```

`.gitignore` 必须先建（否则首次提交 300MB+）：`node_modules/`、`dist/`、`.docgen/`、`.v2c/`、`*.log`、`*.zip`、`Thumbs.db`。

- **分支**：`main`（稳定可构建）+ `feature/xxx`（实验线，做完合回删掉）；原则：main 上每个 commit 都能构建出可用 dist；
- **部署快照**：每次对外部署前打 tag：`git tag -a v8.3-dist-20260905 -m "V8.3 部署快照"`，zip 用同名保存 → 三个任意还原（代码 `git checkout tag` / 部署物翻 zip / 历史 `git log`）；
- 家里机 ↔ 公司机只传 zip；单人项目不值得搭 git 远端。

## 九、备选部署方案与依赖说明（答疑）

- **方案 B（静态服务器 nginx/IIS）**：dist 放独立 VM，反代 `/sap` 到网关（保留路径前缀），config.js host 留空走同源反代；需额外申请 VM/域名/证书/端口放通。前端代码零改动，公司统一门户要求时再迁；
- **Node.js**：仅构建时需要，部署产物纯静态，服务器不装 Node；
- **UI5 运行时**：随包自带方案已与服务器版本彻底无关；唯一仍依赖服务器的是 ICF 登录；
- **浏览器**：Chrome/Edge 近两年版本（fetch/AbortController/CSS :has），不支持 IE11；
- **dist 瘦身**（传输受限时，删了没法本地调试）：删全部 `*.map` 与 `*-dbg.js`；删 `resources/sap/ui/test`、`sap/ui/commons`、`sap/ui/ux3`、`sap/tnt`、`sap/ux`；⚠️ 不要动 `sap/ui/core`、`sap/m`、`sap/ui/layout`、`sap/ui/unified`、`sap/base`、`thirdparty/` 与两套 theme 目录。

## 十、FAQ

| 问题 | 处置 |
|---|---|
| 打开页面 404 | SICF 节点没激活（第五章）；或 zip 多套一层目录（§3.1 重打） |
| 白屏，Console 报 sap-ui-core 加载失败 | dist 没带运行时（检查点 1）或 ui5Src 配错 |
| 一直停在"演示模式" | 后端不可达：服务没发布/ host 非空/网络不通；F12 看 $metadata 状态码 |
| 登录框弹两次 | 正常：第一次 SICF（SAP 标准），第二次应用登录框；同一套 SU01 账密 |
| 登录报"登录服务暂不可用" | /Login FI 未发布/未激活（后端手册第三章），或前端未带 Accept JSON（V8.2 补丁没部署） |
| 登录报"该账号未开通" | 网关验密已过、授权表没这个人 → 找管理员开通（区别于"账号或密码不正确"= SU01 密码错） |
| 更新部署后页面没变化 | 浏览器/BSP 缓存：Ctrl+F5 或无痕窗口 |
| 上传 zip 中途断掉 | 重新执行覆盖上传即可，BSP 对象是覆盖式不留半截状态 |
| 测试库好了生产库打不开 | 生产库忘了 SICF 重新激活（传输不自动激活） |
