## 三、第二步：SEGW 建模（项目 ZAI_CHAT）

SEGW 新建项目 `ZAI_CHAT`（已有项目则打开，只做增量部分）。

### 3.1 Entity Type × 3（新系统才需要；基线已建跳过）

属性名会自动转小写作为 ABAP 结构字段名；每个实体创建后勾选生成对应 EntitySet。

**Model**（键 ModelId）：ModelId String(20) / ModelName String(60) / ModelDesc String(100) / ModelType String(10) / EndpointUrl String(255) / Destination String(30) / ApiModel String(60) / ApiKeySet String(1) / AuthType String(10) / Temperature String(5) / MaxTokens String(10) / TimeoutSec String(10) / IsActive String(1)

**Message**（键 SessionId + MsgSeq）：SessionId String(32) / MsgSeq String(6) / Role String(12) / Content String / ModelId String(20) / ProgramName String(40) / CodeLines String(10) / ElapsedMs String(10) / CreatedAt String(14) / Status String(10)

**Session**（键 SessionId）：SessionId String(32) / Title String(70) / ModelId String(20) / MsgCount String(6) / CreatedAt String(14) / ChangedAt String(14)

EntitySet 名称：**Models / Messages / Sessions**。

### 3.2 ComplexType × 4

| 名称 | 属性（全部 String） | 用途 |
|---|---|---|
| AnalyzeResult | SessionId、Answer、ProgramName、ModelId、CodeLines、ElapsedMs、Status、Message（8 个） | AnalyzeCode 返回 |
| SaveResult | Success、Message | SaveModelCfg / 删除类返回 |
| TestResult | Success、Message、ElapsedMs | TestModel 返回 |
| **V8Result** 🆕 | **Success、Message、Json** | V8 九个接口统一返回（Json 承载列表数据的 JSON 文本） |

⚠️ 属性名**大小写逐字一致**（历史坑：TestResult 建错大小写导致 FI 不可用）。

右键 Data Model → Create → Function Import。**返回类型全部选 Complex Type**（不是 Entity）；**POST 型必须显式改 HTTP Method**（默认 GET）。

### 3.4 生成运行时与激活（最容易漏）

1. 工具栏 **Generate Runtime**（红线全勾）——生成会重写 DPC 父类 `ZCL_ZAI_CHAT_DPC`（不是 DPC_EXT），手工代码不受影响；
2. 报"对象被锁定" → 让同事关掉 SEGW/SE24 编辑会话；
3. `/IWFND/MAINT_SERVICE` 确认 `ZAI_CHAT_SRV` 在列表，SICF 节点已激活；
4. `/IWFND/GW_CLIENT` 测 `GET .../RolesList` → 返回 500 也算通（能进业务代码；404/unknown = 建模没生效）；
5. 改过建模后跑一次 `/IWFND/CACHE_CLEANUP`，浏览器 Ctrl+F5 硬刷（UI5 ODataModel 会缓存旧 metadata）。

## 四、第三步：SE24 粘贴 4 个类

## 六、第五步：模型初始配置与 SICF/权限

1. **模型配置**：SE16/SM30 往 `ZAI_MODEL_CFG` 插一行（或部署前端后在"模型管理"页签维护更方便）：
   `MODEL_ID=AFIONE / MODEL_TYPE=OPENAI / DESTINATION=ZAI_LLM_AFIONE / API_MODEL=<网关模型名> / AUTH_TYPE=BEARER / API_KEY=<key> / TIMEOUT_SEC=300 / IS_ACTIVE=X`
   ⚠️ key 属敏感信息：不落前端、不进聊天记录；泄露过的 key 及时轮换。
2. **SICF**：确认 `/sap/opu/odata/sap/zai_chat_srv` 激活；登录数据处理保持 **Standard**。
3. **权限角色**（找 Basis/权限组给最终用户分配）：
   - `S_ICF`：访问 ui5_ui5 前端节点 + ZAI_CHAT_SRV 服务节点；
   - `S_RFC`：网关 RFC 调用；
   - `S_TABU_DIS` / `S_TABU_NAM`：**决定"表数据分析"能读哪些表**（按权限组放开），无权限时模型会收到"读取失败"说明并如实转告。

## 十、常见问题速查

| 现象 | 根因与处置 |

## 十一、V10 已上线系统增量升级指南（代码提取管控 · 智能路由 · 分块 · 置顶）

### 11.1 升级顺序（务必先表后类，否则类激活即报错）

1. **SE11 加表字段**（各进一次 SE11，激活）：
   - `ZAI_MODEL_CFG` → 追加组件 `SKIP_SOURCE`，组件类型 `CHAR1`，短文本「该模型不做源码解析(X=跳过)」；
   - `ZAI_MODEL_CFG` → 追加组件 `USER_HIDE_SRC`，组件类型 `CHAR1`，短文本「USER用此模型时不下发源码(X=仅程式用途)」；
   - `ZAI_CHAT_SESS` → 追加组件 `PINNED`，组件类型 `CHAR1`，短文本「会话置顶」。
2. **SE24 整类覆盖粘贴**（每类进修改模式，源码全选替换后激活，顺序无关）：
   - `ZCL_AI_CODE_PROVIDER`（V1.8）、`ZCL_AI_CHAT_SERVICE`（V2.2）、`ZCL_ZAI_CHAT_DPC_EXT`（V2.2）；`ZCL_AI_LLM_CLIENT` 本次不动。
3. **SEGW 建模增量**（SE80 打开项目 `ZAI_CHAT`）：
   - 实体 `Model` 新增属性 `SkipSource`（Edm.String，可空，标签「跳过源码解析」）与 `UserHideSrc`（Edm.String，可空，标签「USER禁看源码」）；
   - 实体 `Session` 新增属性 `Pinned`（Edm.String，可空，标签「置顶」）；
   - 新增函数导入 `UpdateSession`：返回类型复用既有 `V8Result` 复杂类型，HTTP 方法 POST，
     入参 `SessionId`（必填）、`Title`、`Pinned`（均 Edm.String）；
   - 全部生成运行时工件 → 保存 → 激活（重新生成只覆盖 DPC/MPC 基类，`ZCL_ZAI_CHAT_DPC_EXT` 自定义代码不受影响）→ SM59 无关 → `SICF` 无需动 → 传输释放。
4. **前端**：按《04-前端实施文档》构建 + 增量上传（V10 前端与 V10 后端配套，旧前端忽略新字段不影响现状）。

- **模型级开关（推荐）**：前端「设置 → 模型管理 → 编辑」里逐模型勾选——「源码分析」=`SKIP_SOURCE`（取消勾选=该模型对所有人生效地跳过源码）、「USER 禁看源码」=`USER_HIDE_SRC`（勾选=USER 用此模型仅见程式用途说明，IT/ADMIN 不受限）；

### 11.5 已知注意

- **超时分块**：LONG_SRC_CHUNK 开启后单次请求可能 >2 分钟（本地 Ollama 尤甚），必要时调大 `icm/server_conn_timeout`（默认 60s）与前端侧等待预期。
- **权限收口**：V10 起 `save_model_cfg`/`test_model` 后端强制 ADMIN（此前仅前端隐藏入口）；USER 调用会收到「该操作仅管理员可执行」，属设计行为。
- **参数事务缺口未动**：`resolve_tcode` 仍只查 TSTC-PGMNA（SM30 等 OO/参数事务解析为空），为既有待办非本次回归。
