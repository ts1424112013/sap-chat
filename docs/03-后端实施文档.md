### 〇-A.5 ZAI_CHAT_CFG 可选配置

| 键 | 值格式 | 作用 | 未维护时 |
|---|---|---|---|
| `AGENT_MODELS` | 模型 ID，逗号/竖线/分号/空格分隔 | 全部 Agent 场景的模型白名单 | 不限制 |
| `AGENT_MODELS_RPT` | 同上 | 覆盖“报表执行”场景 | 沿用全局 |

### 〇-A.6.1 部署前后 Agent 基线测评（前端管理员操作）

这一步不新增 SAP 对象，也不替代 SE24/SEGW 激活；用途是把本次后端改动前后的行为留成可比较证据。测评入口随前端 BSP 发布，只有应用 `ADMIN` 能看到“设置 → 测评 → 打开 Agent 测评”。题库来自 `webapp/model/evalCases.json`，版本 `20261011`，当前 29 题：DATA 12、REPORT 5、INVENTORY 3、CODE 5、AUTO 4。

**部署前基线（旧后端仍在线时）**

2. 打开“设置 → 测评”，题库状态必须显示 `20261011 / 共 29 题`。若是演示模式，记录“仅内置示例，不代表真实模型”并不要把结果当 SAP 通过证据。

4. 等待完成或按需停止。导出 `Agent测评_*.md` 和 `Agent测评明细_*.json`，文件名加上“部署前/旧后端”和日期，归档到发布记录。重点记录总通过率、各场景通过率、跳过数、错误/超时/协议错、工具被拒次数、模型平均轮数和平均/最长耗时。

**本批激活后复测**

1. 9 个 ABAP 对象、SEGW `Scene`、OData 服务、ICF 和前端 BSP 都按本文完成激活；用 Ctrl+F5 清理旧 UI5 资源后重新登录。
2. 在 `$metadata` 中确认 `AnalyzeTask` 有可选 `Scene: Edm.String`。前端“测评”状态此时不应再提示场景用例跳过；若仍跳过，先检查网关缓存/服务版本，不要把报告标为通过。
3. 仍用同一模型、同一题库、同一重复次数重跑；优先分别跑 DATA、REPORT、INVENTORY、CODE、AUTO，再跑全部。默认清理测试会话，确认测评结束后历史会话没有残留测试会话。
4. 导出部署后 Markdown/JSON，与基线比较：场景边界题（D12/R05/I03/C05）应是确定性“换场景”且不成功调用工具；R01/R02 应为 REPORT 参数卡；D08/C04 的危险源码/写操作只能被拒；代码题必须出现 `read_program_source`；数据题必须命中 `run_sql`/`sap_data_analysis` 中的预期工具。
5. 将两份报告和题库版本一起提交发布归档。通过率下降、出现 `ERROR`/协议错、被拒次数异常增加或平均耗时超过题目 `maxSeconds` 时，先保留 JSON 明细和 Trace，再回到对应 ABAP 类排查，不要直接修改题库掩盖回归。

**题库维护边界**：导出的题库可编辑后按 `{ "cases": [{ "scene": "DATA", "turns": ["问题"], "expect": {} }] }` 导入；空题、未知场景、重复 ID 会被规范化/忽略，`requiresScene=true` 只用于依赖 SEGW Scene 的用例。导入题库不写 `ZAI_CHAT_CFG`、不改 SAP 数据；题库改动必须保留版本号、变更原因和基线报告。

### 3.4 生成运行时与激活（最容易漏）

1. 工具栏 **Generate Runtime**（红线全勾）——生成会重写 DPC 父类 `ZCL_ZAI_CHAT_DPC`（不是 DPC_EXT），手工代码不受影响；

   - 新增函数导入 `UpdateSession`：返回类型复用既有 `V8Result` 复杂类型，HTTP 方法 POST，

   - 全部生成运行时工件 → 保存 → 激活（重新生成只覆盖 DPC/MPC 基类，`ZCL_ZAI_CHAT_DPC_EXT` 自定义代码不受影响）→ SM59 无关 → `SICF` 无需动 → 传输释放。
4. **前端**：按《04-前端实施文档》构建 + 增量上传（V10 前端与 V10 后端配套，旧前端忽略新字段不影响现状）。

### 11.3 开关维护入口

- **模型级开关（推荐）**：前端「设置 → 模型管理 → 编辑」里逐模型勾选——「源码分析」=`SKIP_SOURCE`（取消勾选=该模型对所有人生效地跳过源码）、「USER 禁看源码」=`USER_HIDE_SRC`（勾选=USER 用此模型仅见程式用途说明，IT/ADMIN 不受限）；
- **全局开关仅剩一个**：模型管理页顶部「超长源码分块分析」=`ZAI_CHAT_CFG` 的 `LONG_SRC_CHUNK`（仅 ADMIN 可改；也可 SM30 维护 CFGVALUE=X 开启）。

### 11.5 已知注意

- **超时分块**：LONG_SRC_CHUNK 开启后单次请求可能 >2 分钟（本地 Ollama 尤甚），必要时调大 `icm/server_conn_timeout`（默认 60s）与前端侧等待预期。
- **权限收口**：V10 起 `save_model_cfg`/`test_model` 后端强制 ADMIN（此前仅前端隐藏入口）；USER 调用会收到「该操作仅管理员可执行」，属设计行为。
- **参数事务缺口未动**：`resolve_tcode` 仍只查 TSTC-PGMNA（SM30 等 OO/参数事务解析为空），为既有待办非本次回归。
