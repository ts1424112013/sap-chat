## 一、对象总览

<mark>当前后端不是“7 张表 + 4 个类”的旧 V8 口径。完整系统包含基础聊天、任务/报表、数据分析和审计对象；2026-10-11 本批只覆盖 9 个对象，且不新增 SE11 表或必填字段。部署事实源是 `backend-abap/00_对象清单与部署顺序_20261011.md`。</mark>

### 1.0.1 关键协议变化

- `AnalyzeTask` 新增可选 `Scene`（Edm.String、Nullable），取值 `REPORT/DATA/INVENTORY/CODE/AUTO`；`FocusedArtifactId` 保持可选并由后端校验归属、会话和 READY 状态。
- `ZAI_CHAT_SESS.AGENT_TYPE` 保存新会话场景；空值、`GENERAL` 和未知值按 `AUTO` 兼容旧会话，已有会话不会被前端重新改写。
- 普通对话的 `ZCL_AI_CHAT_SERVICE` 默认不读取程序源码、表结构或表数据。问题点名 SAP 对象时，前端提示转到 Agent 对应场景；只有维护 `CHAT_SAP_ACCESS=X` 才恢复旧行为。
- `ZCL_AI_AGENT_SERVICE` 按场景固定工具域：REPORT 不加载通用工具，DATA 走数据分析，INVENTORY 走库存，CODE 只允许 `read_program_source` 和表结构读取；场景外请求返回换场景提示。
- `read_program_source` 只接受 Z/Y 开头或命名空间对象，事务码先解析 TSTC 主程序；单页最多 400 行、字符上限 18000，模型级 `USER_HIDE_SRC=X` 时普通 USER 只收到程序元信息。
- Agent 模型白名单读取 `AGENT_MODELS`、`AGENT_MODELS_RPT`、`AGENT_MODELS_DATA`、`AGENT_MODELS_INV`、`AGENT_MODELS_CODE`；场景键优先，空值回落全局，全部为空代表不限制。
- 报表结果分析先取前端聚焦的 `FocusedArtifactId`，再取当前会话最近 READY Artifact；结果数据作为模型上下文注入，不重新执行报表、不新建 DATA 任务。

### 1.0.2 Agent 测评对后端的边界

管理员测评是前端能力，不新增 ABAP 类、SE11 表、SEGW EntityType 或 Function Import。`webapp/utils/AgentEval.js` 通过已有 `AnalyzeTask`（旧 metadata 没有 `Scene` 时回退已有 `AnalyzeAgent` 通道）调用当前后端，因此测评结果能直接暴露真实的场景路由、工具白名单、模型白名单、参数卡和协议错误。后端部署时不需要为测评单独激活对象，但必须保证 `AnalyzeTask.Scene` 的 metadata 与 [03-后端实施文档](03-后端实施文档.md) 一致，前端才会执行 `requiresScene=true` 的边界用例。

测评中的 `scene` 只在新会话首轮传入；`AUTO` 故意不发送 Scene，表示兼容旧会话/自动路由。后端仍是最终裁判：前端评分里“没有调用工具”“工具被拒”“确定性应答”等只是把 ABAP 返回的 Trace、Status、TaskModule、NeedsInput 和 Answer 结构化展示，不能替代 `ZCL_AI_AGENT_GUARD`、`ZCL_AI_SQL_GUARD` 或 `agent_model_allowed` 的安全校验。

## 二、ZCL_ZAI_CHAT_DPC_EXT —— 网关分发层（334 行）

SEGW 生成类的扩展（`INHERITING FROM zcl_zai_chat_dpc`），只做两件事：

1. **`/iwbep/if_mgw_appl_srv_runtime~execute_action`**：`CASE to_upper( iv_action_name )` 分发 12 个 Function Import 到业务类静态方法：

| Action（CASE 分支） | 调用 | Action | 调用 |
|---|---|---|---|
| ANALYZECODE | `analyze( )` | SAVEPROMPTS | `v8_save_prompts( )` |
| SAVEMODELCFG | `save_model_cfg( )` | PROMPTSLIST | `v8_get_prompts( )` |
| TESTMODEL | `test_model( )` | USERSLIST | `v8_get_users( )` |
| LOGIN | `v8_login( )` | SAVEUSER | `v8_save_user( )` |
| ROLESLIST | `v8_get_roles( )` | GETCONFIG | `v8_get_config( )` |
| SAVEROLES | `v8_save_roles( )` | SAVECONFIG | `v8_save_config( )` |

2. **EntitySet 重定义**：`models_get_entityset` / `messages_get_entityset` / `sessions_get_entityset` / `sessions_delete_entity` —— 透传给 SERVICE 对应方法。

辅助方法 `v8_param( io_tech_request_context, iv_name )`：按名读 Function Import 参数（大小写不敏感），所有 V8 分支取参统一走它。

> 设计要点：SEGW 重新生成运行时会重写的是父类 `ZCL_ZAI_CHAT_DPC`（自动生成物），DPC_EXT 里手工代码不受影响——这就是把业务全部放扩展类的意义。

### 3.2 私有方法地图

| 方法 | 作用 |
|---|---|
| `build_system_prompt` | 固定 system 提示词：资深 SAP ABAP 专家人设 + 简体中文 + Markdown + abap 代码块 + 四步分析框架（概述/数据结构/业务逻辑/问题与优化） |
| `detect_program` | 从提问中识别分析对象（见 3.4） |
| `detect_where`（V2.1） | 解析表取样条件：`字段=值`（AND 连接）与 `前 N 行`；字段名逐一过 DDIC 白名单，值仅允许数字/带引号字面量；出现 OR/LIKE/子查询等不支持语法时**整体放弃条件**（降级无条件），绝不部分采用——防 SQL 注入 |
| `get_table_sample`（V8.4 修复） | 动态建内表 → `SELECT * UP TO N ROWS` → RTTI 序列化 `字段=值; …` 行文本（见 3.5） |
| `read_model_cfg` | 读 ZAI_MODEL_CFG 单行（test_model / analyze 共用） |
| `get_history` | 取会话最近 `gc_max_history = 10` 条消息作为上下文 |
| `append_msg` | 消息落库，序号 `SELECT MAX(msg_seq)+1`（V1.4 并发修复，防多窗口同会话并发主键冲突） |
| `trim_history` | 每会话最多保留 `gc_store_max = 100` 条，超出删最旧 |
| `upsert_session` | 会话头 upsert；标题取首条提问前 60 字 |

### 3.3 analyze 主流程（一次提问的完整时序）

```
入参: SessionId / Question / ModelId / ProgramName(前端恒传空)
  │
  1. read_model_cfg —— 模型必须存在且 IS_ACTIVE='X'，否则返回明确提示
  2. get_history —— 最近 10 条消息（多轮上下文）
  3. 对象识别: ProgramName 为空 → detect_program( Question )
       命中 tcode → meta "已通过事务代码 X 定位到程序 Y"
  4. get_source( 对象 )
       ├─ 成功 & TABL/VIEW → detect_where(条件/行数) + get_table_sample(样例)
       │    meta = "表 X 取样：条件 …，前 N 行（16KB 截断说明…）"
       └─ 失败(不存在/不可读) → 生成 lv_obj_note "系统事实：…请如实告知…"
            并 CLEAR 对象 → 降级纯对话（V1.5，不再报错中断）
  5. 组装消息数组:
       [0] system = build_system_prompt( )
       [1] system = lv_obj_note          (仅对象不存在时)
       [2..] 历史消息
       [n] user = 提问原文
            + 表对象: "请结合以下数据库表/视图结构… ```结构```" + "样例数据 ```text …```"
            + 程序对象: "请分析以下 ABAP 源码… ```abap 带行号源码```"
  6. ZCL_AI_LLM_CLIENT=>chat( cfg, messages ) → 回复/耗时/错误
  7. append_msg × 2（user 原文 + assistant 回复或错误文本）—— 无论成败都落库可追溯
  8. upsert_session + COMMIT WORK + trim_history
出参: AnalyzeResult { SessionId, Answer, ProgramName, ModelId, CodeLines, ElapsedMs, Status, Message }
```

注意第 7 步的设计意图：**后端是唯一事实源**——即使前端点了"停止生成"，后端照常跑完并落库，用户重开会话仍能看到完整回复。

### 3.4 detect_program 对象识别（多层优先级）

| 优先级 | 规则 | 示例 |
|---|---|---|
| 1 | 表名说法：`(表结构|表|TABLE) XXX` 或 `XXX 表 / XXX表`（标记词正则，**长词优先**；不限 Z/Y，标准表可） | `分析 表 MARC 的数据`、`表结构 MARC`、`MARC 表` |
| 2 | Z/Y 词元扫描：候选词先查 **TSTC**（tcode → 主报表 PGMNA，OO 事务 PGMNA 为空不处理），命中即分析主报表 | `分析一下 zapp0018` → `ZAPP_IDP_0018` |
| 3 | Z/Y 词元按 **TADIR** 对象名校验（PROG/CLAS/FUGR/TABL/VIEW），含数字/下划线/长度过滤，防普通单词误触发 | `ZDEMO_TEST_TSC02` |
| — | 显式提到表名时**不再要求对象存在**：不存在 → get_source 失败 → V1.5 降级注入事实 | `分析 表 ZNOTEXIST` |

实现教训（V1.3 勘误，勿再踩）：ABAP 正则引擎是 POSIX 语法，**不支持 `\b` 与非捕获组 `(?:...)`**——V1.2 版在此翻过运行时异常，现改为词元扫描 + 双捕获组。

### 3.5 get_table_sample 表数据取样（V8.4 当前版）

```
动态 CREATE DATA STANDARD TABLE OF (表名)
  → SELECT * UP TO N ROWS [WHERE (动态条件)]
  → RTTI: describe_by_data( 内表 ) 得 CL_ABAP_TABLEDESCR
          → get_table_line_type( ) 得行结构 CL_ABAP_STRUCTDESCR   ← V8.4 修复点
  → 逐行序列化 "字段=值; 字段=值"，单元格 >50 字符截断加 …
  → 总量 > 16KB 截断，ev_note = "样例已按 16KB 上限截断"
护栏: 行数默认 50（提问可指定，上限 200）；任何异常（无权限/空表/类型限制）
      不抛错，经 ev_note 说明 → 模型收到说明后如实转告用户
权限: 动态 SELECT 受 S_TABU_DIS / S_TABU_NAM 约束，用户能读哪些表由权限组决定
```

**V8.4 修复实录**（2026-09-05，用户断点抓到 `CX_SY_MOVE_CAST_ERROR`）：
- 旧代码 `CAST cl_abap_structdescr( describe_by_data( <lt_tab> ) )` 必抛转型异常——`describe_by_data( 内表 )` 返回的是**表描述符**，不是行结构描述符，直接 CAST 结构描述符 100% 失败（表取样功能整体不可用）；
- 修复：`CAST cl_abap_tabledescr( ... )` + `get_table_line_type( )`。修复后 MARA 取样 50 行成功（宽表触发 16KB 截断说明，属正常保护）。

### 3.6 V8 权限体系设计

- **认证与授权分离**：网关 Basic 完成 SU01 验密（401 = 密码错/锁定，业务代码不执行）；`v8_login` 只查授权表回答"开通了吗、什么角色"。应用零密码存储，锁定/复杂度/改密周期全部继承 SU01。
- **两级角色**：ADMIN / USER；管理接口第一行必过 `v8_require_admin`（前端隐藏只是体验，后端校验才是权限）。
- **INITIALIZED 机制**：`SaveConfig BACKEND_URL` 成功自动置 `INITIALIZED='X'`——这是前端"本地初始管理员 admin/123456"的失效开关；该标志**按环境独立**，测试/生产各自走一遍初始化。
- **审计友好**：角色/泡泡保存为全量覆盖 + 逻辑删除；用户停用只置 ACTIVE 空，记录保留。

### 7.2 坑档案（改动前必读）

| 坑 | 结论 |
|---|---|
| `describe_by_data( 内表 )` 返回表描述符 | 必须 `CAST cl_abap_tabledescr` + `get_table_line_type( )`，不能直接 CAST structdescr（V8.4 实锤） |
| ABAP 正则 POSIX 语法 | 不支持 `\b`、非捕获组；写正则前先想替代方案（词元扫描/双捕获组） |
| GW 函数导入返回 JSON | 会包一层 FI 名：`{"d":{"Login":{...}}}`；默认回 Atom XML，前端必须带 `Accept: application/json` |
| 403 + Content-Length 28 | = CSRF token validation failed（POST 无 token），先 GET $metadata 换 token |
| detect_objtype 参数别名 | iv_name 必须 `VALUE()` 传值，防 CLEAR 串改调用方变量 |
| SEGW 只贴 DPC_EXT 不出 FI | metadata 由建模生成，源码粘贴不会让接口出现——必须 SEGW 建模 + 生成运行时 |
| 类激活顺序 | SERVICE 先于 DPC_EXT（TY_V8_RESULT 依赖）；否则报"类型不存在" |
| 动态 WHERE 未带引号的字符串值 | 会被当列名——V2.1 detect_where 已做白名单+字面量校验，扩展时保持该纪律 |

### 9.3 行为要点（联调对照）

- **智能路由**：前端默认传 `ModelId=AUTO`；AnalyzeCode 返回的 ModelId 是实际使用的模型，故障兜底时回复末尾追加引用行「> 注: 首选模型 X 不可用, 本条由模型 Y 兜底回答」。
- **模型级代码权限 USER_HIDE_SRC**：每个模型独立配置，仅对 PROG/CLAS/FUGR 生效；TABL/VIEW 表数据分析对所有角色照旧（业务用户核心场景）。USER 使用开启此开关的模型提问程式时 Answer 无代码，`Message` 注明「当前模型对普通用户隐藏源码」。需按模型×角色精细管控时配此开关即可，无全局开关。
- **LONG_SRC_CHUNK**：关闭时维持现状（6000 行截断）；开启后 >6000 行才走分块，小程序不多花时间。分块会让单次请求耗时成倍增长，注意网关 `icm/server_conn_timeout`（建议 ≥300s）。
- **指定字段**：问法必须是「表 X 的 F1,F2」（顿号/中英文逗号均可，至少 2 个有效字段）；表名需与识别到的表一致。
