## 二、启动链路（index.html → 第一条消息）

```

2. document.write 引导 sap-ui-core    src = ui5Src（缺省=公网 CDN；当前="./resources/…"随包）
                                     ★ 必须 document.write 同步写入：
                                       ui5 serve 的 npm 源码版 core 依赖 document.write
                                       续接 ui5loader，动态插入会被吞
3. hljs 本地加载                       失败不阻塞（控制器有 window.hljs 判空兜底）
4. 主题预加载                          localStorage zai.theme → <html data-theme>（防闪烁）
5. Tab/鼠标输入模态跟踪                .zai-keynav 类（聚焦环只给键盘用户）
6. ComponentSupport 挂载 zai.chat     → App.controller.onInit
7. onInit：
   a. _probeBackend( )               GET $metadata（4s 超时）：200/401/403=可达→backend 模式；
                                     网络错/404/5xx=不可达→自动降级 mock + 顶部提示条 + 徽标"演示模式"
```

## 三-A、2026-10-11 Agent 场景和后端能力对齐

<mark>本节是前端必须和后端 A/B 批一起部署的增量。前端负责选择、展示和 metadata 探测；场景边界、模型白名单、源码权限和结果归属始终由 ABAP 后端强制校验。</mark>

### 三-A.1 一个 Agent 入口，五种会话场景

`App.controller.js` 的 `SCENES` 固定为：

| key | 显示名 | 允许能力 | 示例 |
|---|---|---|---|
| `REPORT` | 报表执行 | 登记报表、参数卡、后台作业、READY 结果追问 | `执行 ZDPMM702` |
| `DATA` | 数据分析 | 已登记的数据分析/只读 SQL 工具 | `按工厂统计 ZIDPMM455` |
| `INVENTORY` | 库存查询 | 物料候选、库存快照、当天收发、批次库存 | `A001 在 0001 工厂的库存` |
| `CODE` | 代码分析 | `read_program_source` 和表结构读取 | `解释 ZDPMM702 的程序逻辑` |
| `AUTO` | 自动 | 兼容旧 Agent 的混合路由 | 老会话空场景或手动选择自动 |

新建 Agent 会话默认使用 `localStorage[zaiChat.lastScene]`，首次为 `REPORT`；首条请求通过 `AnalyzeTask` 的 `Scene` 传给后端，后端写入 `ZAI_CHAT_SESS.AGENT_TYPE`，之后切换按钮会锁定。旧值为空、`GENERAL` 或未知值归一为 `AUTO`。`Scene` 不在旧 metadata 时，前端不发送，保持兼容。

### 三-A.2 请求字段和结果上下文

`ChatService.sendAgent` / 控制器会按以下字段发送：

| 字段 | 何时发送 | 说明 |
|---|---|---|
| `SessionId` | 每次 Agent 请求 | 当前会话 ID |
| `Question` | 每次请求 | 用户原问题 |
| `ModelId` | 每次请求 | `AUTO` 或下拉选中的模型；后端再做白名单检查 |
| `TaskId` | 已有任务时 | 任务上下文 |
| `ClientRequestId` | 新请求 | 幂等和运行追踪 |
| `FocusedArtifactId` | 当前消息聚焦报表结果时 | 后端校验会话归属、用户归属和 READY 状态后才读取 |
| `Scene` | 新会话首条消息且 metadata 支持时 | `REPORT/DATA/INVENTORY/CODE/AUTO`；已有会话以后端值为准 |

结果分析不是重新执行：后端先把 Artifact 的 schema、行数据和来源摘要注入模型；前端只负责把 `AnalysisJson` 和正文展示出来。用户追问若没有可用结果，报表场景显示已登记可执行报表清单，其他场景按自身边界提示。

### 三-A.3 对话页的 SAP 对象提示

普通对话不再隐式调用 `GET_TABLE_SAMPLE`、源码读取或表结构读取。`_sapSceneHint` 只对短问题和对象名做轻量识别：执行/运行类问题建议 `REPORT`，表/数据/统计类问题建议 `DATA`，其余程序或事务码问题建议 `CODE`。提示卡不会阻止用户发送，也不会把粘贴的长代码误判成系统对象；用户确认后 `_jumpToAgentScene` 新建指定场景并自动带原问题发送。后端只有维护 `CHAT_SAP_ACCESS=X` 时才恢复旧对话读 SAP 行为。

### 三-A.4 Agent 模型白名单与设置页

`ChatService.getAgentModelRules()` 读取后端配置；`_syncModelList()` 按场景过滤 `/modelsView`，始终保留 `AUTO`（智能路由）。管理员在“设置 → 模型管理 → Agent 可用模型”中勾选并保存，保存值对应 `AGENT_MODELS`、`AGENT_MODELS_RPT`、`AGENT_MODELS_DATA`、`AGENT_MODELS_INV`、`AGENT_MODELS_CODE`。空白代表不限制，场景键覆盖全局键。前端过滤只是体验层，后端 `agent_model_allowed` 是最终闸门。

### 三-A.5 图表位置和旧数据兼容

分析结果中的每个数据集表格下方紧跟它引用的数据图表；没有数据集锚点的用户图表留在消息附加区末尾。旧消息没有 `analysis` 或 `src` 字段时仍按普通 Markdown 渲染，不报错。重新打开旧 Agent 会话时，`AGENT_TYPE` 为空仍按 `AUTO`。

### 三-A.6 AgentEval.js：管理员测评模块

`SettingsDialog.fragment.xml` 增加仅 `settings>/isAdmin` 可见的“测评”页签；点击后打开 `EvalDialog.fragment.xml`。`App.controller.js` 只负责 UI 状态、题库加载和把 `ChatService.sendTask`/`deleteSession` 注入执行器，评分逻辑集中在纯逻辑模块 `utils/AgentEval.js`，便于脱离 SAP 做离线测试。

#### 题库结构和当前覆盖面

`model/evalCases.json` 的顶层字段是 `version`、`note`、`cases`。每个题目包含 `id`、`scene`、`name`、`turns`、`expect`，可选 `requiresScene`。`turns` 最多保留 5 轮；旧格式只有 `question` 时会自动转成一轮；缺少问题的项计入 `invalid` 并忽略；重复 ID 自动补下划线；未知场景归为 `AUTO`。当前版本 `20261011` 共 29 题：DATA D01-D12、REPORT R01-R05、INVENTORY I01-I03、CODE C01-C05、AUTO G01-G04。

`expect` 支持以下字段，字段只对最后一轮检查，但每一轮都必须满足状态要求（默认只允许 `OK`）：

| 字段 | 评分含义 |
|---|---|
| `status` | 允许一个状态或状态数组，例如 `OK/TIMEOUT` |
| `maxRounds` / `maxSeconds` | Agent 轮数上限 / 前端实测墙钟耗时上限 |
| `tools` / `toolsAny` | 必须调用全部工具 / 至少调用其中一个；只统计 `EXECUTING` 且非 `REJECTED` 的 Trace 行 |
| `noTools` / `toolsNotOk` | 不得成功调用工具 / 指定工具只能被拒绝，覆盖安全用例 |
| `answerAll` / `answerAny` / `answerRegex` | 回答必须包含全部关键词、任一关键词或匹配正则（大小写不敏感） |
| `module` / `needsInput` | 任务模块必须匹配（如 REPORT）/ 必须返回报表参数卡 |
| `deterministic` | 必须是确定性应答：`rounds=0` 且消息含“确定性应答” |

#### 执行与结果记录

`AgentEval.run` 将题目按顺序展开为“题目 × 重复次数”，重复次数在 1~5 之间；每题新建一个 session，多轮共享该 session，某轮为 `ERROR` 后不再追问。每次发送字段固定为 `sessionId/question/modelId/taskId/clientRequestId/focusedArtifactId/scene`；`AUTO` 的 `scene` 为空，其余场景传标准 key。`requiresScene` 题在 `_fiHasParam("AnalyzeTask", "Scene")` 为假时跳过并写明原因，不伪装成通过。`cleanup=true` 时每题结束调用删除会话；停止按钮只阻止下一题，当前 Promise 完成后结束。

每轮 `turnRecord` 保存 `question/status/rounds/elapsedMs/wallMs/tools/rejected/sqlRuns/deterministic/protocolError/answer/message/taskModule/needsInput/modelId`。`tools` 只保留 `EXECUTING` 行的工具、状态、行数和标签；因此报告能分辨“没调用工具”和“调用后被权限拒绝”。`summarize` 输出总计及按场景的 `total/run/skipped/pass/passRate/errors/timeouts/protocolErrors/rejected/avgRounds/avgSeconds/maxSeconds`；`toMarkdown` 另列失败题的每轮问题、状态、耗时、消息和回答前 600 字。

#### UI、导入导出和安全边界

弹窗可选择全部/单个场景、模型、重复次数，显示题目、场景、通过/失败/跳过、最终状态、轮数、耗时、工具和失败原因；点击行查看逐轮详情。可导出 Markdown 报告、JSON 明细和当前题库，也可导入 `{cases:[{scene,turns,expect}]}`；导入 JSON 只影响本次浏览器会话，不会写入 ABAP 配置。普通用户看不到页签，前端权限隐藏之外，测评仍走后端现有权限和工具限制；所有内置测评工具均为只读，REPORT 题只取参数卡，不提交后台作业。

离线纯逻辑回归命令为 `node test-server/agent-eval-tests.js`（或 `cd test-server && npm run test:eval`），覆盖题库规范化、ID/场景、工具与安全评分、轮数/超时、确定性应答、同 session 多轮、跳过、清理、停止、汇总和 Markdown 报告，不访问网络、不调用 LLM。

## 三、ChatService.js —— 服务层方法地图（当前约 1100 行）

全部网络与持久化逻辑的唯一出口，控制器不直接碰 fetch/ODataModel。

### 3.1 连接与凭据

| 方法 | 作用 |
|---|---|
| `setConfig / getConfig / getMode` | 读写 `window.ZAI_CONFIG`；模式判定 backend/mock |
| `_getModel` | 构造 v2 ODataModel。★ 历史关键修复：**构造参数 headers 直接携带 Basic 凭据**——ODataModel 构造瞬间即发 `$metadata`，构造后才 setHeaders 会 401 卡死（V5.2 实锤） |
| `_basicHeader / _loadAuthStore / _persistAuth` | Basic 头拼装；凭据存 localStorage `zaiChat-sapAuth`（UTF-8 安全 base64，结构 `{user,pass,header}`） |
| `setSapCredentials / setSapHeader / verifySapHeader` | 账密 / 整段 Basic 头两种凭据形态 + 校验（$metadata 探测 12s 超时） |
| `_maybeAuthFail` | OData 错误统一挂 401 检测（60s 防抖）→ 回调控制器弹登录框 |
| `_fetchCsrf`（V8.1 补丁） | 同凭据 GET `$metadata` 带 `x-csrf-token: fetch` 换 token，`credentials:"same-origin"` |
| `_read / _fmtError` | OData 读封装 / 错误格式化 |

### 3.2 业务调用（backend 模式走这里）

| 方法 | 后端接口 |
|---|---|
| `getModels / saveModelCfg / testModel` | EntitySet Models / FI SaveModelCfg / FI TestModel |
| `getSessions / deleteSession / getHistory` | EntitySet Sessions、Messages |
| `send` | FI **AnalyzeCode**（核心；返回 AnalyzeResult） |
| `appLogin / appLogout / getAppUser / isAdmin` | FI Login + 登录态管理（`zaiChat-appUser`） |
| `isBackendInitialized / saveBackendConfig` | FI GetConfig(INITIALIZED) / SaveConfig(BACKEND_URL) |
| `getUsersData / saveUserData` | FI UsersList / SaveUser |
| `getRolesData / saveRolesData` | FI RolesList / SaveRoles |
| `getPromptsData / savePromptsData` | FI PromptsList / SavePrompts |
| `_v8Call(action, params, bPost)` ⭐ | 9 个 V8 FI 的统一通道（见 3.4） |
| `_sha256 / _sha256Sync` | 初始管理员改密哈希（`zaiChat.adminPwdHash`，salt 前缀） |

### 3.3 mock 演示模式（`_mock*` 家族）

- 数据落 localStorage：`zaiChat.mockData`（会话/消息）、`zaiChat-roles`、`zaiChat-quickPrompts`、`zaiChat.mockUsers`——**键与旧版兼容**，降级无缝；
- `_mockSend` 模拟打字机流式回复（含 abap 代码块示例，代码高亮/复制可演示）；
- `_mockAppLogin` 本地校验：admin（初始 123456，首登强制改密）/ 演示身份（USER 权限）；
- 多标签页：storage 事件实时同步角色/泡泡/登录态。

### 3.4 `_v8Call` 的三个联调补丁（V8.1~V8.3，2026-09-05 服务器实装踩出来的）

| 补丁 | 问题现象 | 修复 |
|---|---|---|
| V8.1 | `POST /Login` 403，Content-Length 28 = CSRF token validation failed | POST 前先 `_fetchCsrf` 换 token 再发；403 自动刷新 token 重试一次；全程 `credentials:"same-origin"` |
| V8.2 | 后端 Success=X 前端却报"登录服务暂不可用" | GW 默认回 Atom XML，`oResp.json()` 解析失败 → 所有 FI 请求头补 `Accept: application/json` |
| V8.3 | 后端成功前端读 `d.Success` 落空，误报"该账号未开通" | GW 把返回结构包在 **FI 名**下：剥壳改读 `d.Login.Success` / 通用 `d[sAction]` |

改这三个补丁**只动了 ChatService.js**（`_fetchCsrf` / `appLogin` / `_v8Call` 三处方法）。改完必须重新构建部署，并在 dist 的 `Component-preload.js` 里校验标记（见 04-实施文档 §6.3）。

## 五、视图与样式体系

- **App.view.xml**：`SplitApp` 式布局——左侧历史栏（新对话按钮 + 会话列表 + 底部模式徽标）+ 右侧主区（Hero 欢迎态 / 对话态消息列表 + 输入卡）。输入卡两份（首页/对话态）共享控制器逻辑；

```js
window.ZAI_CONFIG = {
```

## 八、构建机制（npm run build）

1. `ui5 build --all --clean-dest`：**--all** 使 ui5.yaml 声明的 framework（OpenUI5 1.130 + sap.m/sap.ui.core/sap.ui.layout + 双主题库）整个打进 `dist/resources/`——**部署后不依赖公网 CDN、也不依赖服务器内置 UI5 版本**（760 老系统行为一致）；
2. 产物关键文件：`dist/Component-preload.js`（**UI5 实际优先加载的文件，校验补丁必须查它，不是 webapp 源码**）、`dist/config.js`（部署生效的配置）、`dist/thirdparty/hljs/`；
3. 全量约 8600 文件 / 31MB（去 .map 后）；构建 1.5~8 分钟（含框架库打包）；
4. 构建机需能访问 OpenUI5 CDN 拉框架（内网构建需先在有网机器做一次，或用交付包里的 `02_部署产物/ui5框架缓存_复制到_C盘用户目录.zip`——解压到 `C:\Users\<用户>\.ui5\` 即离线缓存）。

**构建纪律**（踩过的坑）：
- 补丁晚于 dist 构建 = 服务器跑旧代码——**改代码必须重跑 build 并校验**；
- 并发构建互相覆盖 dist：启动前 `pgrep -f "[u]i5 build"` 确认无存活进程，日志出现 `Executing cleanup` 才算完成；
- preload 校验标记要用**值字符串**（如 `application/json`）或属性访问（`.Login`）——注释版本号会被压缩器剥掉；`rg -c` 是行数（dist 单行恒为 1），要用 `rg -o | wc -l`。
