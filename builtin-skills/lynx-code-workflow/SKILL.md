# 代码分析工作流

所有代码工具都是**只读**的：能看、能做语法检查，不能保存、激活或改 SAP 里的代码；权限和用户在 Eclipse / SE80 里一样。有 `adt_` 工具时优先用它们，没有时用 `read_program_source`（事务码会自动解析到主程序）。

## 常见任务

**① 这个程序 / 类在做什么**
1. 名字不确定：`adt_search`（可用 `*`）。
2. `adt_structure` 看结构（方法、FORM、INCLUDE、属性），先弄清骨架。
3. `adt_read_source` 按行号或 `keyword` 读关键部分，不要从第 1 行通读到底。
4. 回答：功能概述 → 主要数据和读写的表 → 关键逻辑（带对象名和行号）→ 潜在问题。

**② 报错 / 消息在哪里出来**
1. 用报错原文里有辨识度的一段做 `keyword`（`adt_read_source` 或 `read_program_source`），拿到命中行号。
2. 读命中处前后，找触发条件（IF / 检查 / 消息号）。
3. 回答：触发条件 → 关键代码与行号 → 业务含义 → 排查建议（看哪个字段、哪个事务码）。
   消息是消息类 + 编号（如 `E001(ZMM)`）时，keyword 搜 `MESSAGE` 和编号。

**③ 改一个对象会影响谁**
`adt_where_used` 列出使用者 → 挑关键的几个读调用处 → 按「直接调用 / 间接 / 只是引用类型」分层说明。

**④ 包里有什么**：`adt_package`，按类型汇总。

**⑤ 写或改一段 ABAP**
1. 先读要改的原代码，弄清上下文（不读就不要改）。
2. 写代码：本系统 ABAP 7.55，语法边界见「ABAP 7.55 语法边界」技能。
3. 有文件夹时把代码写进文件（如 `/代码/zcl_xxx.abap`），用 `adt_syntax_check` 带 `file` 检查；没有文件夹时带 `source`。
4. 有错误就改了再查，直到没有错误；把检查结果（通过 / 错误行号）一起告诉用户。
5. 要检查的对象还没在 SAP 建好时，不要拿别的对象凑：请用户先在 SE38 / SE24 建一个同名空对象，或告诉你用哪个测试对象。
6. 交给用户的是代码和改动说明，由开发人员在 SAP 里粘贴、激活、传输。

**⑥ 上线前审查**：用「ABAP 代码审查」技能；只看写法改进用「Clean ABAP 规范」；写测试用「ABAP 单元测试」。

## 规则

- 结论引用对象名和行号，只陈述读到的代码；没读到的不要猜，禁止凭记忆补代码。
- 读源码返回 `source_hidden`（账号不能看源码）时，只基于元信息说明用途。
- 对象不存在、不是自开发对象、没有权限时如实告诉用户。
- 用户没点名对象时先问要分析哪个，不要猜。
