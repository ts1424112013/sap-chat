# 查表与 SQL 取数

先确认没有合适的已登记报表（见「报表查询」）：报表的口径和数据权限由 SAP 程序把关，比自己写 SQL 可靠。

## 工具先后

1. **已登记函数** `call_function`：工具说明里列了可用函数；有能直接回答的先用它（秒级出数）。带 * 的参数必填，缺了先问；多值逗号分隔，范围 `low,high`，日期 `YYYYMMDD`。
2. **库存类问题**：`resolve_material`（料号不确定时先找候选）→ `get_stock_snapshot`（当前库位库存，按库存类型）/ `get_batch_stock`（批次，只在批次管理或用户问批次时）/ `get_daily_movement`（某天的收发汇总，空结果 = 当天没有收发，是有效结论）。
3. **数据分析计划** `sap_data_analysis`：统计、趋势、分布类问题且实体在能力目录里时用，args 是查询计划 JSON。
4. **查表 + SQL**：`search_tables`（按业务词找表）→ `describe_table`（**每张要用的表都先确认字段**，不要猜字段名）→ `run_sql`。有 `adt_run_sql` 时用它，不用 `run_sql`。

## SQL 一次写对

只能写**一条只读 SELECT**（Open SQL），校验不过会直接拒绝：

| 要这样写 | 不要这样写 |
|---|---|
| 表加别名、字段写 `a~matnr`，显式 `JOIN … ON` | `a.matnr`、逗号连表 |
| 聚合列给英文别名 `AS total_qty`，非聚合字段全进 `GROUP BY` | 中文别名、带双引号的别名 |
| `COUNT( * )`、`SUM( a~menge )`（括号里有空格，系统也会自动补） | `\|\|` 拼字符串（系统会改成 `&&`） |
| 字符串常量用单引号；日期常量 `'20261101'` | 双引号、反引号 |
| 要前 N 条：`ORDER BY` 后在回答里取前 N | `LIMIT` / `TOP` / `FETCH FIRST` / `UP TO`（行数由系统加） |
| 今天的日期直接写常量（系统说明里有今天） | `sy-datum`、`CURRENT_DATE`、`NOW( )` |
| 空值 `COALESCE( 字段, 默认值 )` | `IFNULL`、`NVL` |
| 日期差 `DATS_DAYS_BETWEEN( a, b )`；相除 `DIVISION( 分子, 分母, 2 )` 或查出两个数在回答里算 | `DATEDIFF`、直接 `/` |
| 状态类一对多的表（如状态表）用 `EXISTS ( SELECT … )` 放在 WHERE | 和数量 `SUM` 写进同一个 JOIN（会重复累计） |

另外：不写分号、不写 `INTO`、`FROM` 后不能跟子查询、最多关联 8 张表、整条不超过 4000 字符、单个字符串常量不超过 150 字符。尽量不用 `UNION`。

**编号补前导零**：编号字段在库里是补满长度的，比如工单号 `AUFNR` 12 位（`131002` 写成 `'000000131002'`），销售 / 采购单号 10 位；纯数字料号同理，长度以 `describe_table` 为准。查不到时先怀疑前导零。物料描述 `MAKT` 的语言码以系统为准（简体中文常为 `'1'`）。

## 大表和次数

- 大表（物料凭证、财务凭证、凭证流、修改记录、预留等）必须带过滤：日期范围、工厂、单号或料号。
- 统计类先 `GROUP BY` 汇总，不要拉大量明细；结果只回填前若干行，回答要说明总行数。
- 每次请求能执行的 SQL 次数有限：先汇总再查明细，不要逐月、逐物料循环查。
- 报错按提示改了再试，同一个错不超过两次；受保护的表、没有表权限时如实告诉用户，**不要换表绕过**。

## 交代结果

1. 先给结论和关键数字（不同单位、币种分开列，不自行换汇）。
2. 附上最后执行的 SQL。
3. 说明是直接查表的结果、口径没有和公司报表核对；明细被截断时只作示例；0 行如实说明（并想一下是不是前导零或条件写错）。
