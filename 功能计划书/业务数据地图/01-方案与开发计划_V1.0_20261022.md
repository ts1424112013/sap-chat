## 0. 一页看懂

- **要解决的问题**：用户说一个业务（“看看 ABZ1 还有多少采购没到货”），模型应该知道**先用哪个数据源**（公司已有报表还是查表）、**查哪几张表、怎么关联**、**口径是什么**（哪些行要排除、单位怎么处理）。现在这些全靠模型按关键词搜表、凭通用 SAP 常识去猜。
- **做法**：建一张「业务数据地图」——按业务主题维护：典型问题、先问清楚的口径、数据源优先级、核心表与关键字段、表之间怎么关联、口径与坑、已验证的示例查询、核对方法。
- **怎么用上**：
  1. 用户提问时按关键词匹配主题，把最相关的 1–2 个主题**摘要直接注入**提示词（不多花一轮模型调用）。
  2. 新增两个工具：`find_data_source`（按业务找数据源，返回完整主题卡）、`get_join_path`（给几张表，返回关联条件）。
  3. 之后仍走现有的 `describe_table` → `run_sql`，安全检查和权限校验不变。
- **维护**：一期每个主题一个 JSON 文件，放仓库里做版本管理，用 SE38 程序导入（与 Fiori 报表登记同一套做法）；二期在设置页维护，并加「口径正确」按钮沉淀已验证查询。
- **不做**：不接 MCP（原因见 §1.3）；不新增任何数据权限，地图只是指引，取数仍按当前用户的权限。
- **样板**：出货、采购未清、库存三个主题（§5），配 15 道测评题（§6），用测评结果对比开 / 关地图的效果。
- **分期**：D0 样板核对 → D1 机制 + 三个样板上线 → D2 测评调优 → D3（二期）设置页维护、已验证查询沉淀、与技能入口合并。

## 1. 要解决的问题

### 1.1 一个例子

用户在「数据分析」场景问：“ABZ1 工厂现在还有多少采购没到货，按供应商列一下”。

| | 现在 | 有了数据地图 |
|---|---|---|
| 第 1 步 | `search_tables("采购")`，返回几十张带“采购”字样的表 | 命中主题「采购未清」，摘要已在提示词里 |
| 选表 | 模型凭常识选 EKPO，常漏掉 EKET（交货计划） | 地图写明 EKKO + EKPO + EKET，关联字段给出 |
| 口径 | “未到货”常被算成 `EKPO-MENGE` 全量，不排除删除行、交货已完成行 | 地图写明：未清 = 计划数量 − 已收货数量；排除删除 / 锁定、交货已完成、退货行 |
| 轮数 | 搜表 → 看字段 ×2 → 写 SQL → 报错重写，常用满 5 次 `run_sql` 额度 | 看字段 ×1（可省）→ 写 SQL，一般 2–3 轮 |
| 结果 | 数字偏大且说不清口径 | 数字可核对（ME2N 选择参数 WE101），回答里说明口径 |

### 1.2 现状的短板

`ZCL_AI_DOMAIN_CARDS` 的「数据分析领域卡」里有一段写死的「常用业务表地图」，只有标准表名（如“MM 采购：EKKO / EKPO / EBAN”）。缺的是：

1. **关联路径**：表之间用哪些字段连、是 1:N 还是 N:1。
2. **公司自己的东西**：已登记的 TCode 报表、Fiori 报表（这才是公司口径），以及公司 Z 表。
3. **口径与坑**：删除标记、完成标记、单位 / 币种、S/4 里已经变成兼容视图的表（`VBUK`、`MSEG`、`KONV`）。
4. **能改**：现在要改一个字都得重贴 ABAP 类。

### 1.3 为什么不是接 MCP

MCP 是一种把工具接进 AI 客户端的标准接口，它解决的是“工具怎么接”，不提供“业务数据在哪、怎么连”的知识。对照外部项目 `romankorim/sap-mcp-server`：它提供的读表、看字段、调只读 BAPI、查 OData，我们在 SAP 内部都已具备，而且按当前用户校验权限；接上它模型照样要靠猜。另外我们的 Agent 在 ABAP 里运行、调用公司内部模型，ABAP 侧没有 MCP 客户端；那个项目还用一个公共技术账号读数据，与我们“助手里看到的不能比 Fiori / SAP 里多”的规则冲突。所以本方案补的是知识层，工具层沿用现有的。

## 3. 总体方案

### 3.1 流程

```text
用户提问（数据分析 / 自动场景）
  │
  ├─ ① 匹配主题：关键词 / 同义词（简繁英）+ 问题里点名的表名 → 得分最高的 ≤ 2 个主题
  │
  ├─ ② 注入摘要（系统消息，≤ 1200 字 / 主题）：先问清楚什么、数据源优先级（含本场景能不能用）、
  │     核心表与关联、关键口径
  │
  ├─ ③ 模型按需调用：
  │     find_data_source  —— 摘要不够时取完整主题卡（含已验证示例查询）
  │     get_join_path     —— 地图之外的表要关联时，问关联条件
  │     describe_table    —— 确认字段（现有）
  │     run_sql           —— 取数（现有，安全检查与权限不变）
  │
  ├─ ④ 回答：数字可溯源，写明口径；首选数据源在别的场景时，提示用户去那个场景（不越权调用）
  │
  └─ ⑤（二期）用户点「口径正确」→ 这次的 SQL 进入待审核 → 管理员通过后成为该主题的已验证查询
```

### 3.2 一个主题里放什么

| 部分 | 内容 | 例（采购未清） |
|---|---|---|
| 基本信息 | 编号、名称、模块、关键词 / 同义词 | `MM_PO_OPEN`、采购未清、MM、“采购未清, 未到货, 未交货, open PO, 採購未清…” |
| 典型问题 | 3–5 个例子，用于匹配和测评 | “某供应商还有多少没交货”“逾期未到的采购单” |
| 先问清楚 | 有歧义时先确认的口径 | “未清”是未收货还是未开票？要不要金额？ |
| 数据源优先级 | 依次：已登记报表 / Fiori（公司口径）→ 专用工具 → 表；每个写用途与所在场景 | 暂无登记报表 → 表 EKKO / EKPO / EKET |
| 核心表 | 表、角色（头 / 行 / 主数据 / 文本）、关键字段 | EKET：`EINDT` 交期、`MENGE` 计划数量、`WEMNG` 已收货 |
| 关联 | 两表之间的 ON 条件和基数 | `EKPO~EBELN = EKET~EBELN AND EKPO~EBELP = EKET~EBELP`（1:N） |
| 口径与坑 | 排除条件、单位 / 币种、S/4 差异、大表必带条件 | 排除 `LOEKZ` 非空、`ELIKZ = 'X'`、`RETPO = 'X'` |
| 示例查询 | 已在 SAP 上跑通的 SQL + 对应问题 | “按供应商统计未清”（§5.2） |
| 核对方法 | 用哪个标准 / 公司 TCode 对数 | ME2N 选择参数 `WE101` |

### 3.3 数据源优先级与场景

1. **公司已有报表优先**：已登记的 TCode 报表（报表执行场景）或 Fiori 报表（Fiori 报表场景）承载的是公司口径，能用就用。
2. **专用工具其次**：如库存的料号级工具（精确、带校验）。
3. **最后才是查表**：标准表 / Z 表 + `run_sql`。

场景限制不放宽：数据分析场景里不能调报表或 Fiori 工具。首选数据源在别的场景时，摘要里会写明（例：“更准的来源：『Fiori 报表』场景的 shipment 報表”），模型照常用表回答，但必须告诉用户口径可能不同、建议去哪个场景查。是否在自动场景里据此直接切换，放到二期（§7 D3）。

### 3.4 与现有几样东西的关系

| | 管什么 | 在哪 | 谁维护 |
|---|---|---|---|
| 场景 | 能用哪些工具（白名单） | `ZCL_AI_TOOL_REGISTRY` | 开发 |
| 业务卡片（领域卡） | 场景通用规则：SQL 写法、报告格式、自查清单 | `ZCL_AI_DOMAIN_CARDS` | 开发 |
| **数据地图（本方案）** | **某个业务的数据在哪、怎么连、口径是什么** | **4 张表 + JSON** | **管理员 / 业务骨干** |
| 技能（设计中） | 某类任务怎么做：步骤、自查、输出格式 | 计划中的 `ZAI_AGENT_SKILL` | 管理员 |

技能可以引用主题（如技能「采购未清分析」引用主题 `MM_PO_OPEN`），二期在设置页里共用一个维护框架。地图上线后，领域卡里写死的「常用业务表地图」一段可以删掉，改由地图提供（待确认，§9）。

### 3.5 越用越准

数字对不对，最终靠“跑通过、对过数”的查询来保证。每个主题保存若干条**已验证查询**（问题 + SQL + 最近一次试跑时间）：

- 一期：随 JSON 维护，导入时经安全检查，并可选试跑一次。
- 二期：回答下方加「口径正确」按钮，把这次运行里的 SQL（来自运行记录）存为草稿，管理员审核通过后入库。

`find_data_source` 返回该主题最多 2 条已验证查询，作为模型写 SQL 的范例；它们仍然只经 `run_sql` 执行，照常过安全检查和权限校验。

### 4.3 匹配与注入

- **计分**：关键词命中按词长加权（“采购未清”比“采购”权重高）；问题里出现某主题核心表名（如 `EKET`）直接加分；同时命中多个主题时取前 2 个。
- **阈值**：低于阈值不注入，模型照旧用 `search_tables` 找表（现有行为不变）。
- **长度**：每个主题摘要 ≤ 1200 字，合计 ≤ 2400 字；注入文本开头写明“以下是业务数据地图的参考，若与用户问题无关请忽略”，降低误命中的影响。
- **记录**：命中了哪些主题、得分多少，写进 Agent 运行步骤，测评时能看到。

注入摘要示例（采购未清，约 600 字）：

```text
【业务数据地图 · 采购未清】(参考信息; 与问题无关请忽略)
先问清楚: "未清"默认指未收货; 用户说未开票/未付款时口径不同, 先确认。
数据源: 暂无登记报表 → 查表(本场景可用)。
核心表: EKKO 采购订单头(LIFNR 供应商, BSTYP, LOEKZ) / EKPO 行(WERKS, MATNR,
  MENGE, MEINS, NETPR, PEINH, LOEKZ, ELIKZ, RETPO) / EKET 交货计划(EINDT 交期,

  EKET~EBELP (1:N); EKKO~LIFNR = LFA1~LIFNR (N:1)

  分组, 禁止跨单位加总; 逾期 = EINDT < 今天。
```

## 5. 三个样板

> 说明：字段名按 SAP S/4HANA 标准表；`ABZ1`、日期等是示例值。“公司报表”一栏来自仓库 `功能计划书/报表执行/` 里的源码，**TCode 与登记状态待确认**。示例 SQL 已按 `run_sql` 规则写（别名 + `~`、显式 JOIN、不写 `INTO` / `UP TO`、英文别名、日期 `YYYYMMDD`），但都**未在 SAP 上跑过**。

### 5.1 出货（`SD_SHIPMENT`）

**范围**：已发货（交货单已过账发货）的数量，按日期、工厂、客户、物料等维度；以及未发货的交货单。

**关键词**：出货, 出貨, 发货, 發貨, 交货单, 交貨單, DN, 已发货, 未发货, shipment, ship mode, 出货量

**先问清楚**

| 歧义 | 默认 | 其他口径 |
|---|---|---|
| “出货”指什么 | 已过账发货（PGI） | 交货单已创建；已开票 |
| 按哪个日期 | 实际发货日期 `LIKP-WADAT_IST` | 计划发货日 `WADAT`；物料凭证过账日期 |
| 按 ship mode / site / model / region / BU 看 | 用 Fiori shipment 報表 | 这些是公司维度，用标准表不一定能复现（待确认） |
| 退货、公司间调拨算不算 | 不算，单列 | 待业务确认 |

**数据源优先级**

| 优先 | 类型 | 引用 | 场景 | 用途 / 说明 | 状态 |
|---:|---|---|---|---|---|
| 10 | Fiori | `SHIPMENT`（shipment報表，`ZSD_IDP_001_SRV`） | Fiori 报表 | 公司口径；按维度 + 月份透视的出货数量 | 已登记（10-22 验证中） |
| 20 | 报表 | `ZRSD_IDP_0012`（TCode `ZDPSD012`，Issued / Open DN report） | 报表执行 | 已发货 / 未发货交货单明细 | 待登记 |
| 30 | 报表 | `ZRSD_IDP_0033`（Order Detail report：订单 → 交货 → 开票） | 报表执行 | 按订单追踪交货与开票 | TCode 待确认、待登记 |
| 40 | 表 | LIKP / LIPS（+ VBAK / VBAP / KNA1 / MAKT / VBFA） | 数据分析 | 公司报表覆盖不到的维度或明细 | 可用 |

**核心表与关键字段**

| 表 | 角色 | 关键字段 |
|---|---|---|
| `LIKP` | 交货单头 | `VBELN`、`LFART` 交货类型、`VSTEL` 装运点、`KUNNR` 送达方、`KUNAG` 售达方、`WADAT` 计划发货日、`WADAT_IST` 实际发货日、`WBSTK` 货物移动状态（A 未处理 / B 部分 / C 完成）、`VSBED` 装运条件 |
| `LIPS` | 交货单行 | `VBELN`、`POSNR`、`MATNR`、`WERKS`、`LGORT`、`CHARG`、`LFIMG` 交货数量（销售单位 `VRKME`）、`LGMNG` 数量（库存单位 `MEINS`）、`VGBEL` / `VGPOS` 参考销售订单 / 行 |
| `VBAK` / `VBAP` | 销售订单头 / 行 | `VBELN`、`POSNR`、`KUNNR`、`NETWR`、`WAERK`、`KWMENG` |
| `VBFA` | 凭证流 | `VBELV` / `POSNV` 前序 → `VBELN` / `POSNN` 后续、`VBTYP_N` 后续类型（J 交货 / M 发票 / R 货物移动） |
| `KNA1` | 客户 | `KUNNR`、`NAME1` |
| `MAKT` | 物料描述 | `MATNR`、`SPRAS`、`MAKTX` |

**关联**

| 左 | 右 | ON | 基数 |
|---|---|---|---|
| LIKP | LIPS | `LIKP~VBELN = LIPS~VBELN` | 1:N |
| LIPS | VBAP | `LIPS~VGBEL = VBAP~VBELN AND LIPS~VGPOS = VBAP~POSNR` | N:1 |
| VBAP | VBAK | `VBAP~VBELN = VBAK~VBELN` | N:1 |
| LIKP | KNA1 | `LIKP~KUNNR = KNA1~KUNNR` | N:1 |
| LIPS | MAKT | `LIPS~MATNR = MAKT~MATNR AND MAKT~SPRAS = '1'` | N:1 |
| LIPS | VBFA（发票） | `VBFA~VBELV = LIPS~VBELN AND VBFA~POSNV = LIPS~POSNR AND VBFA~VBTYP_N = 'M'` | 1:N |

**口径与坑**

1. 已发货 = `LIKP-WADAT_IST` 有值（或 `WBSTK = 'C'`）；未发货交货单 = `WBSTK` 为 `A` / `B`。
2. S/4 里 `VBUK` / `VBUP` 已不再维护（只剩兼容视图），状态直接读 `LIKP` / `LIPS` 上的字段。
3. `LFIMG` 是销售单位数量，汇总必须按 `VRKME` 分组；跨物料汇总改用 `LGMNG` + `MEINS`，仍按单位分组。
4. 交货单上没有价格；要金额需从销售订单行或发票取。`KONV` 在 S/4 不能直接读（公司报表用 `V_KONV_CDS`）。一期样板不算金额。
5. 退货交货（交货类型待确认）单列，不与正常出货相加。
6. `LIPS` 是大表：先用 `LIKP-WADAT_IST` 范围或工厂过滤。
7. `MAKT` 的语言：简体中文内部码 `'1'`、繁体 `'M'`，以系统实际维护为准（待确认）。

**示例查询（草稿）**

① 某月各工厂已发货数量：

```sql
SELECT P~WERKS AS PLANT, P~VRKME AS UNIT,
       COUNT( DISTINCT L~VBELN ) AS DN_CNT,
       SUM( P~LFIMG ) AS SHIP_QTY
  FROM LIKP AS L
  INNER JOIN LIPS AS P ON L~VBELN = P~VBELN
  WHERE L~WADAT_IST BETWEEN '20260901' AND '20260930'
  GROUP BY P~WERKS, P~VRKME
  ORDER BY SHIP_QTY DESCENDING
```

② 某工厂到期未发货的交货单：

```sql
SELECT L~VBELN AS DN, L~WADAT AS PLAN_GI_DATE, L~KUNNR AS SHIP_TO, C~NAME1 AS SHIP_TO_NAME,
       P~MATNR AS MATERIAL, P~LFIMG AS QTY, P~VRKME AS UNIT
  FROM LIKP AS L
  INNER JOIN LIPS AS P ON L~VBELN = P~VBELN
  LEFT OUTER JOIN KNA1 AS C ON L~KUNNR = C~KUNNR
  WHERE L~WBSTK IN ( 'A', 'B' ) AND L~WADAT <= '20261022' AND P~WERKS = 'ABZ1'
  ORDER BY PLAN_GI_DATE
```

**核对**：Fiori shipment 页面（同条件）；`VL06G`（发货过账的出库交货）；`ZDPSD012`。

**待确认**：公司“出货”口径（过账发货 / 开票）；ship mode 对应的字段（可能是 `LIKP-VSBED` 装运条件，也可能是 Z 字段）；退货与公司间交货是否计入；`ZRSD_IDP_0033` 的 TCode；两个报表是否登记。

### 5.2 采购未清（`MM_PO_OPEN`）

**范围**：已下单、未收货的采购订单（数量，可选金额），按供应商、工厂、物料、交期 / 逾期。

**关键词**：采购未清, 未清, 未到货, 没到货, 未交货, 未收货, 在途采购, 逾期未交, open PO, 採購未清, 未交貨

**先问清楚**

| 歧义 | 默认 | 其他口径 |
|---|---|---|
| “未清”指什么 | 未收货（收货未清） | 已收货未开票（发票未清）——用 `EKBE` 算，见坑 6 |
| 要不要金额 | 只给数量 | 要金额时按近似计算并注明（坑 4） |
| 订单范围 | 只看采购订单 `BSTYP = 'F'` | 合同 / 计划协议、公司间调拨（STO）、外协、服务是否计入待确认 |
| 逾期 | 交期 `EKET-EINDT` 早于今天且仍未清 | — |

**数据源优先级**

| 优先 | 类型 | 引用 | 场景 | 用途 / 说明 | 状态 |
|---:|---|---|---|---|---|
| 10 | 报表 | 候选：标准 `ME2N`（程序 `RM06EN00`，选择参数 `WE101`） | 报表执行 | 标准口径的未清清单 | 候选：需先验证 ALV 采集能否取到，再登记 |
| 20 | 表 | EKKO / EKPO / EKET（+ LFA1 / MAKT / EKBE） | 数据分析 | 按任意维度统计、逾期分析 | 可用 |

**核心表与关键字段**

| 表 | 角色 | 关键字段 |
|---|---|---|
| `EKKO` | 采购订单头 | `EBELN`、`BSTYP`（F 订单 / K 合同 / L 计划协议）、`BSART` 订单类型、`LIFNR` 供应商、`EKORG`、`EKGRP`、`BEDAT` 订单日期、`WAERS` 币种、`LOEKZ` |
| `EKPO` | 行项目 | `EBELN`、`EBELP`、`MATNR`、`TXZ01` 短文本、`WERKS`、`LGORT`、`MENGE`、`MEINS` 订单单位、`NETPR`、`PEINH` 价格单位、`LOEKZ`（L 删除 / S 锁定）、`ELIKZ` 交货已完成、`RETPO` 退货行、`PSTYP` 项目类别 |
| `EKET` | 交货计划 | `EBELN`、`EBELP`、`ETENR`、`EINDT` 交期、`MENGE` 计划数量、`WEMNG` 已收货数量（均为订单单位） |
| `EKBE` | 订单历史 | `EBELN`、`EBELP`、`VGABE`（1 收货 / 2 发票）、`SHKZG`（S / H）、`MENGE`、`BUDAT` |
| `LFA1` | 供应商 | `LIFNR`、`NAME1` |

**关联**

| 左 | 右 | ON | 基数 |
|---|---|---|---|
| EKKO | EKPO | `EKKO~EBELN = EKPO~EBELN` | 1:N |
| EKPO | EKET | `EKPO~EBELN = EKET~EBELN AND EKPO~EBELP = EKET~EBELP` | 1:N |
| EKPO | EKBE | `EKPO~EBELN = EKBE~EBELN AND EKPO~EBELP = EKBE~EBELP` | 1:N |
| EKKO | LFA1 | `EKKO~LIFNR = LFA1~LIFNR` | N:1 |
| EKPO | MAKT | `EKPO~MATNR = MAKT~MATNR AND MAKT~SPRAS = '1'` | N:1 |

**口径与坑**

1. 未清数量按**计划行**算：`EKET-MENGE − EKET-WEMNG`，只计大于 0 的行；不要用 `EKPO-MENGE` 直接当未清。
2. 排除：`EKKO-LOEKZ` / `EKPO-LOEKZ` 非空、`EKPO-ELIKZ = 'X'`（交货已完成，剩余量不再交）、`EKPO-RETPO = 'X'`（退货行）；只看 `EKKO-BSTYP = 'F'`。
3. 数量是订单单位 `EKPO-MEINS`，按单位分组，禁止跨单位加总。
4. 金额只能近似：未清数量 × `NETPR` ÷ `PEINH`；价格单位与订单单位不同（`BPRME`）时不准，回答必须注明；币种 `EKKO-WAERS`，按币种分组。
5. EKPO 一行有多条 EKET 时，按行汇总前不要把 EKPO 的数量字段一起 SUM（会重复计数）。
6. 用 `EKBE` 算收货量要按 `SHKZG` 区分正负（冲销为 H）；“已收货未开票”= 收货净量 − 发票净量，一期不做样板。
7. 逾期：`EKET-EINDT < 当天` 且仍未清。

**示例查询（草稿）**

① 某工厂按供应商统计未清（数量按单位分组）：

```sql
SELECT K~LIFNR AS VENDOR, V~NAME1 AS VENDOR_NAME, P~MEINS AS UNIT,
       COUNT( DISTINCT P~EBELN ) AS PO_CNT,
       SUM( E~MENGE ) AS SCHED_QTY,
       SUM( E~WEMNG ) AS GR_QTY
  FROM EKKO AS K
  INNER JOIN EKPO AS P ON K~EBELN = P~EBELN
  INNER JOIN EKET AS E ON P~EBELN = E~EBELN AND P~EBELP = E~EBELP
  LEFT OUTER JOIN LFA1 AS V ON K~LIFNR = V~LIFNR
  WHERE K~BSTYP = 'F' AND K~LOEKZ = ' ' AND P~LOEKZ = ' '
    AND P~ELIKZ = ' ' AND P~RETPO = ' '
    AND E~MENGE > E~WEMNG AND P~WERKS = 'ABZ1'
  GROUP BY K~LIFNR, V~NAME1, P~MEINS
  ORDER BY SCHED_QTY DESCENDING
```

未清数量 = `SCHED_QTY − GR_QTY`（只统计了未清的计划行，所以差值就是未清量）。若试跑确认 7.50 支持 `SUM( E~MENGE - E~WEMNG )`，改成直接输出 `OPEN_QTY`。

② 逾期未交的计划行明细：

```sql
SELECT K~EBELN AS PO, P~EBELP AS ITEM, K~LIFNR AS VENDOR, P~MATNR AS MATERIAL,
       E~EINDT AS DUE_DATE, E~MENGE AS SCHED_QTY, E~WEMNG AS GR_QTY, P~MEINS AS UNIT
  FROM EKKO AS K
  INNER JOIN EKPO AS P ON K~EBELN = P~EBELN
  INNER JOIN EKET AS E ON P~EBELN = E~EBELN AND P~EBELP = E~EBELP
  WHERE K~BSTYP = 'F' AND K~LOEKZ = ' ' AND P~LOEKZ = ' '
    AND P~ELIKZ = ' ' AND P~RETPO = ' '
    AND E~MENGE > E~WEMNG AND E~EINDT < '20261022' AND P~WERKS = 'ABZ1'
  ORDER BY DUE_DATE
```

**核对**：`ME2N` / `ME2L`（按供应商）选择参数 `WE101`；单张订单用 `ME23N`。

**待确认**：公司间调拨（`BSART = 'UB'`）、外协（`PSTYP = '3'`）、服务行是否计入；是否需要金额；`ME2N` 能否经 ALV 采集取数并登记。

### 5.3 库存（`MM_STOCK`）

**范围**：当前库存（按工厂 / 库位 / 物料 / 库存类型 / 批次）、收发统计、某日库存、库龄 / 呆滞、库存金额。

**关键词**：库存, 庫存, 在库, 在庫, 库存量, 库位, 批次库存, 收发, 收發, 库龄, 庫齡, 呆滞, 库存金额, stock, kitting

**先问清楚**

| 歧义 | 默认 | 其他口径 |
|---|---|---|
| 查一个料号还是做统计 | 点名料号 → 料号级工具；统计 → 查表 | — |
| 库存包含哪些类型 | 按类型分开列：非限制 / 质检 / 冻结 / 退货 / 在途 | 公司“库存”是否含项目库存、寄售——待确认 |
| 时点 | 当前 | 某个历史日期 → 用公司报表 `ZRMM_IDP_0003C`（按日期） |
| 要不要金额、库龄 | 不给 | 要时用 `ZRMM_IDP_0003C`（含库龄、成本 / 移动平均价口径） |

**数据源优先级**

| 优先 | 类型 | 引用 | 场景 | 用途 / 说明 | 状态 |
|---:|---|---|---|---|---|
| 10 | 工具 | `resolve_material` → `get_stock_snapshot` / `get_daily_movement` / `get_batch_stock` | 自动（命中库存意图） | 单料号的库存快照、当天收发、批次 | 可用 |
| 20 | 报表 | `ZRMM_IDP_0003C`（按日期的库存，含库龄、项目库存、寄售、金额） | 报表执行 | 某日库存、库龄、金额 | TCode 待确认、待登记 |
| 30 | 报表 | `ZRMM_IDP_0018`（Kitting stock report，工厂 + 库位必填，含 WBS） | 报表执行 | Kitting 库存 | 待登记 |
| 40 | 报表 | `ZRSD_IDP_0021`（FTU 可用库存 / 分仓） | 报表执行 | 可发货的可用库存 | 待登记；含建调拨单回调，登记时只登记查询条件 |
| 50 | 表 | MARD / MCHB / MARA / MAKT / MARC / MSEG / MBEW | 数据分析 | 统计、排名、收发汇总 | 可用 |

**核心表与关键字段**

| 表 | 角色 | 关键字段 |
|---|---|---|
| `MARD` | 库位库存 | `MATNR`、`WERKS`、`LGORT`、`LABST` 非限制、`INSME` 质检、`SPEME` 冻结、`RETME` 退货、`UMLME` 在途（库位间）、`EINME` 受限 |
| `MCHB` | 批次库存 | 同上 + `CHARG`；`CLABS` / `CINSM` / `CSPEM` / `CRETM` / `CUMLM` / `CEINM` |
| `MARA` / `MAKT` | 物料 / 描述 | `MATNR`、`MEINS` 基本单位、`MTART`、`MATKL`；`MAKTX` |
| `MARC` | 工厂视图 | `MATNR`、`WERKS`、`XCHPF` 批次管理、`EISBE` 安全库存、`DISPO` MRP 控制者 |
| `MSEG` | 物料凭证行（S/4 中为 `MATDOC` 的兼容视图） | `MBLNR`、`MJAHR`、`ZEILE`、`BUDAT_MKPF` 过账日期、`BWART` 移动类型、`SHKZG`（S 收 / H 发）、`MENGE`、`MEINS`、`WERKS`、`LGORT`、`CHARG`、`SOBKZ` 特殊库存 |
| `MBEW` | 估价 | `MATNR`、`BWKEY`、`BWTAR`、`LBKUM` 总库存、`SALK3` 总价值、`VPRSV` 价格控制、`VERPR` 移动平均价、`STPRS` 标准价、`PEINH` |
| `MSPR` / `MKOL` / `MSKA` | 特殊库存 | 项目库存（WBS）/ 供应商寄售 / 销售订单库存——**不在 MARD 里** |

**关联**

| 左 | 右 | ON | 基数 |
|---|---|---|---|
| MARD | MARA | `MARD~MATNR = MARA~MATNR` | N:1 |
| MARD | MAKT | `MARD~MATNR = MAKT~MATNR AND MAKT~SPRAS = '1'` | N:1 |
| MARD | MARC | `MARD~MATNR = MARC~MATNR AND MARD~WERKS = MARC~WERKS` | N:1 |
| MCHB | MARD | `MCHB~MATNR = MARD~MATNR AND MCHB~WERKS = MARD~WERKS AND MCHB~LGORT = MARD~LGORT` | N:1 |
| MARD | MBEW | `MARD~MATNR = MBEW~MATNR AND MARD~WERKS = MBEW~BWKEY AND MBEW~BWTAR = ' '` | N:1（估价范围 = 工厂、非分割估价时） |
| MSEG | MARA | `MSEG~MATNR = MARA~MATNR` | N:1 |

**口径与坑**

1. 库存按类型分开列（非限制 / 质检 / 冻结 / 退货 / 在途），不要只报 `LABST` 就叫“库存”。
2. 项目库存（`MSPR`）、寄售（`MKOL`）、销售订单库存（`MSKA`）不在 `MARD` 里；公司报表 `0003C` / `0018` 都把它们算进来，用表查时必须说明是否包含。
3. `MARD` 只有当前值；某个历史日期的库存要用报表 `0003C`（或 `MB5B`），不要自己倒推。
4. 金额：`MBEW` 是工厂级总值，不是库位级；库位金额只能用数量 × 单价近似。公司口径（成本价 / 移动平均价）以 `0003C` 为准。
5. 基本单位 `MARA-MEINS`，不同单位的物料不能加总。
6. 收发净额按 `SHKZG` 区分方向；冲销是成对的移动类型（101 / 102、261 / 262、601 / 602……），统计时不要只看收货类型。
7. `MSEG`、`MARD` 在 S/4 是兼容视图，`MSEG` 取数必须带过账日期范围和工厂。
8. 0 行是有效结论（该范围内没有库存记录），不是失败。

**示例查询（草稿）**

① 某工厂非限制库存最多的物料（含质检、冻结）：

```sql
SELECT D~MATNR AS MATERIAL, T~MAKTX AS DESCR, A~MEINS AS UNIT,
       SUM( D~LABST ) AS UNRESTRICTED, SUM( D~INSME ) AS QUALITY, SUM( D~SPEME ) AS BLOCKED
  FROM MARD AS D
  INNER JOIN MARA AS A ON D~MATNR = A~MATNR
  LEFT OUTER JOIN MAKT AS T ON D~MATNR = T~MATNR AND T~SPRAS = '1'
  WHERE D~WERKS = 'ABZ1'
  GROUP BY D~MATNR, T~MAKTX, A~MEINS
  ORDER BY UNRESTRICTED DESCENDING
```

② 某段时间按移动类型统计收发：

```sql
SELECT M~BWART AS MVT_TYPE, M~SHKZG AS DEBIT_CREDIT, M~MEINS AS UNIT,
       COUNT( * ) AS LINE_CNT, SUM( M~MENGE ) AS QTY
  FROM MSEG AS M
  WHERE M~WERKS = 'ABZ1' AND M~BUDAT_MKPF BETWEEN '20261001' AND '20261022'
  GROUP BY M~BWART, M~SHKZG, M~MEINS
  ORDER BY QTY DESCENDING
```

**核对**：`MMBE`（单料号）、`MB52`（仓库库存）、`MB51`（物料凭证清单）、`MB5B`（按日期库存）、`ZRMM_IDP_0003C`。

**待确认**：公司“库存”是否含项目库存 / 寄售 / 在途；库龄与金额是否一律以 `0003C` 为准；`0003C` / `0018` / `0021` 的 TCode 与是否登记；公司 Z 表（如 `ZIDPMM016` / `ZIDPMM017` 库位附加信息、`ZIDPMMWHCD` 仓码对应账册、`ZIDPMMAGING` 库龄）的用途，决定要不要写进地图。

## 8. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 地图内容写错 | 模型更“自信”地给错数字 | 只收试跑通过的示例；每个主题写核对方法；「待确认」未闭环前不上线该主题；`VERSION` 可回退 |
| 关键词误命中 | 无关问题被塞进业务摘要 | 阈值 + 最多 2 个主题 + 摘要开头写“无关请忽略”；命中记录进运行步骤，测评可见 |
| 提示词变长 | 轮数 / 耗时上升 | 摘要限长；`DMAP_INJECT_MAX` 可调为 0 只留工具 |
| 公司口径不在标准表里（如 ship mode） | 用表查的结果与公司报表不一致 | 地图把公司报表排在前面；用表时必须说明口径差异 |
| S/4 兼容视图（`MSEG`、`MARD`、`VBUK`）性能 | 查询慢、超时 | 坑里写明必带条件；必要时二期改读 `MATDOC`（字段与记录类型待确认） |
| `AGENT_SERVICE` 是大类，重贴有风险 | 部署出错影响全部 Agent | 改动集中在两处小块；按核对标记检查；开关默认关 |
| 没人维护 | 地图过时 | 一期 JSON 进仓库随版本走；二期设置页 + 「口径正确」降低维护成本 |
