# SAP Compass 动态 SQL 业务数据分析功能设计

**版本**：V1.0 (OPUS)  
**更新**：2026-10-05  
**阶段**：P0 - 核心功能实现

---

## 一、需求确认

### 1.1 用户背景

- **账号类型**：IT 开发账号（系统账号），具有或可获得全部权限
- **系统版本**：SAP S/4HANA 2020 SP03（ABAP Platform 2020 = SAP_BASIS 755，ABAP 按 7.50 语法编写，755 完全兼容）
- **模型部署**：内网私有化，可接收所有业务数据
- **第一阶段范围**：仅 IT 用户，只读 SELECT（不含 INSERT/UPDATE/DELETE）
- **后续扩展**：其他业务场景、其他用户、高级写操作

### 1.2 核心诉求

现有的数据分析功能被写死成只能查 MARA（库存物料表），每加一个业务场景都要改 ABAP 代码。新方案：

1. 模型自己根据用户问题**决定查哪张表**
2. 模型自己**写 SQL**（Open SQL，模型能理解的语言）
3. 后端校验、执行、返回结果
4. 模型做**分析和总结**

这样一来，"分析库存"、"分析销售"、"分析成本" 等所有业务场景都能用同一套工具。

### 1.3 参数与限制（已确认）

| 参数 | 取值 | 理由 |
|---|---|---|
| 单条 SQL 取回行数 | 5000（硬上限 50000） | 分析多数是汇总，5000 行明细够用 |
| 回填给模型的数据 | 200 行明细 + 列统计 | 超过 200 行让模型改用 GROUP BY |
| 单次请求 SQL 执行次数 | 5 次（含报错重试） | 通常 1-2 次，5 次容错足够 |
| Agent 循环轮数 | 10（原 4 提升） | 6 轮基本流程：搜表→描表→执行→分析 |
| Agent 总时长 | 180 秒（原 60） | 需 Basis 调 ICM PROCTIMEOUT > 200s |
| SQL 语句长度 | ≤ 4000 字符 | 防止超大查询 |
| JOIN 表数 | ≤ 8 张 | 复杂关联上限 |

## 二、总体架构

### 2.1 三个新工具（均只读）

```
Agent 会话
    ↓
┌───────────────────────────────────────┐
│  搜表工具：search_tables               │
│  输入：业务关键词（库存、销售、采购）  │
│  输出：表名、中英文描述、主键          │
└───────────────────────────────────────┘
    ↓
┌───────────────────────────────────────┐
│  读结构工具：describe_table            │
│  输入：表名                            │
│  输出：字段、类型、描述、可选值范围    │
└───────────────────────────────────────┘
    ↓
┌───────────────────────────────────────┐
│  执行 SQL 工具：run_sql                │
│  输入：SELECT 语句（模型写的）         │
│  输出：数据 + 错误提示（含重试）       │
└───────────────────────────────────────┘
    ↓
Agent 根据结果做分析、生成图表
```

### 2.2 后端执行流程（run_sql 工具）

```
OData 请求 (tool_request: run_sql, sql_text)
    ↓
┌─────────────────────────────┐
│ ZCL_AI_SQL_GUARD            │
│ 1. 词法扫描（禁止 UPDATE 等）│
│ 2. 表权限校验               │
│ 3. 敏感表黑名单             │
│ 4. 注入防护                 │
└─────────────────────────────┘
    ↓ 校验通过
┌─────────────────────────────┐
│ ZCL_AI_SQL_EXECUTOR         │
│ 1. 拼装 INTO 与 UP TO        │
│ 2. GENERATE SUBROUTINE POOL │
│ 3. 动态执行                 │
│ 4. 错误捕获                 │
└─────────────────────────────┘
    ↓
返回 JSON（数据或错误）
```

## 三、ABAP 实现细节

### 3.1 新增类 ZCL_AI_SQL_GUARD

**职责**：SQL 校验与审计

**核心方法**：

#### `validate_sql`
```abap
METHOD validate_sql.
  " 1. 长度检查
  IF strlen( iv_sql ) > 4000.
    ev_error = 'SQL 超过 4000 字符'.
    RETURN.
  ENDIF.

  " 2. 关键字黑名单（只允许 SELECT）
  DATA(lv_upper) = to_upper( iv_sql ).
  IF lv_upper CS 'INSERT' OR lv_upper CS 'UPDATE' OR lv_upper CS 'DELETE'
     OR lv_upper CS 'INTO' OR lv_upper CS 'CALL' OR lv_upper CS '/*' OR lv_upper CS '--'.
    ev_error = '不允许的 SQL 操作或注释'.
    RETURN.
  ENDIF.

  " 3. 只允许单条语句（没有 ; 结束符）
  IF iv_sql CS ';'.
    ev_error = '只允许单条 SELECT 语句'.
    RETURN.
  ENDIF.

  " 4. 提取表名（REGEX 匹配 FROM 后面的标识符）
  DATA: lt_tables TYPE TABLE OF string.
  PERFORM extract_table_names USING iv_sql CHANGING lt_tables.

  " 5. 逐表检查权限和黑名单
  LOOP AT lt_tables INTO DATA(lv_tab).
    IF is_sensitive_table( lv_tab ) = abap_true.
      ev_error = |表 { lv_tab } 属于敏感表，不允许查询|.
      RETURN.
    ENDIF.

    CALL FUNCTION 'VIEW_AUTHORITY_CHECK'
      EXPORTING view = lv_tab
      EXCEPTIONS no_authorization = 1 table_not_found = 2.
    IF sy-subrc <> 0.
      ev_error = |没有权限读取表 { lv_tab }|.
      RETURN.
    ENDIF.
  ENDLOOP.

  " 6. 检查 JOIN 表数
  IF lines( lt_tables ) > 8.
    ev_error = 'JOIN 表数超过 8 张'.
    RETURN.
  ENDIF.

  ev_error = ''.  " 校验通过
ENDMETHOD.
```

#### `is_sensitive_table`
```abap
METHOD is_sensitive_table.
  " 敏感表黑名单：用户表、人事、银行、凭证、费用、API 密钥
  rs_result = abap_false.
  
  DATA(lv_tab) = to_upper( iv_tabname ).
  
  IF lv_tab = 'USR02' OR lv_tab = 'USR05' OR lv_tab = 'RSECTAB'
     OR lv_tab = 'PA0001' OR lv_tab = 'PA0002'
     OR lv_tab = 'LFA1' AND iv_tabname CS 'BANK'
     OR lv_tab = 'ZAI_MODEL_CFG'  " API Key 存放地
     OR lv_tab CS 'HRM%' OR lv_tab CS 'RP%' .
    rs_result = abap_true.
  ENDIF.
ENDMETHOD.
```

#### `extract_table_names`
```abap
PERFORM extract_table_names USING iv_sql CHANGING ct_tables.

FORM extract_table_names USING iv_sql TYPE string CHANGING ct_tables TYPE TABLE OF string.
  " 简单 REGEX：FROM + 空格 + 表名（或 (subquery)）
  DATA: lv_pattern TYPE string,
        lv_matches TYPE string.
  
  lv_pattern = 'FROM\s+([A-Z_][A-Z0-9_]*)'.
  FIND ALL OCCURRENCES OF REGEX lv_pattern IN iv_sql
    RESULTS DATA(lt_matches).
  
  LOOP AT lt_matches INTO DATA(ls_match).
    DATA(lv_tab) = iv_sql+ls_match-offset(ls_match-length).
    APPEND lv_tab TO ct_tables.
  ENDLOOP.
ENDFORM.
```

#### `log_query`
```abap
METHOD log_query.
  " 审计：记录每条 SQL 的执行情况（成功/失败）
  DATA ls_log TYPE zai_sql_log.
  ls_log-query_id     = cl_uuid_factory=>create_system_uuid( )->string.
  ls_log-username     = sy-uname.
  ls_log-sql_text     = iv_sql.
  ls_log-result_rows  = iv_result_rows.
  ls_log-status       = iv_status.  " SUCCESS / ERROR / TIMEOUT
  ls_log-error_msg    = iv_error.
  ls_log-created_at   = sy-datum && sy-uzeit.

  INSERT zai_sql_log FROM ls_log.
ENDMETHOD.
```

### 3.2 新增类 ZCL_AI_SQL_EXECUTOR

**职责**：SQL 动态执行

**核心方法**：

#### `execute_sql`
```abap
METHOD execute_sql.
  " 1. 校验
  DATA lv_error TYPE string.
  zcl_ai_sql_guard=>validate_sql( EXPORTING iv_sql = iv_sql
                                  IMPORTING ev_error = lv_error ).
  IF lv_error IS NOT INITIAL.
    ev_error = lv_error.
    RETURN.
  ENDIF.

  " 2. 动态生成与执行
  DATA: lv_subprog TYPE string,
        lv_rows    TYPE i,
        lv_code    TYPE string.

  lv_rows = iv_max_rows.
  IF lv_rows IS INITIAL OR lv_rows > 50000.
    lv_rows = 5000.
  ENDIF.

  " 3. 生成 ABAP 代码字符串
  lv_code = |
    DATA: lt_result TYPE STANDARD TABLE OF dref, ls_row TYPE dref.
    FIELD-SYMBOLS: <lt_data> TYPE STANDARD TABLE.
    
    SELECT * FROM ({ iv_sql } ) UP TO { lv_rows } ROWS INTO TABLE @lt_result.
    
    LOOP AT lt_result INTO ls_row.
      APPEND ls_row TO <lt_data>.
    ENDLOOP.
  |.

  " 4. 生成子程序池
  TRY.
      GENERATE SUBROUTINE POOL lv_code NAME lv_subprog.
      PERFORM (lv_subprog) IN PROGRAM (lv_subprog) USING lt_result CHANGING <lt_data>.
      
      " 5. 转换结果为 JSON
      et_result = convert_result_to_json( <lt_data> ).
      
  CATCH cx_sy_dyn_call_illegal_form.
    ev_error = '动态 SQL 生成失败，请检查语法'.
  CATCH OTHERS INTO DATA(lx).
    ev_error = lx->get_text( ).
  ENDTRY.

  " 6. 审计
  zcl_ai_sql_guard=>log_query( iv_sql        = iv_sql
                                iv_status     = COND #( WHEN ev_error IS INITIAL THEN 'SUCCESS' ELSE 'ERROR' )
                                iv_error      = ev_error
                                iv_result_rows = lines( et_result ) ).
ENDMETHOD.
```

#### `convert_result_to_json`
```abap
METHOD convert_result_to_json.
  " 将 ABAP 表转为 JSON 数组
  " 行数超过 200 时只回 200 行明细 + 列统计
  
  DATA(lv_count) = lines( it_result ).
  
  IF lv_count > 200.
    " 明细只返回前 200 行
    DATA lt_detail LIKE it_result.
    lt_detail = it_result[1:200].
    
    " 额外返回列统计（COUNT/SUM/AVG 等）
    DATA lv_stats TYPE string.
    lv_stats = |总行数: { lv_count }, 已显示前 200 行|.
    
    et_result = convert_to_json_with_stats( lt_detail, lv_stats ).
  ELSE.
    et_result = convert_to_json( it_result ).
  ENDIF.
ENDMETHOD.
```

### 3.3 新增类 ZCL_AI_DDIC_TOOLS

**职责**：元数据查询（表结构、字段、值域等）

#### `search_tables`
```abap
METHOD search_tables.
  " 输入：关键词（库存、销售、成本等）
  " 输出：表名、描述、主键、常用字段

  DATA: lt_tables TYPE TABLE OF dd02t,
        lv_keyword TYPE string.

  lv_keyword = '%' && to_upper( iv_keyword ) && '%'.

  SELECT tabname, ddtext FROM dd02t
    WHERE ddtext LIKE @lv_keyword AND ddlanguage = @sy-langu
    ORDER BY ddtext ASCENDING
    INTO CORRESPONDING FIELDS OF TABLE @et_tables
    UP TO 10 ROWS.

  LOOP AT et_tables ASSIGNING FIELD-SYMBOL(<ls_tab>).
    " 补充主键
    SELECT tabname FROM dd03l
      WHERE tabname = <ls_tab>-tabname AND keyflag = 'X' AND ddlanguage = @sy-langu
      INTO TABLE @DATA(lt_keys).
    <ls_tab>-primary_key = concat_lines_of( table = lt_keys sep = ',' ).
  ENDLOOP.
ENDMETHOD.
```

#### `describe_table`
```abap
METHOD describe_table.
  " 输入：表名
  " 输出：字段清单（名称、类型、长度、描述、值域等）

  SELECT fieldname, inttype, leng, ddtext
    FROM dd03l
    WHERE tabname = @iv_tabname AND ddlanguage = @sy-langu
    ORDER BY position ASCENDING
    INTO CORRESPONDING FIELDS OF TABLE @et_fields.

  LOOP AT et_fields ASSIGNING FIELD-SYMBOL(<ls_field>).
    " 查值域（DOMA 表）
    SELECT SINGLE domname FROM dd04l
      WHERE rollname = <ls_field>-fieldname
      INTO @<ls_field>-domain.
  ENDLOOP.
ENDMETHOD.
```

## 四、前端展示

### 4.1 Trace 中新增 SQL 步骤

```
Agent 流程 (Trace)：
1. [UNDERSTANDING] 理解用户问题
   └─ 关键词：库存、前五名
2. [SEARCHING] 搜索相关表
   └─ search_tables(关键词) → 候选表：MARA, MARDH, ...
3. [PLANNING] 规划 SQL
   └─ 选定 MARA、MARDH，准备 SELECT
4. [EXECUTING] 执行 SQL
   ├─ run_sql("SELECT ... FROM MARA WHERE ...") 
   │  └─ 返回 200 行 + 统计
   └─ run_sql("SELECT ... FROM MARDH WHERE ...") 
      └─ 返回 150 行
5. [COMPOSING] 生成分析结果
   └─ 已完成总结和图表
```

### 4.2 结果导出

- **CSV 导出**：原始查询结果（全行）
- **JSON 导出**：模型分析结果 + 源 SQL
- **PDF 报告**：图表 + 总结

## 五、安全与权限

### 5.1 多层权限校验

```
第 1 层：用户是否开通 SQL 工具
  ↓ ZAI_CHAT_USER.SQL_ALLOWED = 'X'
第 2 层：表是否在白名单内（敏感表黑名单）
  ↓ is_sensitive_table() = false
第 3 层：用户对表是否有查看权限
  ↓ VIEW_AUTHORITY_CHECK( tabname )
第 4 层：SQL 语法是否只读（拒绝 INSERT/UPDATE/DELETE）
  ↓ validate_sql() 词法扫描
执行
```

### 5.2 审计日志

每条 SQL 记录到 ZAI_SQL_LOG：
- 谁执行的
- 执行了什么 SQL
- 什么时间
- 返回多少行
- 是否出错

### 5.3 已知限制

- **第一阶段**：只有 IT 账号能用（SQL_ALLOWED 不勾选其他人）
- **只读操作**：SELECT only，不支持写操作
- **简单 SQL**：不支持子查询中的 UPDATE、CTE、存储过程
