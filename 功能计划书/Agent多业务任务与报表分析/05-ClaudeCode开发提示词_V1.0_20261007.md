# Claude Code 开发提示词：Agent 多业务任务与报表分析

版本：V1.0  
编写日期：2026-10-07（Asia/Shanghai）  
用途：复制下面“开始执行”后的内容，交给 Claude Code。

## 使用说明

这份提示词已经把当前方案、开发边界、实施顺序和验收要求合并进去。真实 SAP 报表的 TCode、程序、选择屏幕字段、结果来源、权限角色和目标 SAP 版本尚未确认，因此 Claude Code 不得把 `ZM001` 当成真实可执行对象，也不得在没有配置和开关的情况下连接或提交真实报表。

## 开始执行

你现在位于 SAP Compass / `sap-chat` 项目根目录。请根据仓库中的以下方案文档实施功能：

- `功能计划书/Agent多业务任务与报表分析/01-开发计划_V1.0_20261007.md`
- `功能计划书/Agent多业务任务与报表分析/02-接口与数据设计_V1.0_20261007.md`
- `功能计划书/Agent多业务任务与报表分析/03-验收与场景清单_V1.0_20261007.md`
- `功能计划书/Agent多业务任务与报表分析/04-后续优化计划_V1.0_20261007.md`

你的目标是给现有 Agent 增加“多业务任务隔离 + 自开发 TCode 报表分析”的基础能力，同时保持现有普通对话、库存分析、动态 SQL 和源码分析链路兼容。

### 一、先做仓库审计，再动代码

1. 先读取仓库根目录及所有适用的 `AGENTS.md`、项目说明和测试说明。
2. 检查 `git status`、当前分支和已有未提交变更。不要覆盖、回退、删除或格式化与本需求无关的修改。
3. 阅读并总结以下现有实现，再决定最小改动点：
   - `backend-abap/ZCL_AI_AGENT_SERVICE.abap`
   - `backend-abap/ZCL_AI_DOMAIN_CARDS.abap`
   - `backend-abap/ZCL_AI_TOOL_REGISTRY.abap`
   - `backend-abap/ZCL_AI_CODE_PROVIDER.abap`
   - `backend-abap/ZCL_AI_DATA_ANALYSIS_SERVICE.abap`
   - `backend-abap/ZCL_AI_SQL_EXECUTOR.abap`
   - `backend-abap/ZCL_ZAI_CHAT_DPC_EXT.abap` 或现有 OData 扩展类
   - `webapp/controller/App.controller.js`
   - `webapp/service/ChatService.js`（按实际路径查找）
   - `test-server/` 中的 Mock、协议和测试
4. 输出一份简短的“现状 → 改动点 → 风险”报告。报告中必须明确哪些 SAP 端事实无法在本地验证。
5. 若仓库中的类名或路径与文档不同，以实际代码为准，并在最终报告说明映射关系。

### 二、必须遵守的安全边界

1. 不执行任意 TCode、任意 ABAP 程序、任意 SQL 或任意业务写操作。
2. 不实现通用 SAP GUI 自动点击、屏幕抓取、截图识别、关闭 ALV 后恢复临时内表或 Spool 还原。
3. 不把 `ZM001` 当成真实报表；它只能作为文档和 Mock 示例。
4. 未登记的 TCode、未启用的报表、参数校验失败、权限校验失败，都必须在后端拒绝执行。
5. `REPORT_EXEC_ENABLED` 默认关闭；没有真实 SAP 配置和权限验证时，只允许 Mock/模拟执行链路。
6. 模型输出的 TCode、程序名、TaskId、表名和参数全部是候选值，不能作为授权依据。
7. 不把模型猜测写成“已执行成功”，不把超时写成“作业已停止”，不把空结果写成执行失败。
8. 不保存密码、Token、完整敏感参数或完整业务明细到日志、Trace、模型上下文或前端 localStorage。
9. 不破坏旧的 `AnalyzeAgent`、`AnalyzeCode`、现有会话查询和现有返回字段。
10. 不安装外部 Skill，不引入向量数据库、外部 Agent 平台或无关依赖。

### 三、实施策略

采用“旁路新增、开关控制、逐步接入”的方式，不要一次重构全部前后端。

建议功能开关：

- `TASK_CONTEXT_ENABLED`：默认关闭或按现有配置约定处理
- `REPORT_READ_ENABLED`：默认关闭
- `REPORT_EXEC_ENABLED`：默认关闭

如果项目已有统一配置读取方式，复用它；不要新建第二套配置系统。真实 SAP DDIC、SEGW metadata、锁对象、权限对象和后台作业接口需要在目标 SAP 环境核验，不能仅凭本地源码假定已经存在。

### 四、第一阶段：先实现任务与上下文基础

优先实现 P1 的可测试基础能力，至少包括：

1. 业务任务模型：`SessionId`、`TaskId`、模块、意图、状态、标题、当前焦点结果和版本号。
2. 任务消息关联：能把现有消息关联到 TaskId，但不要破坏旧消息表主键和旧查询语义。
3. 结果索引：统一记录 `ArtifactId`、`DatasetId`、来源、类型、状态、行数、摘要和权限归属。
4. 任务上下文组装：优先注入当前任务状态、待办参数、结果引用和有限相关消息；不要把整段聊天历史全部发送给模型。
5. 结构化意图协议：至少支持 REPORT、INVENTORY、DATA、CODE、GENERAL，以及创建/恢复任务、待补参数、查看已有结果、执行和分析等动作。
6. 任务选择规则：明确指定的 TaskId/结果编号优先；对象明确时按对象选择；指代不明确时返回候选或追问，不猜唯一对象。
7. 工具正向白名单：修正库存模块误带入 SQL 工具的问题；REPORT 工具只能在 REPORT 模块启用。
8. 跨业务切换：同一个 Session 可以有多个 Task；从报表切到库存或自建表时，报表草稿和运行状态必须保留。
9. 旧链路兼容：旧客户端未传 TaskId 时创建或恢复任务；旧接口字段和旧会话读取行为保持兼容。

任务状态至少支持：`OPEN`、`WAITING_INPUT`、`QUEUED`、`RUNNING`、`ANALYZING`、`PAUSED`、`COMPLETED`、`PARTIAL`、`FAILED`、`CANCELLED`、`EXPIRED`。报表运行状态与任务状态分开，不要用 Agent 运行记录代替 ReportRun。

### 五、第二阶段：实现报表登记和参数准备，但先不开放真实执行

实现受控的报表定义和参数接口，建议对应文档中的：

- `ZAI_RPT_DEF`：TCode、已核验程序、结果模式、读取/执行/分析开关、配置版本和启用状态。
- `ZAI_RPT_PARAM`：ABAP 字段名、标签、类型、必填、多值、区间、默认值来源、值域和校验规则。
- `ZAI_RPT_RUN`：一次运行的参数快照、参数哈希、RequestId、状态、结果引用和错误信息。
- `ZAI_RPT_STEP`：解析、校验、授权、提交、轮询、结果绑定和分析阶段的脱敏审计。

注意：文档中的表名和字段名是候选设计，必须先检查项目现有 DDIC、命名规范和 ABAP 版本，再决定实际落地方式。若本地仓库只有 ABAP 源码而没有可执行 DDIC/SEGW 环境：

1. 可以实现 ABAP 中的结构、服务方法、Mock 协议、校验和开关。
2. 不要伪造“表已创建、类已激活、SEGW 已生成或 SAP 联调已通过”。
3. 把需要 SAP 端确认的内容列为阻塞项，并在文档中记录。

报表参数必须支持单值、多值、日期范围等结构化输入；禁止通过字符串拼接方式把用户输入直接交给 SQL 或程序执行器。缺参数、类型错误、范围错误和权限错误都只返回 `WAITING_INPUT` 或拒绝，不创建真实 SAP 运行。

### 六、第三阶段：实现安全的运行接口和 Mock 闭环

实现以下接口或等价服务，具体命名按现有项目风格调整：

- `Tasks`
- `TaskContext`
- `ReportDefinitions`
- `StartReportRun`
- `ReportRunStatus`
- `ReportResult`
- `TaskAction`

运行接口必须具备：

1. `ClientRequestId / RequestId` 幂等；相同请求重试不能产生两个 ReportRun。
2. 用户主动重跑必须产生新的 RequestId，并保留旧参数和旧结果。
3. 任务版本或乐观锁，避免两个页面覆盖同一任务的参数和状态。
4. 报表配置版本、参数快照和参数哈希绑定到 ReportRun。
5. 作业状态、结果状态、分析状态分别保存。
6. 结果就绪但分析失败时，只允许重试分析，不默认重跑报表。
7. 无法确认本次结果来源时，拒绝分析并返回明确原因，不能按“最新数据”猜测。

在没有真实 SAP 作业接口和真实结果表之前，先提供 Mock adapter 或测试 double，覆盖：创建、排队、运行、成功、空结果、失败、超时、未知状态、结果过期和重复请求。Mock 必须与生产接口契约一致，但最终报告要明确 Mock 不能证明真实 SAP 权限、后台作业和结果锁正确。

### 七、前端要求

在不破坏旧 UI 的前提下，增加最小可用展示：

1. 当前任务、任务模块、状态和标题。
2. 待填写参数和参数校验错误。
3. 报表运行状态、ReportRunId/ArtifactId 的可读短标识。
4. 同一聊天中的任务切换和恢复。
5. 报表后台运行时，聊天输入不被整个会话级 busy 锁死；后台轮询不能把结果写入其他任务。
6. 旧浏览器或后端未开启新能力时继续走旧 Agent。

不要在前端决定权限、白名单、报表是否存在或运行是否成功；前端只展示后端确认的状态。

### 八、测试要求

必须先运行现有测试，再增加有意义的测试。至少覆盖：

1. “执行一下 ZM001，并分析其结果” → REPORT，缺参数时 `WAITING_INPUT`。
2. “分析表 ZTEST_DATA” → DATA，不误判为 REPORT。
3. “先看库存” → 新建/切换 INVENTORY，报表任务保留。
4. “继续刚才的 ZM001” → 恢复唯一报表任务；多个候选时追问。
5. 重复 RequestId → 只有一个逻辑运行。
6. 未登记 TCode、停用报表、无权限用户 → 后端拒绝，不能提交 SAP 作业。
7. 空结果、失败、超时、未知状态 → 状态和提示互不混淆。
8. 结果分析必须绑定正确 ArtifactId/DatasetId，不能串到库存结果。
9. 长聊天只注入当前任务上下文，不把所有历史和完整明细塞进模型。
10. 旧 `AnalyzeAgent`、`AnalyzeCode` 和旧会话回归通过。

测试报告中区分：本地单元/契约测试、Mock 行为测试、前端构建/界面测试、SAP 端未验证项目。不能把 Mock 通过写成真实 SAP 已验收。

### 九、提交前检查清单

在修改完成后执行：

1. `git diff --check`。
2. 项目已有的 lint、单元测试、Mock 测试和前端构建。
3. 检查是否有无关文件被修改。
4. 检查默认配置是否安全：报表执行默认关闭。
5. 检查日志、Trace、上下文和前端存储没有密码及敏感明细。
6. 检查旧接口响应字段没有被删除或改成必填。
7. 检查每个运行结果都能追溯到 TaskId、RequestId、ConfigVersion 和来源。

最终输出必须包含：

- 修改了哪些文件，以及每个文件的目的。
- 实现了哪些能力，哪些仍是 Mock 或开关关闭状态。
- 运行了哪些测试，测试结果是什么。
- 哪些事项必须在 SAP 端确认。
- 发现的风险、未解决问题和下一步建议。
- 不要声称已创建 DDIC、激活 ABAP、生成 SEGW 或连接真实 SAP，除非你确实有对应环境和证据。

开始前先输出仓库审计结果和实施计划；如果没有新的本地阻塞项，就直接按 P1 → P2 → P3 的顺序小步修改。遇到必须在 SAP 端确认的事实时，先实现安全的接口、Mock 和开关，并把该项列为阻塞项，不要用假数据宣称已完成。每完成一个阶段都运行对应测试并汇报，不要一次性大范围重构。
