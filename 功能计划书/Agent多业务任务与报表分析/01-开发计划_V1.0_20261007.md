# Agent 多业务任务与报表分析：开发计划

版本：V1.0  
编写日期：2026-10-07（Asia/Shanghai）  
项目：SAP Compass / sap-chat  
状态：需求与技术方案初稿；本次仅编写文档，代码实施未开始。

## 1. 目标与业务体验

在现有 Agent 聊天中支持自然语言驱动多个业务，同时让每个业务任务拥有自己的参数、状态、运行记录与结果。首个新增业务为静态参数的自开发报表，继续复用已有库存和表数据分析能力。

用户不必知道 ABAP 程序名、工具 ID 或内部字段名，也不必每换一个业务就新建聊天。系统可以提供任务卡和聚焦入口，让用户在长聊天中找到之前的任务。

典型流程：

~~~text
用户：执行一下 ZM001，并分析其结果。
系统：定位已登记的报表，显示尚未填写的参数。
用户：先分析工厂 1000 的库存。
系统：创建库存任务，报表草稿保留，不将库存参数写入报表草稿。
用户：继续刚才的 ZM001。
系统：恢复对应报表任务，展示已填写与待填写参数。
用户：提交参数。
系统：后台执行报表，输入框可以继续使用。
用户：统计表 ZTEST_DATA 的记录分布。
系统：创建表分析任务，报表仍在后台运行。
报表完成：更新原任务卡；按原请求继续分析这一轮运行结果。
~~~

“执行报表”和“读取已有结果”必须分清。“分析 ZM001”本身不代表用户授权重新执行；有多个可用结果且指向不明确时，需要澄清。

## 3. 首期范围和不做的事项

### 首期必须完成

1. 每条消息重新理解用户动作、目标对象及与已有任务的关系。
2. 报表、库存、表分析任务相互隔离；任务可以跨多轮继续。
3. 保存结果索引及可重读的数据快照，支持“刚才那份结果”。
4. 按预算组装相关上下文，避免历史越长请求越大。
5. 静态参数报表登记、参数表单、服务端校验、执行授权绑定。
6. 后台报表运行状态、幂等提交、防重复运行、异常处理。
7. 报表完成后准确读取本次结果并分析，允许继续聊其他业务。
8. 模块化扩展契约、权限与审计、回归和部署说明。

### 首期排除

- 任意 TCode、任意程序、任意 ABAP 代码执行。
- 过账、订单修改、业务记录删除、审批等业务写操作。
- 参数事务、模块池、多画面交互事务的通用执行。
- 临时 ALV 内表捕获、Spool 文本还原、截图识别、GUI 自动操作。
- 向量数据库、外部 Agent 平台、第三方 Skill 批量安装。
- 同时重构全部前后端；本期采用逐步接入与功能开关。
- 把一个月的计划写成确定工期；工期需要 P0 试点验证后评估。

报表刷新自己的分析结果表、任务表和审计表属于本功能允许的持久化动作，但必须限定表、范围和并发规则；“允许生成报表结果”不能扩大成“允许修改其他业务数据”。

## 4. 架构：会话、任务、调用、结果四层

| 层 | 含义 | 示例 |
|---|---|---|
| SessionId | 用户看到的聊天容器 | 同一个 Agent 聊天 |
| TaskId | 一件有独立目标的业务任务，可跨多轮 | 执行 ZM001；分析库存 |
| AgentRunId / ReportRunId | 某次 Agent 调用 / 某次报表实际执行 | 同一任务可能多次重新执行 |
| DatasetId | 一份可引用的结果及其数据版本 | 某次报表数据快照 |

已有 ZAI_AGENT_RUN 继续表示 Agent 调用审计，不当作业务任务表，也不当作报表执行记录表。新报表执行用独立 ReportRunId，避免和原有 run_id 混用。

~~~mermaid
flowchart TD
    A[当前用户消息] --> B[意图和对象解析]
    B --> C[选择或创建业务任务]
    C --> D[按任务组装上下文]
    D --> E[模块工具白名单与权限校验]
    E --> F[库存模块]
    E --> G[表数据模块]
    E --> H[报表模块]
    H --> I[参数草稿与校验]
    I --> J[后台报表运行]
    J --> K[关联本次结果]
    F --> L[结果索引与快照]
    G --> L
    K --> L
    L --> M[分析与任务卡]
~~~

共享基础层负责：身份、会话归属、任务权限、请求幂等、上下文预算、结果访问、审计。业务模块负责：自己的对象、参数、规则、执行器和结果口径。

## 5. 意图与任务选择规则

### 5.1 分两步，不让模型直接执行

第一步给模型轻量能力目录和候选任务摘要，输出结构化意图。第二步由后端核验对象和任务归属，再加载选定模块的工具定义。模型输出的 TaskId、表名、报表编号都属于候选输入，不是授权证据。

确定性快捷规则只覆盖无歧义对象和明确动作，避免额外模型调用；不明确的自然语言再使用模型。解析失败最多修复一次，仍失败就说明需要补充信息，不尝试执行。

### 5.2 任务选择优先级

1. 明确的任务卡点击、用户指定的任务或结果编号；后端仍校验归属。
2. 当前消息明确说出的对象类型、对象名和动作。
3. 当前消息中的指代，与最近相关候选任务匹配。
4. 当前聚焦任务，仅作为缺省提示，不覆盖明确的新业务请求。
5. 候选不唯一或执行意图不明确时澄清。

例子：

| 用户说法 | 预期处理 |
|---|---|
| 执行 / 运行 / 跑一下 ZM001，并分析结果 | REPORT，定位配置，收集参数，按授权执行并分析 |
| 看一下 ZM001 的代码 | CODE；不执行报表，保留现有源码权限 |
| 分析表 ZSTOCK 的库存分布 | DATA；明确“表”优先于“库存”关键词 |
| 查询物料 M001 在工厂 1000 的库存 | INVENTORY，使用库存专用能力 |
| 分析 ZM001 | 结合可用结果判断；没有唯一结果时问“分析已有结果还是重新执行” |
| 分析刚才那张表 | 唯一对应 DatasetId 时继续，否则列候选 |
| 先看库存 | 切换任务；报表草稿保留，不取消已运行的报表 |
| 继续 ZM001 | 恢复对应草稿；有多个 ZM001 任务时澄清 |
| 用刚才的条件再跑一次 | 解析指定任务与参数版本；不继承无关任务参数 |

### 5.3 创建、继续、关联

- 补参数、追问同一结果、查看状态：继续已有任务。
- 新对象或新的独立业务目标：创建新任务。
- 一个请求既执行报表又分析：同一个任务的多个步骤。
- 报表结果与库存交叉比较：创建比较任务，显式引用两份结果。
- 不强制每句话创建任务，也不强制每个模块创建新聊天。
- 自动判断可以被任务卡切换修正，修正结果要保存。

## 6. 上下文与结果管理

### 6.1 每轮组装顺序

1. 固定系统规则与当前用户消息。
2. 当前任务结构化状态：目标、已确认参数、缺失项、待执行动作。
3. 当前任务最近几轮相关消息。
4. 相关结果元数据：DatasetId、来源、时间口径、行数、完整性、字段。
5. 当前问题需要的结果汇总与有限样例。
6. 任务摘要；需要时读取指定历史原文。

其他业务只注入短目录摘要，不默认注入完整历史、明细和工具定义。失败、拒绝和结果过期也要保留结构化事实，不能只记成功回复。

### 6.2 预算与数据原则

- 上下文上限从模型配置读取，不把用户提供的 256K 硬编码成事实。
- P0 核对内部模型的真实可用输入量、输出预留及 token 统计方式。
- 首期建议应用级输入预算起点 32K token，作为待验证的配置默认值；并非模型极限。另预留输出预算和安全余量，不能挤到端点上限。
- 工具回填也计入每次模型调用预算，不能只裁剪最初的聊天历史。
- token 无可靠计数时，使用保守字符/字节双重限制并在 Trace 标记估算；不能把中文字符数等同 token 数。
- 已确认参数、权限信息、当前动作不能通过摘要改写；结构化保存是事实源。
- 完整报表结果留在 SAP，模型拿字段、受控汇总和样例。大结果按条件查询。
- 数据分析数值由后端计算；样例不能被当作完整总体来求合计。
- “上次结果”必须指向冻结快照或稳定分区；若只能重新查当前表，明确标为新查询，不能冒充原结果。
- 保留货币、单位、时区和高精度数值口径；禁止跨币种/单位直接加总。

### 6.3 存储期限

运行审计和业务快照分别设置保留策略。过期的 DatasetId 仍能显示来源与过期原因，但不能继续返回已清理的数据。删除聊天、后台任务和结果清理的关系在 P0 确定，首期禁止删聊天时静默终止仍运行的报表。

## 7. 业务模块扩展方式

首期在 ABAP 中采用显式注册的模块定义，稳定后再评估配置化。每个模块声明：

- module_id、名称、支持的意图及示例；
- 对象解析方法、参数校验方法；
- 工具白名单、执行器；
- 权限检查、允许的副作用；
- 同步/异步运行方式、预算和超时；
- 结果结构和上下文摘要规则；
- 验收场景及回归要求。

核心 Agent 委托模块处理业务，不持续往一个巨大 CASE 中追加采购、销售、财务逻辑。工具必须同时满足“已注册、当前模块允许、当前用户允许、当前任务动作允许”。

CODE 首期仅提供现有源码分析通道的明确引导或适配，不凭空宣布 Agent 已有源码工具。是否在 Agent 内正式接入源码工具，放到后续优化；权限不能因迁移入口而降低。

GENERAL 不调用业务工具。一次跨模块请求只开放必要工具，并有显式结果引用；不把所有模块的全部工具交给模型自由挑选。

## 8. 报表流程与结果边界

### 8.1 参数登记

采用报表主表 + 参数明细表。主表保存 TCode、程序和结果适配方式；参数表保存每个选择屏幕字段的类型、必填、默认值、多值、区间及允许操作符。字段映射必须对应真实 ABAP 字段。

代码提取可以帮助第一次填写配置和检查变更，但本期不做全自动解析，不要求业务用户具备读源码权限。报表参数是静态的，不代表默认值、业务权限或输入校验也必然静态，试点要逐项核实。

### 8.2 执行授权

- 单纯查询、帮助、查看状态，不要求多次确认。
- 用户明确要求执行且参数齐全、合法：可以按登记策略提交，展示最终执行摘要。
- 缺参数时用表单补齐；“执行并分析”按钮一次提交最终参数，不再反复询问。
- 从历史恢复的参数、模型补出的业务值、默认时间范围发生变化时，先展示并由用户确认；模型不能把自己的猜测当作用户输入。
- 授权绑定 TaskId、报表配置版本、参数版本/哈希和动作；更换参数后旧授权失效。
- “分析”不隐含“重新执行”；“先看库存”不隐含“取消报表”。

### 8.3 后台执行

用户请求提交后先创建运行记录，后台作业独立运行。提交接口迅速返回 ReportRunId 与状态，解除聊天请求 busy；后台轮询不占用聊天发送锁。第一版仍允许一次一个前台 Agent 请求，不承诺多路前台生成并发。

RequestId 用于网络重试和重复点击去重。同一请求的重试返回同一 ReportRunId；用户主动“再执行一次”产生新 RequestId。未知是否已提交成功时先查已有运行，不盲目重新启动。

通过任务版本锁和报表结果范围锁控制并发。后台作业用当前用户或经核验的等效权限执行，不默认切换为高权限服务账号。

关闭页面不取消后台作业；重新打开后从数据库恢复。停止回复显示与取消 SAP 作业是两种动作。取消只在 P0 核验支持后开放，未支持时显示真实限制。超时不等于作业已经停止，必须核对作业状态。

### 8.4 本次结果如何准确读取

优先顺序：

1. 结果表有运行/批次键：按实际键关联 ReportRunId。
2. 结果表只有明确业务范围与版本：适配器校验范围，并在安全窗口内保存快照。
3. 表会覆盖写且无法区分并发结果：按报表及结果范围串行，或先改造结果关联；不能按“最新时间”猜哪批是本次结果。
4. 没有稳定结果来源：登记为不支持本期结果分析，转后续 ALV 方案。

还要与原 GUI 用户和其他作业协调锁，不能只锁住本应用里的调用。做不到完整范围锁或结果版本校验，就不能宣布支持可靠快照。

TCode 用于定位和授权。SUBMIT 执行程序不等同在 SAP GUI 输入 TCode；程序若依赖 sy-tcode、参数事务默认值、选择屏幕交互或前台控件，必须用经过验证的适配器，不能当作通用直接执行。

报表作业成功但结果关联失败时，状态为结果错误，不能拿旧表数据分析。零行结果是有效业务事实；模型分析失败但结果已保存时允许只重试分析，不能重跑报表。

### 8.5 完成后继续分析

RUN_AND_ANALYZE 在结果 READY 后进入 ANALYZING，再进入 COMPLETED。第一版可以由当前页面的完成轮询触发一次幂等分析请求；页面关闭时保存“结果已就绪、分析待续”，重新打开可恢复，不夸大为离线也一定自动完成分析。

后台分析调度属于后续优化。分析结果始终回写原 TaskId / ReportRunId，不插入用户正在操作的新任务。不要因为后台通知变化把当前聚焦任务强制切走。

## 9. 实施阶段与可交付任务

阶段编号是开发顺序，不代表已完成。实施必须在小风明确开工后进行。

| 阶段 | 内容 | 交付和通过条件 |
|---|---|---|
| P0 基线核验 | 确認试点、内部模型、SAP 接口/权限、结果关联、DDIC/OData 结构 | 试点能力矩阵、冻结协议、阻塞项清单；没有可靠结果来源的报表排除 |
| P1 任务与上下文基础 | 任务数据模型、结果快照、路由、引用消歧、按任务预算、库存/DATA 接入 | 同一聊天跨域不串参数；可继续旧结果；现有功能回归 |
| P2 报表参数与已有结果 | 报表/参数配置、动态表单、参数草稿、结果适配器、历史结果读取 | 参数定义与实际输入分开；只分析已有结果不触发执行 |
| P3 报表后台执行 | 作业提交、运行记录、去重、并发锁、状态卡、结果校验、执行后分析 | 一张试点报表完整闭环；运行中可继续库存和表分析 |
| P4 扩展与交付 | 第二类报表验证、模块扩展指南、联调、部署、恢复和回滚说明 | 证明不是只适配一个报表；完成必验场景与 SAP 证据 |

### P0 详细任务

1. 选择 1 张真实自开发报表，提供 TCode、程序、选择屏幕字段和结果来源；不把示例 ZM001 当真实清单。
2. 核对报表的所有权限检查、后台兼容、sy-tcode 依赖、结果写入/覆盖规则。
3. 核验 SELECT-OPTIONS 范围语义及参数传值长度，不能把多选简单拼成字符串。
4. 核验内部模型名称、端点、预算、JSON 输出能力；不用历史 GLM 测试冒充当前模型验收。
5. 确定结果稳定关联、快照保留、运行用户、最大行数、运行上限和并发策略。
6. 核对新表长文本字段类型、索引、锁对象、SEGW 返回结构和方法名长度。
7. 输出试点能力矩阵和 V1.1 修订（如需要），再进入实现。

### P1 详细任务

1. 新建业务任务、消息关联、数据集索引与快照存储；不改已有审计表的语义。
2. 增加任务服务、上下文组装与意图协议校验。
3. 模块工具正向白名单；修正已有 INVENTORY 误带 SQL 工具的规则。
4. 用户消息归入正确任务；结构化保存参数、引用和待办状态。
5. 库存与 DATA 输出登记为可引用结果；结果权限与来源完整性二次校验。
6. 前端新增本会话任务区及每轮业务标签；保留普通对话入口。
7. 运行验收清单中的路由、引用、长聊天、权限和回归场景。

### P2 详细任务

1. 报表主表/参数表及受控维护方式；首期 SM30 或配置录入即可，不急做完整报表管理后台。
2. 表单控件只按受信任配置生成，支持单值、多值、日期范围、复选框及单选组。
3. 服务端参数校验、转换、默认值来源和草稿版本控制。
4. 结果适配器和受控结果查询；用户可以先分析现有结果。
5. 明确数据时间/业务期间和执行时间是不同字段。

### P3 详细任务

1. 报表白名单与执行权限检查，参数和配置版本绑定。
2. 幂等提交、RequestId 唯一约束、作业关联、异常补偿。
3. 当前用户/等效权限执行；验证报表内部业务授权依然生效。
4. 作业状态与结果状态分开；确保任务状态转换原子化。
5. 前端独立轮询、重连恢复、旧请求/旧任务结果归属。
6. 结果 READY 后运行分析；失败只重试对应步骤。
7. 按 03 清单保存 SAP 激活、作业、结果、审计和前端证据。

### P4 详细任务

1. 第二张参数或结果方式不同的真实报表验证。
2. 完成部署对象清单、依赖顺序、配置键、SEGW 增量与演示说明。
3. 按模块扩展示例证明新增业务不需要重写总 Agent。
4. 关闭功能开关可恢复现有 Agent；已经运行的作业继续可查询。
5. 专项进度写明代码完成、本地通过、SAP 激活、业务验收、生产传输各自状态。

## 11. 验证、发布与回滚

- 文档阶段只验证链接、结构、范围一致性和源码未改；不声明已通过代码构建或业务测试。
- 实施后先跑有意义的 Mock 契约/行为场景、前端构建与界面验证，再完成 SAP 激活和真实报表联调。
- Mock 不能验证 S_TCODE、程序授权、后台作业用户、DDIC 长文本、结果范围锁或真实运行时间。
- SAP 验收包含无权限用户、跨用户任务/结果引用、重复提交、并发报表、作业失败、结果过期及重连。
- 发布必须同步 SE11、锁对象、SEGW metadata、ABAP 类和前端；不能写“只贴类即可”而遗漏建模。
- 回滚通过关闭新入口和执行开关、恢复旧前端/接口；新表保留审计，不直接删除有运行记录的表。
- 回滚前检查活动作业；旧实现不能误把后台任务标记为已停止。

详细通过条件见 [03-验收与场景清单](03-验收与场景清单_V1.0_20261007.md)。

## 13. 技术参考与使用边界

- SAP 支持通过 SUBMIT 的选择参数选项向可执行程序传值，其中 WITH SELECTION-TABLE 使用结构化选择表。实际字段、长度和事件行为需按目标系统验证：[SAP：Filling the Selection Screen of a Called Program](https://help.sap.com/docs/SAP_NETWEAVER_731_BW_ABAP/cfae740a0a21455dbe6e510c2d86e36a/9fdba51a35c111d1829f0000e829fbfe.html?version=7.31.30)。
- SAP 后台作业步骤可以通过 SUBMIT VIA JOB 添加，并指定运行时授权用户；接口组合按试点系统验证：[SAP 7.50：Adding a Job Step with ABAP SUBMIT](https://help.sap.com/docs/SAP_NETWEAVER_750/b07e7195f03f438b8e7ed273099d74f3/4d938d6848846e73e10000000a15822b.html)。
- 选择屏幕支持运行时修改和校验，因此“静态字段”不能替代运行时业务规则：[SAP：Selection Screen](https://help.sap.com/docs/SUPPORT_CONTENT/ABAP/3353523980.html?locale=en-US&state=PRODUCTION)。
- 外部 Skill 仅借鉴规格、证据留痕和数据分析的方法。本功能执行能力必须由 SAP 服务实现，安装 Skill 不会自动增加报表执行接口。
