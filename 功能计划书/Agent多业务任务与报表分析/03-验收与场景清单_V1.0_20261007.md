# Agent 多业务任务与报表分析：验收与场景清单

版本：V1.0  
编写日期：2026-10-07（Asia/Shanghai）  
状态：验收基线；开发完成后逐项记录证据。

## 1. 使用方式

本清单用于 P0～P4 开发验收。每个场景都要记录：测试用户、客户端请求、`SessionId / TaskId / RequestId`、后端日志、SAP 运行编号、结果编号和实际结论。只看到模型回复，不能算通过；必须能在后端或 SAP 中核对关键事实。

验收分为三种结果：

- **通过**：行为、权限、状态和数据都符合预期，并留有证据。
- **有条件通过**：主链路可用，但有明确限制、人工步骤或后续优化项。
- **不通过**：串任务、越权执行、重复执行、参数错位、状态与事实不一致，或旧功能回归。

## 2. 分阶段门槛

| 阶段 | 必须通过的内容 | 未通过时的处理 |
|---|---|---|
| P0 基线 | SAP 版本、试点 TCode、程序名、静态参数、结果来源、权限边界和回滚方式确认 | 不进入建表和接口开发 |
| P1 任务与路由 | 任务创建/恢复、意图路由、跨业务切换、旧会话兼容 | 不接入真实报表执行 |
| P2 报表准备 | 报表白名单、参数表单、校验、确认、幂等键和权限 | 只能使用模拟运行，不得提交 SAP 作业 |
| P3 执行与结果 | 后台执行、状态查询、失败重试、结果绑定、分析引用 | 不开放生产用户 |
| P4 发布验收 | 并发、审计、保留策略、旧功能回归、灰度和回滚 | 保持灰度或回退到旧入口 |

## 3. 必测场景

| 编号 | 场景与输入示例 | 验收重点 | 证据 | 阶段 |
|---|---|---|---|---|
| S01 | “执行一下 ZM001，并分析其结果” | 识别为报表执行+结果分析；创建一个报表任务，不直接猜参数 | 路由 JSON、TaskId、待填参数 | P1 |
| S02 | “运行 ZM001，工厂 1000，日期 2026-09-01 至 2026-09-30” | 参数名称、格式、默认值和范围正确映射；不把自然语言中的说明当成参数 | 参数快照、校验结果 | P2 |
| S03 | 缺少必填参数 | 状态为 `WAITING_INPUT`；只追问缺失项；补填后能恢复原任务 | 前后两次 RequestId、TaskId 不变 | P2 |
| S04 | 输入非法工厂、日期倒置或超大范围 | 后端拒绝；不提交报表；提示可修正内容 | 校验错误、无 ReportRunId | P2 |
| S05 | 用户确认执行 | 只在确认后提交；确认前没有 SAP 作业或读数副作用 | 确认事件、SAP 作业号 | P2/P3 |
| S06 | 相同 `RequestId` 重复点击执行 | 只产生一次 ReportRun；第二次返回原运行状态 | 幂等日志、唯一键、运行记录数 | P2/P3 |
| S07 | 报表未登记或已停用 | 不允许模型临时执行；给出登记/权限提示 | 白名单命中结果、无 SAP 提交 | P2 |
| S08 | 无该 TCode 或程序执行权限 | 拒绝执行并记录审计；不泄露不必要的程序信息 | 权限检查、审计记录 | P2/P4 |
| S09 | 报表后台运行中，用户说“先看库存” | 报表任务保持 `RUNNING`；新建/切换库存任务；两者结果不串 | 两个 TaskId、各自状态 | P3 |
| S10 | 用户说“继续刚才的 ZM001” | 在当前会话中按任务、模块、最近活动找候选；有多个候选时先澄清 | 候选列表、最终 TaskId | P1/P3 |
| S11 | 用户说“分析刚才的报表结果” | 绑定明确 `ArtifactId / DatasetId`；不能把库存结果当报表结果 | 结果引用、数据集摘要 | P3 |
| S12 | 报表执行成功但结果表为空 | 区分“成功但无数据”和“执行失败”；允许用户查看运行参数和时间 | ReportRun、Dataset 状态 | P3 |
| S13 | 报表执行超时或 SAP 状态未知 | 显示 `TIMEOUT / UNKNOWN`；不伪造成功；可继续查询或人工核对 | SAP 作业状态、重试记录 | P3/P4 |
| S14 | 结果分析请求包含“只看前 20 行/按金额降序” | 结果范围、排序和列白名单在后端约束；分析结论可回溯 | 查询审计、DatasetId、分析输入 | P3 |
| S15 | 用户在报表任务中改问“分析 Z自建表” | 新建 DATA 任务或明确切换；报表草稿、参数和运行状态不丢失 | Task 列表、上下文包 | P1/P3 |
| S16 | 先分析自建表，再说“回到报表” | 恢复原 Report 任务；不把表分析条件带入报表参数 | 两个任务的消息和参数快照 | P1/P3 |
| S17 | 普通对话调用旧工具 | 原 `AnalyzeAgent / AnalyzeCode` 链路结果不变；老会话可打开 | 回归用例、接口响应 | P4 |
| S18 | 同一用户多浏览器/多标签页同时执行 | 任务锁、RequestId 和状态机避免重复提交或覆盖参数 | 并发日志、运行记录数 | P4 |
| S19 | 无权读取结果表或结果属于其他用户 | 返回统一拒绝；不通过模型泄露表名、行数或字段值 | 权限审计、响应脱敏 | P3/P4 |
| S20 | 长对话超过上下文预算 | 只发送当前任务上下文包、摘要和结果引用；回复质量不因旧消息堆积明显下降 | token/字符统计、上下文包 | P4 |

## 4. 核心验收断言

### 4.1 路由和任务隔离

1. 每次主动动作都有唯一 `RequestId`，每个可继续业务都有稳定 `TaskId`。
2. `SessionId` 只表示聊天容器，不能作为业务状态或结果主键。
3. 业务切换后，当前任务改变，但旧任务仍可按编号恢复。
4. “刚才、继续、那个结果”等指代不明确时，系统先列候选或追问，不猜唯一对象。
5. 一条消息包含“执行并分析”时可以拆为多个步骤，但仍归属于同一业务任务和同一结果链。

### 4.2 报表执行和结果绑定

1. 未登记 TCode、停用定义、参数校验失败或权限失败，均不得创建真实 SAP 运行。
2. 报表参数以提交时快照保存；后续配置变更不能改写历史运行。
3. `ReportRun`、`Dataset` 和 `Artifact` 的状态只由后端事实更新，模型不能直接写成功状态。
4. 结果分析必须引用明确数据集；分析提示中要能看到来源和时间范围。
5. 失败、超时、未知状态和空结果必须分别展示，不能统称为“没有数据”。

### 4.3 安全和兼容

1. 任务、运行记录、结果和报表定义均按用户/角色/客户端做访问控制。
2. 日志可以追踪动作，但不记录密码、完整敏感参数或不必要的结果明细。
3. 旧接口和普通聊天在新模块未启用时继续工作。
4. 灰度关闭新路由后，已存在的旧会话仍可读取；未完成的后台作业有明确人工处理方式。

## 5. 当前基线结论

截至 2026-10-07，以上场景是计划和验收基线，尚未执行本功能代码测试；当前仓库已有的 Agent、动态 SQL 和前端回归结论不自动等同于本功能通过。进入 P0 后先补齐试点报表、目标 SAP 版本、权限角色和结果来源，再把示例中的 `ZM001` 换成真实对象并建立可重复测试数据。
