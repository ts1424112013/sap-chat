# Agent 多业务任务与报表分析：接口与数据设计

版本：V1.0  
编写日期：2026-10-07（Asia/Shanghai）  
状态：初始设计；P0 核验后冻结字段和 SEGW 变更。

## 1. 设计原则

1. **会话、任务、执行、结果分层**：不能用 `SessionId` 代替 `TaskId`，不能用 Agent 运行记录代替报表运行记录。
2. **后端是事实源**：模型输出的是候选意图和参数；后端决定对象是否存在、是否登记、是否有权限和是否可以执行。
3. **显式引用结果**：用 `ArtifactId / DatasetId / ReportRunId` 关联结果，不让模型仅凭“刚才那个”猜。
4. **向后兼容**：现有 `AnalyzeAgent`、`AnalyzeCode` 和旧会话继续可用；新契约并行接入，验证后再考虑收敛。
5. **配置先简单**：静态参数报表首期采用主表 + 参数明细表；不做通用源码解析器。
6. **接口少而明确**：自然语言入口负责理解和编排；表单提交、后台状态和结果读取使用可重试的结构化接口。
7. **安全默认关闭**：报表读取、报表执行分别设置开关；未登记的 TCode/程序不能因为模型要求而临时加入白名单。

字段名是候选名，最终以目标 SAP DDIC、SEGW 生成规则和现有命名约束为准。ABAP 30 字符方法名、客户字段 MANDT、长文本字段长度、索引和锁对象都要在 P0 核验。

## 2. 标识符和状态

### 2.1 标识符

| 标识符 | 作用 | 生成规则 | 是否可被用户直接输入 |
|---|---|---|---|
| SessionId | 聊天容器 | 现有会话生成逻辑 | 可以作为界面内部标识 |
| TaskId | 一项可继续的业务任务 | GUID/32 字符，唯一 | 可以显示短别名，但后端以完整值为准 |
| RequestId | 一次客户端请求幂等键 | 客户端生成，每次主动动作不同 | 否 |
| AgentRunId | 一次 Agent 编排调用 | 后端生成 | 否 |
| ReportRunId | 一次实际报表运行 | 后端生成 | 可显示 |
| ArtifactId | 一个可引用的结果对象 | 后端生成 | 可显示 |
| DatasetId | 结果数据集版本 | 后端生成 | 可显示 |
| ConfigVersion | 报表定义/参数版本 | 配置变更时递增或使用 GUID | 否 |

用户说“上一次”时，先由后端根据 TaskId、结果类型和创建时间生成候选；模型不能直接编造 ID。

### 2.2 状态

任务状态：

```text
OPEN          可继续对话
WAITING_INPUT 等待用户填写或确认
QUEUED        已排队
RUNNING       正在执行
ANALYZING     结果已就绪，正在分析
PAUSED        用户切换业务或主动暂停草稿
COMPLETED     已完成
PARTIAL       部分完成或结果可用但分析失败
FAILED        失败
CANCELLED     已取消（仅在 SAP 作业确认取消后使用）
EXPIRED       结果或任务超过保留期限
```

报表运行状态和任务状态分开：

```text
ReportRun：CREATED → SUBMITTED → RUNNING → READY / FAILED / TIMEOUT / UNKNOWN
Artifact：CREATED → AVAILABLE / STALE / EXPIRED / DENIED
```

`TIMEOUT` 不自动等于 SAP 作业已停止；`UNKNOWN` 需要继续查询或人工核对。`CANCELLED` 只有拿到真实取消结果才能写入。

## 3. 数据表候选

### 3.1 业务任务表：`ZAI_TASK`

一条记录代表一个跨多轮的业务任务。

| 字段 | 类型建议 | 说明 |
|---|---|---|
| MANDT | MANDT | 客户端 |
| TASK_ID | CHAR32 | 主键 |
| SESSION_ID | CHAR32 | 所属聊天，会话归属校验 |
| PARENT_TASK_ID | CHAR32 | 比较/派生任务的父任务，可空 |
| MODULE_ID | CHAR30 | REPORT / INVENTORY / DATA / CODE 等 |
| INTENT_CODE | CHAR40 | 当前主要意图 |
| TITLE | CHAR120 | 用户可见标题 |
| STATUS | CHAR20 | 任务状态 |
| OWNER | CHAR12 | 创建用户 |
| FOCUS_ARTIFACT_ID | CHAR32 | 当前聚焦结果，可空 |
| CURRENT_VERSION | INT4 | 乐观锁版本 |
| PENDING_JSON | STRING | 待填写项、待确认项；不保存密钥 |
| SUMMARY_TEXT | STRING | 面向模型的短摘要，不作事实源 |
| CREATED_AT | CHAR14 | 创建时间 |
| CHANGED_AT | CHAR14 | 最近更新时间 |
| CLOSED_AT | CHAR14 | 关闭时间，可空 |

`PENDING_JSON` 和 `SUMMARY_TEXT` 可重建，不能代替结构化参数、权限和运行状态。

### 3.2 任务消息关联表：`ZAI_TASK_MSG`

首期建议用关联表，避免直接改现有 `ZAI_CHAT_MSG` 的主键和历史接口；稳定后再评估给消息表增加 TaskId。

| 字段 | 类型建议 | 说明 |
|---|---|---|
| MANDT | MANDT | 客户端 |
| TASK_ID | CHAR32 | 任务 |
| SESSION_ID | CHAR32 | 防止跨会话错误关联 |
| MSG_SEQ | INT4 | 现有消息序号 |
| ROLE | CHAR12 | user / assistant / system |
| RELEVANCE | CHAR12 | CURRENT / SUMMARY / REFERENCE |
| CREATED_AT | CHAR14 | 关联时间 |

原消息正文仍由 `ZAI_CHAT_MSG` 保存。任务上下文只读取被标记为相关的消息或摘要，不复制大段正文。

### 3.3 结果索引表：`ZAI_ARTIFACT`

所有模块的可引用结果共用索引；完整数据按 SourceType 访问。

| 字段 | 类型建议 | 说明 |
|---|---|---|
| MANDT | MANDT | 客户端 |
| ARTIFACT_ID | CHAR32 | 主键 |
| TASK_ID | CHAR32 | 生成任务 |
| SESSION_ID | CHAR32 | 原会话 |
| ARTIFACT_TYPE | CHAR30 | REPORT_RESULT / TABLE_DATA / INVENTORY_RESULT / ANALYSIS |
| SOURCE_TYPE | CHAR20 | ZTABLE / QUERY / SNAPSHOT / INLINE |
| SOURCE_REF | CHAR120 | 结果表、DatasetId 或安全引用 |
| REPORT_RUN_ID | CHAR32 | 报表结果可空 |
| DATASET_ID | CHAR32 | 数据集版本可空 |
| LABEL | CHAR120 | 用户可见标题 |
| STATUS | CHAR20 | AVAILABLE / STALE / EXPIRED 等 |
| ROW_COUNT | INT4 | 行数，未知时用明确标记 |
| SCHEMA_JSON | STRING | 字段、类型、单位和敏感级别 |
| SUMMARY_JSON | STRING | 统计摘要，不代替明细 |
| SOURCE_TIME_FROM | CHAR14 | 数据业务时间起点，可空 |
| SOURCE_TIME_TO | CHAR14 | 数据业务时间终点，可空 |
| CREATED_AT | CHAR14 | 创建时间 |
| EXPIRES_AT | CHAR14 | 到期时间 |
| OWNER | CHAR12 | 结果所有者 |

访问结果时必须再次校验当前用户、SessionId/TaskId 归属、模块权限和结果状态。

### 3.4 报表主表：`ZAI_RPT_DEF`

一条记录代表一个允许被系统发现的报表。它是白名单和表单模板入口，不保存每次业务结果。

| 字段 | 类型建议 | 说明 |
|---|---|---|
| MANDT | MANDT | 客户端 |
| REPORT_ID | CHAR30 | 内部稳定编号 |
| TCODE | CHAR20 | 事务代码，大写 |
| PROGRAM | CHAR40 | 已核验的可执行程序 |
| REPORT_NAME | CHAR120 | 展示名称 |
| DESCRIPTION | STRING | 能力边界和结果口径 |
| REPORT_KIND | CHAR20 | EXECUTABLE / ADAPTER / READ_ONLY |
| RESULT_MODE | CHAR20 | EXISTING_TABLE / ADAPTER / UNSUPPORTED |
| RESULT_REF | CHAR120 | 已核验结果表或适配器标识 |
| EXEC_MODE | CHAR12 | SYNC / BACKGROUND |
| READ_ENABLED | CHAR1 | 是否允许读取已有结果 |
| EXEC_ENABLED | CHAR1 | 是否允许执行 |
| ANALYZE_ENABLED | CHAR1 | 是否允许分析结果 |
| MAX_RUNTIME_SEC | INT4 | 后端硬上限内的报表上限 |
| MAX_ROWS | INT4 | 返回/保存上限 |
| ROLE_RULE | STRING | 角色或权限规则引用，不存密码 |
| CONFIG_VERSION | CHAR32 | 当前配置版本 |
| ACTIVE | CHAR1 | 是否启用 |
| CREATED_AT / CHANGED_AT | CHAR14 | 审计 |

首期不允许模型把 TCode 直接当作 `PROGRAM` 使用；先按 TCode 查活动配置，再核验程序。

### 3.5 报表参数表：`ZAI_RPT_PARAM`

一条记录代表一个选择屏幕输入项。一个报表有多条参数记录。

| 字段 | 类型建议 | 说明 |
|---|---|---|
| MANDT | MANDT | 客户端 |
| REPORT_ID | CHAR30 | 报表 |
| CONFIG_VERSION | CHAR32 | 与主表版本一致 |
| PARAM_ID | CHAR30 | 配置内稳定编号 |
| ABAP_NAME | CHAR30 | P_*/S_* 等真实字段名 |
| LABEL | CHAR120 | 用户显示名 |
| DATA_TYPE | CHAR20 | CHAR / DATE / NUM / BOOL / ENUM / MATERIAL 等 |
| LENGTH | INT4 | 长度 |
| DECIMALS | INT4 | 小数位 |
| REQUIRED | CHAR1 | 是否必填 |
| MULTI_VALUE | CHAR1 | 是否多值 |
| RANGE_ALLOWED | CHAR1 | 是否支持 LOW/HIGH |
| DEFAULT_TYPE | CHAR20 | NONE / STATIC / USER / SYSTEM |
| DEFAULT_VALUE | STRING | 默认值；敏感默认值禁止明文 |
| ALLOWED_OPS | CHAR120 | eq / between / in 等 |
| VALUE_SOURCE | CHAR20 | NONE / DDIC / FIXED / SERVICE |
| VALIDATION_RULE | STRING | 后端可执行规则引用，不能保存模型代码 |
| HELP_TEXT | STRING | 用户提示 |
| SORT_NO | INT4 | 表单顺序 |
| ACTIVE | CHAR1 | 是否启用 |

`MULTI_VALUE` 和 `RANGE_ALLOWED` 不等于把用户输入直接拼进 SQL。执行器要按报表协议转换为选择表或已验证参数。

### 3.6 报表参数草稿/运行表：`ZAI_RPT_RUN`

一条记录代表一次真正提交或准备提交的报表运行。

| 字段 | 类型建议 | 说明 |
|---|---|---|
| MANDT | MANDT | 客户端 |
| REPORT_RUN_ID | CHAR32 | 主键 |
| TASK_ID | CHAR32 | 发起任务 |
| REQUEST_ID | CHAR32 | 幂等键，唯一 |
| REPORT_ID | CHAR30 | 配置编号 |
| CONFIG_VERSION | CHAR32 | 执行时配置版本 |
| TCODE | CHAR20 | 执行快照 |
| PROGRAM | CHAR40 | 执行快照 |
| PARAMS_JSON | STRING | 已规范化参数快照，不保存密钥 |
| PARAMS_HASH | CHAR64 | 参数一致性/去重 |
| STATUS | CHAR20 | CREATED/SUBMITTED/RUNNING/READY/FAILED/TIMEOUT/UNKNOWN |
| SAP_JOB_NAME | CHAR32 | 后台作业名，可空 |
| SAP_JOB_NUMBER | CHAR8 | 后台作业号，可空 |
| RESULT_ARTIFACT_ID | CHAR32 | 结果索引，可空 |
| STARTED_AT / FINISHED_AT | CHAR14 | 运行时间 |
| ROW_COUNT | INT4 | 结果行数 |
| ERROR_CODE | CHAR40 | 脱敏错误码 |
| ERROR_MESSAGE | STRING | 用户可读脱敏错误 |
| CREATED_BY | CHAR12 | 请求用户 |

执行时参数冻结在本表。用户后续修改草稿不能改变已经提交的运行。

### 3.7 报表运行步骤/审计表：`ZAI_RPT_STEP`（建议）

记录解析、授权、提交、状态查询、结果绑定、分析等阶段。不要把完整敏感参数和完整业务明细写进 Trace。

| 字段 | 说明 |
|---|---|
| REPORT_RUN_ID / TASK_ID | 归属 |
| STEP_NO | 顺序 |
| PHASE | RESOLVE / VALIDATE / SUBMIT / POLL / RESULT / ANALYZE |
| STATUS | OK / DENIED / ERROR / TIMEOUT |
| ELAPSED_MS | 耗时 |
| SAFE_SUMMARY | 脱敏摘要 |
| CREATED_AT | 时间 |

## 4. 结构化意图协议

### 4.1 Agent 规划输出

模型只能输出候选计划，后端二次校验。字段建议：

~~~json
{
  "intent": "RUN_AND_ANALYZE_REPORT",
  "module": "REPORT",
  "object": {"kind": "TCODE", "value": "ZM001"},
  "task_ref": {"mode": "CREATE_OR_RESUME", "task_id": ""},
  "params": {},
  "artifact_refs": [],
  "needs_user_input": true,
  "needs_confirmation": false,
  "next_action": "GET_REPORT_PARAMETERS",
  "reason": "用户要求执行并分析，但缺少报表参数"
}
~~~

后端必须检查：intent 是否注册、module 是否允许、object 是否存在、任务是否归属当前用户、参数是否符合配置、动作是否需要确认。任意失败都返回可读的补充信息，不调用执行器。

### 4.2 AnalyzeTask 输入

建议新增接口与现有 AnalyzeAgent 并行：

~~~json
{
  "SessionId": "...",
  "TaskId": "...",
  "Question": "执行一下 ZM001，并分析其结果",
  "ModelId": "AUTO",
  "ClientRequestId": "...",
  "FocusedArtifactId": "..."
}
~~~

首期兼容：旧客户端不传 TaskId 时，由后端创建或恢复任务；旧 AnalyzeAgent 不改变已有响应字段。新返回增加可选字段：

~~~json
{
  "TaskId": "...",
  "Intent": "RUN_AND_ANALYZE_REPORT",
  "Module": "REPORT",
  "TaskStatus": "WAITING_INPUT",
  "NeedsInput": true,
  "NeedsConfirmation": false,
  "PendingParamsJson": "[...]",
  "ArtifactRefsJson": "[]",
  "OperationId": "...",
  "Answer": "请填写工厂和日期范围",
  "TraceJson": "[...]",
  "AnalysisJson": "{}"
}
~~~

### 4.3 结构化辅助接口

| 接口 | 用途 | 是否改变业务数据 |
|---|---|---|
| `Tasks` | 读取当前用户可见任务及状态 | 否 |
| `TaskContext` | 读取任务摘要、待办和结果索引 | 否 |
| `ReportDefinitions` | 获取可用报表/参数元数据 | 否 |
| `StartReportRun` | 用已确认参数创建幂等运行 | 会创建运行记录并可能提交作业 |
| `ReportRunStatus` | 轮询 SAP 作业和结果状态 | 否 |
| `ReportResult` | 读取结果摘要、字段、分页/聚合数据 | 否 |
| `TaskAction` | 暂停、恢复、重新分析、重新执行（动作白名单） | 视动作而定 |

P0 决定是否直接扩展现有 SEGW，或先由 `AnalyzeTask` 返回必要结构；不得在未确认 metadata 的情况下直接修改现有接口。

## 5. 报表工具契约

| 工具 | 关键输入 | 关键输出 | 必须校验 |
|---|---|---|---|
| `resolve_report` | TCode/名称/任务引用 | ReportId、名称、可用动作 | 当前用户可见、配置活动、对象类型 |
| `get_report_parameters` | ReportId、ConfigVersion | 参数 Schema、默认值来源 | 不返回敏感默认值，版本一致 |
| `validate_report_params` | ReportId、参数对象 | 规范化参数、错误列表 | 类型、必填、范围、值域、权限 |
| `start_report_run` | ReportRun 请求、确认凭证 | ReportRunId、状态 | 幂等、权限、并发、执行开关 |
| `get_report_status` | ReportRunId | 作业/结果状态、下一次轮询建议 | 归属、状态真实来源 |
| `get_report_result` | ArtifactId/ReportRunId、查询计划 | Schema、汇总、受限数据集 | 结果状态、权限、范围、单位 |
| `analyze_artifact` | ArtifactId、分析问题 | 结论、数据集、图表 | 结论数字可溯源 |
| `rerun_report` | 历史 ReportRunId、修改项 | 新 ReportRunId | 不覆盖旧参数/结果 |

首期所有报表工具只对 REPORT 模块注入；库存和 DATA 模块不能因为同一轮模型请求而自动获得报表执行工具。

## 6. 幂等、并发和错误

- 同一 `ClientRequestId` 只允许产生一个逻辑动作；网络重试返回原结果。
- 用户主动重跑必须使用新的 RequestId，并在 UI 标明“新运行”。
- Task 的版本更新使用乐观锁；旧响应不能覆盖新焦点和新状态。
- 前端请求令牌只能保护显示归属，不能替代后端幂等。
- 运行中切换业务不取消原 ReportRun；任务卡仍能查看。
- 作业提交成功但 HTTP 断开：重连后按 RequestId/报告参数哈希查找，不盲目重复提交。
- 作业失败、结果失败、分析失败分别呈现；可单独重试可重试步骤。
- 结果过期、权限变化、来源范围不确定时拒绝分析，提示重新取数或重新执行。
- 任何模型无法完成的动作不能通过降级答案声称“已执行”。

## 7. 权限与审计

至少分四层：

1. 当前用户是否启用 Agent/业务模块。
2. 是否可查看报表定义和参数帮助。
3. 是否有该 TCode/程序/业务数据的执行权限。
4. 是否可以读取该 Task、ReportRun、Artifact 和结果字段。

TCode 白名单、程序映射、用户角色、报表内部授权和结果表权限不能只放前端。模型不参与授权决定。审计至少记录用户、动作、对象、任务、请求、配置版本、参数哈希、SAP 作业、结果状态、错误码和时间。

## 8. 上下文包格式

模型每轮收到的业务上下文建议是可审计 JSON，而不是拼接全量聊天：

~~~json
{
  "session": {"id": "...", "owner": "..."},
  "current_task": {
    "id": "...",
    "module": "REPORT",
    "intent": "RUN_AND_ANALYZE_REPORT",
    "status": "WAITING_INPUT",
    "pending": ["P_WERKS", "P_DATE_FROM", "P_DATE_TO"]
  },
  "related_tasks": [
    {"id": "...", "module": "INVENTORY", "status": "COMPLETED"}
  ],
  "artifacts": [
    {"id": "...", "type": "REPORT_RESULT", "label": "ZM001 上次结果", "status": "AVAILABLE", "row_count": 2486}
  ],
  "recent_messages": [],
  "policy": {"max_rows": 200, "allow_execute": true}
}
~~~

上下文包内的 `policy` 由后端生成，模型不能修改。工具返回结果只带本轮所需的摘要和受限数据；完整结果通过 Artifact 工具再次读取。

## 9. 向后兼容与迁移顺序

1. 不改现有 `ZAI_CHAT_MSG`、`ZAI_CHAT_SESS` 的主键和旧查询语义。
2. 新表与新接口先旁路记录，不改变现有 AnalyzeAgent 的成功路径。
3. 前端用能力探测确认新接口存在；不存在时继续旧 Agent。
4. 按用户/角色打开 TASK_CONTEXT_ENABLED，再打开 REPORT_READ_ENABLED，最后才打开 REPORT_EXEC_ENABLED。
5. 每次启用前保存 metadata、DDIC 对象、类源码、前端包和配置快照。
6. 失败时关闭新开关即可停止新入口；保留已完成任务和审计，避免孤儿作业。
