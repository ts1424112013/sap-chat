## 0. 一页看懂

- **问题**：让模型自己写 SQL 回答业务问题，最大的风险不是语法错，而是 SQL 跑通了、数字却错了（口径、状态、单位、重复计数）；同时 SQL 只按「整张表」检查权限，标准报表会按工厂 / 公司代码检查，SQL 不会。
- **分流**：
  - **普通用户**：业务问题先找**已登记的报表**（公司口径、行级权限都由报表程序把关）。模型的工作是找对报表、把用户话里的值填进参数卡，用户核对后执行，结果出来再回答原问题。
  - **IT**：可以自由写 SQL，由 SAP 经 **ADT 的 SQL 控制台接口**直接执行（用本人权限，执行前过灵犀的 SQL 守卫并审计），自动执行，不用 IT 一步步确认。
  - 没有报表能回答的问题：如实说明；第二批记下来，由 IT 写成**查询模板**或开发成报表，再开放给普通用户。
- **同时修 SQL 成功率**：按 `ZAI_SQL_LOG` 的失败原因，把能机械修正的写法在守卫里自动改对。

## 1. 依据：ZAI_SQL_LOG（2026-10-12 ~ 11-05）

159 条，成功 75 条（47%），失败 84 条，没有 REJECTED。失败原因：

| 原因 | 条数 | 第一批怎么处理 |
|---|---|---|
| 函数括号内没空格（`COUNT(*)`、`SUM(X)`、`COUNT(Z~WERKS)`） | 50 | 守卫自动补空格 |
| SQL 超过 200 字符被截断 | 21 | 10-28 已修，现场已确认 |
| UNION 被拼了 `UP TO n ROWS` | 6 | 执行器遇 UNION 不拼 `UP TO` |
| `\|\|` 拼接 | 2 | 守卫自动改 `&&` |
| 单号补零补多了 | 3 | 域卡写明补零后长度等于字段长度 |
| 其他（UNION 各段类型不一致、FROM 子查询） | 2 | 域卡不再推荐 UNION ALL 合并 |

重放估算：同一批语句修完后最多约 97% 能编译通过。这只是**编译**成功率的上限，答案对不对要靠第 2 节的分流来保证。

## 2. 普通用户：业务问题先找报表

```text
用户：「ABG1 工厂今天开的工单」
  → 系统说明里列出用户有权限的报表（每张一句说明；多于 40 张时按与问题的相关度挑）
  → 模型选报表：一张明显合适 → 直接用；两三张都可能 → ask_user 让用户选；没有 → 如实说明
  → get_report_parameters：看参数编号、类型、单值 / 多值 / 范围、说明、选项
  → open_report(tcode, params={工厂: ABG1, 创建日期: 20261109,20261109})
  → 参数卡已预填，卡片说明「已按你的话预填: …」→ 用户核对、提交 → 后台执行
  → 结果出来：先回答原问题（「今天开了 12 张」），再说明来自哪张报表；统计用 query_result 在全部行上算
```

要点：
- 预填只填用户话里已经给出的值，没说的不猜；参数卡上登记了默认值的照常带出。
- 报表里没有的参数编号不带入，卡片说明写出来，方便发现模型填错。
- 执行仍要用户在卡上提交，模型不能直接执行报表。

**效果取决于报表登记的质量**：报表说明（能看到什么）和参数说明（日期参数到底是创建日期还是开始日期）写得越清楚，选报表、填参数就越准。建议先给最常用的 30 ~ 50 张报表补齐说明（可用 ADT 读报表源码生成草稿，人工审核）。

## 3. IT：自由 SQL 经 ADT 自动执行

- 工具 `adt_run_sql`：只下发给开了 ADT、开了数据分析、且配置 `BROWSER_ADT_SQL = X` 的人。
- 浏览器调 ADT `datapreview/freestyle`（Eclipse 的 SQL 控制台用的接口）执行：SAP 自己的解析器，没有灵犀执行器「拼进 ABAP 程序再生成」那一层，所以截断、`INTO TABLE` 冲突、UNION 的 `UP TO` 这类问题都不会出现，也没有代码注入的风险。
- 执行前浏览器先向 SAP 报备，SAP 用同一个 `ZCL_AI_SQL_GUARD` 校验（只读单条 SELECT、敏感表、表权限），不通过就不发；执行结果记进 `ZAI_SQL_LOG`，和 run_sql 同一张审计表。
- 用的是 IT 本人的权限：能查到的和他在 Eclipse / SE16 里能查到的一样，灵犀没有额外放开。
- 回答附最后执行的 SQL，并说明是直接查表、口径未与公司报表核对。

## 5. 风险与未验证

- `datapreview/freestyle` 的真实返回格式只按公开资料和本地模拟写，**还没在 SAP 上跑过**。
- 报表选得准不准，取决于报表说明的质量；先在 QAS 用 10 ~ 20 个真实问题试，看选错的是哪类。
- 自由 SQL 只给 IT；`S_TABU_DIS` 权限很宽的账号仍能查到成本、价格类表，必要时在守卫的敏感表清单里补充。
