# 新引擎界面改版 —— 方案 V1.1

> 日期：2026-11-08 ｜ 状态：方案，未开工 ｜ 前置：新引擎 M1 ~ M3 与上下文修复（《03》〇-AF ~ 〇-AI）
> 样式：对话里确认的第三版示意 ——「Claude Code 的结构和节奏，正常界面的排版」（不要终端感）
> V1.1（同日）：新增第 3 节「每个节点都有说明」——模型在关键节点说一句、每一步自动配一句结果、深度思考可展开；后续章节顺延

---

## 1. 要解决什么

新引擎能给出的过程信息比原引擎丰富得多：计划、每一步工具、改文件、数据表、技能、压缩。但界面还是按原引擎的方式展示：

| 现在 | 问题 |
|---|---|
| 过程全收在回答上方的「已完成 · 3 轮 · 3 次工具」折叠块里 | 要点开才看得到，只剩工具名和一个参数，看不出它是怎么得出结论的 |
| 计划只是一行「计划 ✓…○…」文字 | 进度不直观 |
| 模型在步骤之间说的话被截成 300 字，混在步骤里 | 读不顺 |
| 改文件弹窗确认 | 挡住页面，看不到上下文；每次都要点 |
| 数据表全堆在回答最后 | 不知道是哪一步查出来的 |
| 没有上下文用量、次数、停止状态的总览 | 用户不知道它还要跑多久、离上限多远 |
| 刷新或重开会话后只剩最后的回答 | 过程丢了，没法回看 |

目标：新引擎的一次运行，读起来像 Claude 桌面应用里看 Claude Code 干活——一句话说明打算 → 一行一步 → 结果就地出现 → 需要确认时就地确认 → 结论。

## 2. 样式规范（第三版）

整体：正常字体（灵犀现有字体），**等宽字体只用在路径、料号、参数、代码上**；不画时间线竖线、不用大卡片，靠缩进和留白分层；颜色只用灵犀现有的主色（蓝）、成功（绿）、等待（琥珀）、失败（红）。

| 元素 | 样子 | 交互 |
|---|---|---|
| **说明** | 模型在工具之间说的话，普通段落，完整显示（不截断） | — |
| **工具行** | 一行：状态图标 + 工具中文名（加粗）+ 主要参数（灰色，过长省略）；执行中图标转圈（蓝），完成换成该工具的图标（绿），失败红色 ✕ | 悬停整行浅色高亮、右侧出现耗时；点击展开 / 收起详情（参数、返回摘要），箭头随之翻转 |
| **结果行** | 工具行下面缩进一行灰色小字：一句话结果（如「找到 1 份：成品可用库存，1,727 行」「SAP 在全部 1,727 行上排序，返回 10 行」） | — |
| **数据卡** | 产出数据的那一步下面就地出现：标题 + 行数 + 「表格 / 图表」切换；默认 5 行，「展开」看全部；「导出 CSV · 加入组合 · 复制」 | 沿用现有表格、图表、组合分析的能力 |
| **计划** | 工具行样式的标题「计划 · 2 / 3 完成」+ 缩进的勾选清单；当前项勾选框蓝边，完成打勾划掉 | 随模型更新实时变化 |
| **确认面板** | 缩进的边框面板：标题（「要新建这个文件吗？」）+ 路径与行数 + 带行号的改动对比（新增绿、删除红）+ 三行编号选项 | 点选或按 1 / 2 / 3；选完收成一行结果（「已写入 11 行 · 原样已备份 · 撤回」/「你拒绝了…」） |
| **状态行** | 运行中固定在过程最下方：转圈 + 带流光的动作词（「查询中…」「排序中…」「整理回答…」）+ 已用秒数 | 等确认时变成琥珀色「等你确认」 |
| **回答** | 普通段落，逐字打出；下面一行灰色小字「完成 · 4 次模型 · 3 个工具 · 6.8 秒」 | 沿用现有复制、点赞等 |
| **输入区信息** | 输入框下一行灰色小字：新引擎 · 模型、当前文件夹、上下文用量、模型 / 工具次数（对上限）、停止 | 停止 = 现有的停止生成 |

另外几种步骤的样子：使用技能（一行「使用技能：采购未清分析」）、对话压缩（一行灰字「对话较长，已自动压缩」）、子任务（工具行，展开看子任务的结论）、参数卡（沿用现有报表 / Fiori 参数卡，出现在对应那一步下面）、出错（红色工具行 + 结果行写原因）。

## 3. 每个节点都有说明

**现状**：模型调工具时可以顺带说一段话，也可以不说；新引擎的提示词没有要求，DeepSeek 不开思考时经常只调工具不说话。像「分析工单目前的状态」这类任务，过程里可能连着几个「表结构」「执行查询」，中间没有一句解释。

**做法：两层说明，再加可选的思考**

1. **模型在关键节点说一句**（提示词规则，引擎 `BASE_PROMPT` 增加）：
   - 开始时：一句话说打算怎么做（先查什么、再看什么）；
   - 拿到重要发现时：一句话说看到了什么、接下来往哪查（如「已下达的里有 41 张超过计划完工日，接着看卡在哪个工序」）；
   - 要用户确认之前：一句话说为什么要这么做；
   - **不要求每次调工具都说**：公司模型输出约 37 字 / 秒，每句话多 1～2 秒，每步都说一次任务会多出十几秒。简单的连续查表、读文件不说。
   - 说明要短（一句、不超过 40 字），不重复工具名，不写客套话。
2. **每一步自动配一句结果**（不花模型时间，引擎按工具和返回生成，即第 7 节的 `summary`）：

   | 工具 | 结果句示例 |
   |---|---|
   | 表结构 | 工单表头 AFKO，48 个字段 |
   | 执行查询 / 数据分析 / 调用函数 | 查到 326 行（回填给模型 200 行）；分组时写组数 |
   | 查询结果 | 按状态分组：已下达 210、部分报工 86、待收货 30（取前 3 组） |
   | 我的结果 | 找到 2 份：成品可用库存 1,727 行；…… |
   | 读文件 / 搜内容 / 列目录 | 读了第 1–500 行（共 1,280 行）/ 3 处匹配 / 12 个文件 |
   | 写文件 | 已写入 11 行 / 你拒绝了 |
   | 参数卡 | 已生成 ZDPMM702 的参数卡 |
   | 失败 | 失败原因（如「没有表 ZXX 的查看权限」） |

   取不到结构化信息时，退回「返回 N 字」。
3. **深度思考（可选）**：用户打开「深度思考」时，DeepSeek 每轮先输出一段思考过程（网关返回在 `reasoning_content`）。引擎把它作为 `think` 事件交给界面，挂在这一轮的说明 / 工具行上方，显示为一行灰色「思考 · 12 秒」，**默认收起**，点开看全文。不开深度思考时没有这一行。思考内容不写进会话正文（和原引擎一致）。

**效果示意**（「分析工单目前的状态」）：

> 先查工单表头和状态，按状态分组看分布，再找逾期的。
> 计划 · 0 / 3　☐ 查工单表结构　☐ 按状态统计　☐ 找逾期工单
> **表结构** AFKO　→ 工单表头 AFKO，48 个字段
> **执行查询** 按状态分组　→ 326 张未完工：已下达 210、部分报工 86、待收货 30
> 已下达的里有 41 张超过计划完工日，接着看卡在哪个工序。
> **执行查询** 逾期工单的工序确认　→ 41 张中 29 张卡在装配工序
> （结论……）

## 4. 新的交互

1. **就地确认 + 「本次都允许」**：改文件、以后的写入类工具（料号 / BOM、MCP 写工具）都用同一个确认面板。选「本次运行都不再询问」后，这次运行里同类操作自动通过，并在结果行注明「已按本次允许自动写入」。只在本次运行有效，下次提问重新询问。
2. **键盘**：确认面板出现时按 1 / 2 / 3 选择；`Esc` 停止运行。鼠标始终可用（按你的习惯以鼠标为主，键盘是补充）。
3. **滚动**：运行中停在底部时自动跟随；用户往上翻看时不再强行拉回，右下角出现「回到最新」小按钮。
4. **收起**：一次运行结束后，回答上方出现「收起过程（6 步）」；收起后只剩一行摘要，再点展开。全局可在设置里选「默认展开 / 默认收起已完成的过程」。
5. **复制**：工具行详情里的参数、SQL、路径可一键复制。

## 5. 新引擎成为主角后的简化

| 现在 | 改为 | 原因 |
|---|---|---|
| 输入框下「新引擎」开关 | 稳定后默认开启，开关移到设置；原引擎作为「兼容模式」保留 | 不占输入区位置 |
| 场景按钮一排（报表执行、Fiori 报表、数据分析、代码分析、自动） | 默认「自动」；其余收进一个下拉「指定场景」 | 新引擎会按问题挑工具；场景仍决定 SAP 开放哪些工具，不能删 |
| 技能下拉 | 改名「指定技能（可选）」，默认不选 | 模型会自己读相关技能 |
| 原引擎的「边跑边看」轮询、「已思考」摘要块 | 新引擎不使用（原引擎保留原样） | 新引擎有完整过程 |
| 改文件弹窗 | 删除，改为就地确认面板 | — |

保留不动：左侧会话列表、报表 / Fiori 参数卡、Fiori「交给模型分析」闸门、组合分析面板、定时任务、设置与管理页。

## 6. 刷新后能回看过程

现在过程只在浏览器内存里，刷新就没了。改为：

- 引擎在 `/run/finish` 时把**精简的过程记录**交给 SAP：每步只存类型、工具名、主要参数（≤ 200 字）、结果一句话、状态、耗时；数据集只存「第几个数据集」的引用（数据本身仍按现有方式恢复）；不存文件内容、源码、对比全文。
- SAP 存进 `ZAI_BSTEP`（ADT 方案里设计的逐步审计表，本方案和它共用：谁先做谁建），按会话 + 消息序号关联。
- 重开会话时，`ResultRestore` 读回过程记录，按同样的样式画出来（全部是已完成状态，详情可展开但没有返回全文）。

这一节同时补上新引擎「只有一行汇总、没有逐步审计」的缺口。

## 7. 改动范围

**引擎（`agent-bundle`）**——事件补全，界面只消费事件：
- `BASE_PROMPT` 加「关键节点说一句」的规则（第 3 节第 1 条）。
- `thinking` 改名 `say`，传完整文字（不再截 300 字）。
- `tool_end` 增加一句话结果 `summary`（按第 3 节的表生成：SAP 工具从返回 JSON 里取行数 / 条数 / 分组前几项；文件工具取行数 / 字节数；失败取原因）和返回摘要 `preview`（≤ 1000 字，供展开详情）。
- 新事件 `think`：模型回应里的思考内容（`reasoning_content`，LangChain 放在 `additional_kwargs`）连同耗时交给界面；不进会话正文。需确认 SAP 转发时保留这个字段（`forward_openai` 原样透传回应，应无需改动）。
- `datasets` 事件带上工具调用编号，界面据此把数据卡挂在对应那一步下面。
- 新事件 `usage`：每次模型回应带回 `prompt_tokens`（网关返回时），界面据此显示真实的上下文用量（没有时用估算）。
- 确认回调支持「本次都允许」：`confirm` 返回 `{ approved, always }`，引擎在本次运行内记住。
- `/run/finish` 附带精简过程记录（§6）。

**前端**
- 新文件 `controller/mixin/RunTimeline.js`：把引擎事件画成第 2、3 节的样式（说明、工具行、结果行、数据卡、计划、确认面板、状态行、默认收起的「思考」行），处理展开 / 收起、滚动跟随、键盘。
- `BrowserAgentPanel`：确认从 `Dialog` 改为调用时间线里的就地面板；状态行、输入区信息栏。
- `App.controller`：新引擎的消息不再走 `_applyLive` / `_liveHtml`（原引擎照旧）。
- `ResultRestore`：重开会话时恢复过程记录。
- `style-gale.css`：新增一组样式（浅色 / 深色都要）。
- 输入区：场景、技能收进下拉；「新引擎」开关移到设置（第二期）。

**SAP**
- `ZAI_BSTEP`（若 ADT 方案还没建）+ `browser_finish` 写过程记录；读取过程记录的接口（放在 `/sap/bc/zai_agent`，不动 SEGW）。

**测试**
- 引擎自测：事件字段（`say` 全文、各类工具的 `summary`、`think`、`datasets` 带编号、`usage`、本次都允许）；提示词里有「关键节点说一句」规则。
- 前端测试：时间线渲染（各类步骤、出错、停止、拒绝）、确认面板键盘、刷新恢复。
- 演示模式全流程走一遍；浅色 / 深色截图确认。

## 8. 分期与工作量

| 期 | 内容 | 估计 |
|---|---|---|
| **第一期** | 引擎事件补全（含节点说明规则、各工具结果句、思考）；时间线渲染（说明、工具行、结果行、计划、数据卡就地、状态行、思考行、输入区信息）；就地确认面板 + 本次都允许 + 键盘；滚动跟随与收起；浅色 / 深色 | 2.5 天 |
| **第二期** | 刷新后回看过程（`ZAI_BSTEP` + 恢复）；输入区简化（场景 / 技能收进下拉，新引擎开关移到设置，默认开启）；真实上下文用量 | 1.5 天 |

原引擎的界面在两期里都不动，关掉新引擎就是现在的样子。

## 9. 验收

1. 演示模式、新引擎：问「上月工厂 1000 库存最高的 10 个料号，存一份 CSV 到文件夹」（选好文件夹）——依次出现说明、计划（逐项勾掉）、「我的结果」「查询结果」两行（结果行有一句话、数据卡挂在「查询结果」下面）、确认面板（按 1 写入）、回答与完成统计；状态行动作词随步骤变化；输入区显示上下文用量与次数。
2. 点工具行展开 / 收起详情；悬停显示耗时；数据卡「表格 / 图表」切换、「展开」。
2a. 每个工具行下面都有一句结果（按第 3 节的表）；在 SAP 上用真实模型问「分析一下工单目前的状态」：开头有一句打算、中间有重要发现时的一句说明，不是每一步都说。
2b. 打开「深度思考」再问：每轮上方出现默认收起的「思考 · N 秒」，点开有全文；关掉深度思考就没有这一行。
3. 确认面板按 3 拒绝：结果行「你拒绝了…」，回答如实说明没写入；选 2 后同一次运行再写文件不再询问，结果行注明自动写入。
4. 运行中往上翻：不被拉回底部，「回到最新」可用；`Esc` 停止：状态行消失，未完成的工具行标「已停止」。
5. 运行结束后「收起过程」可用。
6. （第二期）刷新页面、重开会话：过程按同样样式恢复。
7. 浅色、深色各截图一套给你确认。
8. 关掉新引擎：原引擎界面与现在完全一致；`npm run test:frontend` 全过。

## 10. 风险

| 风险 | 应对 |
|---|---|
| 模型不遵守「关键节点说一句」（说太多或完全不说） | 每一步都有自动结果句兜底，过程照样看得懂；说太多时在验收里调提示词措辞 |
| 节点说明拖慢运行 | 只在三类关键节点说、每句不超过 40 字；验收时对比开关规则前后的耗时 |
| 过程变长，回答被挤到很下面 | 结束后可一键收起；设置里可选默认收起 |
| 模型在步骤间说很多话 | 正常显示（这是它的思路）；超长的段落折叠到 3 行，可展开 |
| 网关不返回 token 用量 | 显示估算值并标「约」 |
| 过程记录占 SAP 存储 | 只存精简字段，单次运行上限 200 步；按现有会话清理策略一起清 |
