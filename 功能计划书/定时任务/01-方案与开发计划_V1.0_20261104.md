# 定时任务：方案与开发计划

版本：V1.0；编写日期：2026-11-04（Asia/Shanghai）。状态：**方案已定（D1–D4 见 §13），未开发**。

## 1. 要解决的事

现场有些报表每天、每周都要看（例如每天早上看成品可用库存、每周一看未清采购），现在只能每次手动打开灵犀、填参数、提交、等结果。希望设定一次后自动按时运行，打开灵犀就能看到最新结果，需要时由灵犀顺带给出分析。

## 2. 范围

| | 一期（本方案） | 二期（以后再说） |
|---|---|---|
| 定时跑什么 | **报表执行**（含登记成报表的函数）和 **Fiori 报表** | 数据分析问题（查表 / SQL） |
| 跑完做什么 | 存成结果；**可选**：让灵犀按设定的问题分析 | — |
| 结果怎么送达 | 系统里看：每个定时任务一个专属会话 + 未读标记 + 运行记录 | 邮件（要 SAP 配好 SCOT 邮件服务器） |
| 怎么创建 | 结果卡上「设为定时」；「定时任务」页面新建 | 聊天里说"每天 8 点帮我跑…"（属于写操作，要先做确认卡） |
| 谁能建 | 所有开通的用户；管理员能看到并停用所有人的 | — |

## 3. 用户流程

1. **从结果卡创建**：报表执行 / Fiori 报表跑出结果后，结果卡工具条点「设为定时」。弹出设置框，参数预填成这次运行的参数：
   - 名称（默认「报表名 · 每天 08:00」）；
   - 频率：每天 / 每周（勾选星期几）/ 每月（几号，可选「最后一天」）/ 每 N 小时；时间点；
   - 日期参数逐个选「固定日期」还是「相对日期」（今天、昨天、N 天前、本周一、本月第一天、本月最后一天、上月第一天、上月最后一天、今年第一天），见 §6；
   - 跑完让灵犀分析（可选）：填一句问题，例如「看库存最高的前 10 料号，和上次比有什么变化」；
   - 保存。
2. **在「定时任务」页面创建**：选报表 → 填参数卡 → 同上设置。
3. **到点后**：后台自动运行。结果和分析写进这个定时任务的专属会话「定时：<名称>」，侧栏这一行出现未读点；登录时提示「有 N 个定时任务有新结果」。
4. **管理**：「定时任务」页面列出自己的定时任务（名称、来源、频率、下次运行、上次结果、状态），可以暂停 / 恢复、修改、删除、立即运行一次，展开看最近的运行记录（时间、状态、行数、耗时、失败原因，点击跳到对应结果）。管理员多一个「全部用户」页签，可以停用任何人的定时任务。

## 4. 运行机制

### 4.1 用谁的身份跑

**每个定时任务以创建人自己的身份建一个 SAP 周期后台作业**（用户在页面上点保存，后端在这次 OData 请求里调 `JOB_OPEN` / `SUBMIT … VIA JOB` / `JOB_CLOSE`，作业用户就是他本人）。所以到点运行时看到的数据、受到的权限检查，和他手动执行完全一样，不会越权。

不采用「一个调度作业用技术用户统一跑」：那样所有定时任务都以技术用户的权限运行，要么越权，要么还得给技术用户 `S_BTCH_NAM` 去冒用他人身份，安全上更麻烦。

### 4.2 作业怎么排

SAP 周期作业本身只支持「每 N 分钟 / 小时 / 天 / 周 / 月」，不支持「周一到周五」「每月最后一天」这类规则。做法：

- 频率是每天 / 每周 / 每月的，一律建成**每天在设定时间点运行**的作业；每 N 小时的建成**每 N 小时**的作业。
- 作业步骤是新程序 `ZAI_SCHED_RUNNER`（参数 = 定时任务号）。它先读定时任务：今天不是勾选的星期几、不是设定的日期，或者定时任务已暂停 / 被管理员停用，就直接结束，不跑报表。
- 作业名 `ZAI_SCHED_<定时任务号前 8 位>`，作业名和作业号存进定时任务表，修改 / 暂停 / 删除时用。
- **修改频率或时间**：删掉旧作业，按新设置重建。**暂停**：删掉作业，状态记为暂停；恢复时重建。**删除**：删作业 + 定时任务记录（运行记录和已有结果保留，按现有规则过期）。
- **管理员停用别人的**：只把状态改成「管理员停用」，运行程序看到后直接结束。不去删别人的作业（那需要 `S_BTCH_ADM` 权限）。主人下次打开页面时看到状态和原因。

### 4.3 两种来源怎么跑

| | 报表执行 | Fiori 报表 |
|---|---|---|
| 现有链路 | `ZCL_AI_REPORT_SERVICE=>start_run`：建运行记录 + 另起一个后台作业跑报表；页面轮询 `get_run_status` 推进状态，READY 时登记结果 | `ZCL_AI_FIORI_REPORT_SERVICE=>run`：同步取数（RFC 新会话 `Z_AI_ODATA_GET`），存进 `ZAI_FRPT_RUN` / `ZAI_FRPT_DATA` 并登记结果 |
| 定时任务里 | 运行程序调 `start_run`，然后每 15 秒调一次 `get_run_status`，直到 READY / FAILED 或超过等待上限（默认 30 分钟）。结果登记沿用 `get_run_status` 的逻辑 | 运行程序直接调 `run`，同步返回 |
| 改动 | 现有类不用改，只是由运行程序代替页面去轮询 | 现有类不用改 |

两种来源都用定时任务自己的任务号和专属会话号调用，结果就挂在这个会话上。每次运行都用新的请求号（`ClientRequestId`），不会被幂等逻辑当成同一次。

### 4.4 跑完让灵犀分析（可选）

结果就绪后，如果设置了分析问题，运行程序调 `ZCL_AI_AGENT_SERVICE=>analyze_agent`（会话 = 专属会话，问题 = 设定的问题，聚焦结果 = 本次结果号）。这个方法不依赖页面，后台作业里可以调；调模型走 HTTP（`cl_http_client`），后台作业里也能发。分析会用上 11.4 的全量摘要和 `query_result`，大结果也是在全部数据上算的。

- 问题里可以说「和上次比」：专属会话里有上一次的结果和分析，灵犀能看到。一期不做专门的两次结果对比计算。
- **Fiori 报表**：现在必须用户同意后结果才交给模型（`ANALYZED` 标记）。定时任务设置框里勾「跑完让灵犀分析」就算同意，运行程序对本次运行置 `ANALYZED`；报表登记 `ANALYZE_ENABLED` 为空的不显示这个选项。
- 分析失败（模型超时等）不影响结果本身，运行记录里写「结果已就绪，分析失败：原因」。

### 4.5 结果送达

- **专属会话**：创建定时任务时新建会话「定时：<名称>」（场景 = 报表执行 / Fiori 报表），任务也挂在这个会话上。每次运行写一条助手消息「【定时运行】11-05 08:00 ZDPSD021 成品可用库存报表：共 1,727 行」，结果卡插在消息下面（复用 10.31 的结果恢复链路）；有分析时，分析回答紧跟在后面。用户也可以在这个会话里继续追问。
- **未读**：定时任务表记「上次运行时间」和「上次查看时间」，前者更新就算未读。打开专属会话时前端通知后端更新「上次查看时间」。不改 `ZAI_CHAT_SESS`。
- **登录提示**：登录后前端调一次定时任务列表，有未读就弹一条提示，点击进「定时任务」页面。

## 5. 安全与权限

| 检查 | 时机 | 说明 |
|---|---|---|
| 总开关 `SCHED_ENABLED` | 保存 / 每次运行 | 关掉后保存被拒，已有作业到点也直接结束 |
| 场景是否开放 | 保存 / 每次运行 | 用户没开放「报表执行」或「Fiori 报表」场景（`ZCL_AI_ACCESS=>scene_ok`）就不能建对应的定时任务 |
| 报表授权 | 保存 / 每次运行 | `ZCL_AI_ACCESS=>report_ok`；`start_run` / `run` 内部本来也会检查 |
| 报表登记 | 每次运行 | 登记停用、关闭执行（`EXEC_ENABLED`）的，本次不跑，写失败原因 |
| 释放作业 | 保存 | 用户要有 `S_BTCH_JOB` 释放权限。能执行报表的用户本来就有；没有时如实提示 |
| 数量与频率 | 保存 | 每人最多 10 个（`SCHED_MAX_PER_USER`）；最短间隔 1 小时（`SCHED_MIN_HOURS`）；同一个定时任务上一次还没跑完，这一次跳过并记录 |
| 参数 | 保存 / 每次运行 | 参数快照在保存时按 `validate_params` 校验一次；每次运行先把相对日期换算成具体日期，再走一遍原来的校验 |
| 用户离职 / 被锁 | 每次运行 | 作业以他的身份运行会失败；SM37 可见，管理员页签显示「作业失败」 |

## 6. 相对日期

参数快照里，日期参数的值可以是具体日期，也可以是记号。记号只用于 `data_type = 'DATE'` 的参数；范围参数「从」「至」各自可以是记号，多值参数逐项替换。

| 记号 | 含义（以运行当天为准） |
|---|---|
| `@TODAY` | 今天 |
| `@TODAY-N` | N 天前（N 为 1–366），如 `@TODAY-1` = 昨天 |
| `@WEEK_START` | 本周一 |
| `@MONTH_START` / `@MONTH_END` | 本月第一天 / 最后一天 |
| `@LMONTH_START` / `@LMONTH_END` | 上月第一天 / 最后一天 |
| `@YEAR_START` | 今年 1 月 1 日 |

例：范围参数「过账日期」存 `@LMONTH_START,@LMONTH_END`，11 月 5 日运行时换算成 `20261001,20261031`。

- 换算放在定时任务类里（新方法 `resolve_params`），换算后的参数和原来手动提交的格式完全一样，`start_run` / `run` 不用改。
- 运行记录里同时存换算后的参数，事后能查到这次到底跑的哪天。
- 设置框里只显示中文选项，用户不用知道记号。

## 8. 接口（SEGW，项目 `ZAI_CHAT`）

全部返回 `GenericResult`，参数都是 `Edm.String`。

| 函数导入 | HTTP | 参数 | 说明 |
|---|---|---|---|
| `ScheduleSave` | POST | `ScheduleJson`、`ClientRequestId` | 新建或修改（JSON 里有 `schedId` 即修改）；超过 3000 字符走长文本通道 `ChatTexts` |
| `ScheduleList` | GET | `Scope`（空 = 自己的；`ALL` = 管理员看全部） | 列表，含未读、下次运行时间 |
| `ScheduleAction` | POST | `ScheduleId`、`Action`（PAUSE / RESUME / DELETE / RUNNOW / SEEN / ADMIN_STOP）、`Note` | `RUNNOW` 建一个立即运行的一次性作业；`SEEN` 更新上次查看时间 |
| `ScheduleRuns` | GET | `ScheduleId` | 最近的运行记录 |

前端按 `$metadata` 里有没有 `ScheduleSave` 决定显示不显示「设为定时」和「定时任务」入口。

## 12. 要在 SAP 上实测的

| # | 内容 | 不通时怎么办 |
|---|---|---|
| 1 | OData 请求里调 `JOB_CLOSE` 建**周期**作业（`PRDDAYS` / `PRDHOURS` + `SDLSTRTDT` / `SDLSTRTTM`），作业用户是当前用户、状态为「已释放」 | 参数名按印象写，SE37 看 `JOB_CLOSE` 接口回填 |
| 2 | 后台作业里调 Fiori 取数（RFC `DESTINATION 'NONE'` 调 `Z_AI_ODATA_GET`） | 页面里能取数，后台多半也行；不行就看 ST22 / SM21 |
| 3 | 后台作业里调模型（`cl_http_client` + SM59 / URL） | 一般没问题；不行看 SMICM 日志、代理设置 |
| 4 | 系统时区：作业时间按应用服务器时间，和用户所在时区是否一致 | 一致就不用处理；不一致在设置框写明「按服务器时间」 |
| 5 | 系统停机错过的运行：SAP 周期作业恢复后的行为 | 一期不补跑，运行记录里看得出缺了哪天 |
| 6 | 一个后台作业里再起报表执行的子作业并等待（占 2 个后台进程） | 后台进程紧张时可以改成运行程序里直接跑报表（要给 EXEC_SAP 加一个同步入口） |

## 13. 已定的事（2026-11-04 确认，按建议）

| # | 问题 | 结论 |
|---|---|---|
| D1 | 最小频率：允许「每 N 小时」，还是只到每天？ | **允许每 N 小时，N ≥ 1**（`SCHED_MIN_HOURS` = 1） |
| D2 | 一期带不带「跑完让灵犀分析」？ | **带，选填** |
| D3 | 每个定时任务保留多少条运行记录？ | **30 条**（`SCHED_KEEP_RUNS` = 30） |
| D4 | 系统停机错过的运行要不要补跑？ | **不补跑**，运行记录里能看出缺了哪次 |

## 14. 顺序

1. 先把《03》〇-Z 那批部署到 SAP 并验证（本功能依赖它，也避免一次上太多改动）。
2. 后端：两张表 → `ZCL_AI_SCHEDULE_SERVICE` + `ZAI_SCHED_RUNNER` → DPC / SEGW；本地静态测试。
3. 前端：设置框 → 定时任务页 → 结果卡按钮 → 侧栏未读；演示模式跑通。
4. 部署清单 `02-部署清单` + 《03》《04》各加一节。
5. SAP 上先按 §12 逐项实测（建议先用一个每小时运行的定时任务观察两三次），再开 `SCHED_ENABLED` 给用户用。
