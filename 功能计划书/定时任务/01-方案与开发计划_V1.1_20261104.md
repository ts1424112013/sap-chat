# 定时任务：方案与开发计划

版本：V1.1；编写日期：2026-11-04（Asia/Shanghai）。状态：**已开发（2026-11-04），未上 SAP**；部署见《02-部署清单》。D1–D5 见 §13。

> **V1.1 变更（2026-11-04）**：按用户给的参考界面（Claude 的「新建定时任务」）改成**以指令为主**：名称 + 一段指令 + 场景 + 模型 + 触发方式（可以加多个）+ 高级设置。
> 1. 定时任务的核心从「绑定一张报表」改成「一段指令」，到点由灵犀照指令执行；报表执行 / Fiori 报表作为「数据来源」，**参数在保存时确认一次**（§4.3）。
> 2. 场景按用户已开放的列：自动 / 报表执行 / Fiori 报表 / 数据分析 / 代码分析。数据分析原定放二期，指令式下不用额外开发，一期一起支持。
> 3. 触发方式可以加多个（最多 3 个，如每天 09:00 和 17:00），新表 `ZAI_SCHED_TRIG`。
> 4. 「跑完让灵犀分析」不再单独做开关：有指令就分析，只配数据来源、指令留空就只跑报表。
> 5. 新增事项 D5（无人值守时能不能让灵犀自己决定报表参数）：已定**不允许**。
> D1–D5 已确认（§13）。

## 1. 要解决的事

现场有些查询和报表每天、每周都要看，例如每天早上看成品可用库存的 Top10、每周一看未清采购。现在只能每次手动打开灵犀、填参数、提交、等结果、再问分析。希望像写一条消息一样写好指令、设好时间，之后自动运行，打开灵犀就能看到结果和分析。

## 2. 范围

| | 一期（本方案） | 二期 |
|---|---|---|
| 定时做什么 | 一段指令，按选定的场景由灵犀执行 | — |
| 场景 | 自动 / 报表执行 / Fiori 报表 / 数据分析 / 代码分析（只列用户已开放的） | — |
| 数据来源 | 可选绑定一张**报表执行**（含登记成报表的函数）或 **Fiori 报表**，参数保存时确认 | 一个定时任务绑定多张报表 |
| 结果怎么送达 | 系统里看：专属会话 + 未读标记 + 运行记录 | 邮件（要 SAP 配好 SCOT） |
| 怎么创建 | 「定时任务」页面新建；结果卡上「设为定时」（带上数据来源和参数） | 聊天里说"每天 8 点帮我…"（写操作，要先做确认卡） |
| 谁能建 | 所有开通的用户；管理员能看到并停用所有人的 | — |

## 3. 界面（参考截图）

### 3.1 新建定时任务（对话框）

从上到下：

1. **名称**：占位提示「每日简报」。
2. **指令框**：多行，占位提示「写下到点后要灵犀做什么，例如：看成品可用库存里库存最高的前 10 个料号，和上次比有什么变化」。框底部一条工具栏：
   - 左边**场景**下拉（默认「自动」），只列用户已开放的场景；
   - 右边**模型**下拉（默认「默认模型」），只列这个场景白名单里的模型（`AGENT_MODELS` / `AGENT_MODELS_<场景>`）。
3. **说明条**：「到点后灵犀会直接执行，不会停下来等你确认。报表参数在下面「数据来源」里确认一次，之后按它运行（相对日期按当天换算）；查表照常受你自己的表权限限制。」后面一个「查看说明」链接，展开讲 §5 的安全规则。
4. **触发方式**：一行一个触发。`[定时 ▾] [每天 ▾] [09:00]`，频率可选每天 / 每周（再勾星期几）/ 每月（几号，可选「最后一天」）/ 每 N 小时；行尾「+」再加一个触发，最多 3 个，多出来的行有删除按钮。
5. **高级设置**（默认收起）：
   - **数据来源**：只能从结果卡「设为定时」带进来（实现时定：参数就是那次成功运行的参数，不在这里重新填参数卡）。显示来源报表和参数：非日期参数只读，日期参数旁一个「固定 / 相对」下拉（§6）。从「定时任务」页面新建时数据来源为「无」，并提示先执行一次报表再设为定时。
   - **结果保留**：显示「保留最近 30 次运行记录」（D3，只读说明）。
6. 底部「取消」「创建」。创建后列表里出现这一行，并显示下次运行时间。

指令和数据来源至少填一个：只填指令 = 灵犀按指令在选定场景里做（例如数据分析场景里查表统计）；只填数据来源 = 到点只跑报表、不分析；两个都填 = 先跑报表，再让灵犀拿这份结果按指令分析。

### 3.2 定时任务页面

侧栏「定时任务」入口。列表列：名称、场景、触发（「每天 09:00、17:00」）、下次运行、上次结果（✓ / ✗ + 时间）、状态。每行操作：立即运行、暂停 / 恢复、编辑、删除；展开看最近 30 次运行记录（时间、状态、行数、耗时、失败原因；点击跳到专属会话里对应的位置）。管理员多一个「全部用户」页签，可以停用任何人的定时任务并写原因。

### 3.3 结果在哪

每个定时任务一个专属会话「定时：<名称>」，侧栏这一行有时钟图标；有新结果时显示未读点，登录时提示「有 N 个定时任务有新结果」。会话里每次运行依次是：一条「【定时运行】11-05 09:00」消息 → 数据来源的结果卡（如果有）→ 灵犀按指令的回答（如果有指令）。用户可以在这个会话里接着追问。

## 4. 运行机制

### 4.1 用谁的身份跑

每个触发以**创建人自己的身份**建一个 SAP 周期后台作业（用户在页面点创建，后端在这次 OData 请求里调 `JOB_OPEN` / `SUBMIT … VIA JOB` / `JOB_CLOSE`，作业用户就是他本人）。到点运行时看到的数据、受到的权限检查，和他手动操作完全一样。

不采用「一个调度作业用技术用户统一跑」：那样所有定时任务都以技术用户的权限运行，要么越权，要么得给技术用户 `S_BTCH_NAM` 去冒用他人身份。

### 4.2 作业怎么排

SAP 周期作业只支持「每 N 分钟 / 小时 / 天 / 周 / 月」，不支持「周一到周五」「每月最后一天」。做法：

- 每天 / 每周 / 每月的触发，一律建成**每天在设定时间点运行**的作业；每 N 小时的建成**每 N 小时**的作业。一个触发一个作业。
- 作业步骤是新程序 `ZAI_SCHED_RUNNER`（参数 = 定时任务号 + 触发号）。它先读定时任务：今天不是勾选的星期几、不是设定的日期，或者定时任务已暂停 / 被管理员停用，就直接结束。
- 作业名 `ZAI_SCHED_<定时任务号前 8 位>_<触发号>`，作业名和作业号存进触发表，修改 / 暂停 / 删除时用。
- **修改触发**：删掉这个触发的旧作业，按新设置重建。**暂停**：删掉所有作业，状态记为暂停；恢复时重建。**删除**：删作业 + 定时任务（运行记录和已有结果保留，按现有规则过期）。
- **管理员停用别人的**：只把状态改成「管理员停用」，运行程序看到后直接结束。不去删别人的作业（那需要 `S_BTCH_ADM`）。
- **同一个定时任务上一次还没跑完**（例如两个触发离得很近），这一次跳过并记录。

### 4.3 每次运行做什么

```
ZAI_SCHED_RUNNER（以创建人身份）
 ├─ 核对：总开关、状态、今天该不该跑、场景是否还开放、上一次是否还在跑
 ├─ 有数据来源：
 │    ├─ 参数快照里的相对日期换算成当天的具体日期（§6）
 │    ├─ 报表执行：start_run → 每 15 秒 get_run_status，直到 READY / FAILED 或超过 30 分钟
 │    └─ Fiori 报表：run（同步取数）
 │    → 得到本次结果号；失败就记录原因，有指令时也把失败告诉灵犀（让它如实说明）
 ├─ 有指令：analyze_agent（会话 = 专属会话，场景 = 设定的场景，模型 = 设定的模型，
 │          问题 = 指令，聚焦结果 = 本次结果号）
 └─ 写运行记录；更新「上次运行时间」（前端据此显示未读）
```

- **数据来源的参数在保存时确认，运行时不由模型决定**。现在灵犀在聊天里从不自己提交报表，参数一定经用户在参数卡上确认；定时任务沿用这条：保存时参数卡上点的就是确认，之后每次只做日期换算。
- **只有指令、没有数据来源时**，灵犀在选定场景里照常工作：数据分析场景可以查表、写只读 SQL、调用已登记的函数（都受当前用户的表权限和函数授权限制）；报表执行场景没有数据来源时只能分析会话里已有的结果，不会自己去执行报表（D5）。
- 两种来源的调用都用定时任务自己的任务号和专属会话号，每次运行用新的请求号，不会被幂等逻辑当成同一次。
- `analyze_agent` 不依赖页面，后台作业里可以调；调模型走 HTTP（`cl_http_client`），后台作业里也能发。大结果的分析会用上 11.4 的全量摘要和 `query_result`。
- **Fiori 报表**：现在必须用户同意后结果才交给模型（`ANALYZED` 标记）。保存定时任务时，数据来源是 Fiori 且填了指令，对话框写明「运行结果会交给灵犀分析」，点创建就算同意，运行程序对本次运行置 `ANALYZED`。报表登记 `ANALYZE_ENABLED` 为空的，只能跑、不能填指令。
- 灵犀那一步失败（模型超时等）不影响结果本身，运行记录写「结果已就绪，分析失败：原因」。

### 4.4 结果送达与未读

- 创建定时任务时新建专属会话（场景 = 设定的场景）和任务。每次运行写一条助手消息「【定时运行】<时间>」，结果卡挂在任务上，按 10.31 的结果恢复链路显示在消息下面；灵犀的回答由 `analyze_agent` 照常写进会话。
- 未读：定时任务表记「上次运行时间」和「上次查看时间」，前者新于后者就是未读。打开专属会话时前端调 `ScheduleAction(SEEN)` 更新查看时间。不改 `ZAI_CHAT_SESS`。
- 登录后前端调一次定时任务列表，有未读就弹一条提示。

## 5. 安全与权限

| 检查 | 时机 | 说明 |
|---|---|---|
| 总开关 `SCHED_ENABLED` | 保存 / 每次运行 | 关掉后保存被拒，已有作业到点直接结束 |
| 场景是否开放 | 保存 / 每次运行 | `ZCL_AI_ACCESS=>scene_ok`；没开放的场景不能选，开放被收回后运行时跳过并记录 |
| 模型白名单 | 保存 / 每次运行 | 沿用 `agent_model_allowed`（`AGENT_MODELS[_<场景>]`）；模型被移出白名单时运行失败并记录 |
| 报表授权与登记 | 保存 / 每次运行 | `ZCL_AI_ACCESS=>report_ok`；登记停用、关闭执行的本次不跑 |
| 报表参数 | 保存 / 每次运行 | 保存时按 `validate_params` 校验；运行时先换算相对日期，再走一遍原来的校验 |
| 灵犀能做什么 | 每次运行 | 和用户在该场景里手动提问完全一样：只读工具，受表权限 / 函数授权 / 报表授权限制；**不会提交报表、不会写任何业务数据** |
| 释放作业 | 保存 | 用户要有 `S_BTCH_JOB` 释放权限（能执行报表的用户本来就有）；没有时如实提示 |
| 数量与频率 | 保存 | 每人最多 10 个定时任务（`SCHED_MAX_PER_USER`），每个最多 3 个触发；每 N 小时的 N ≥ 1（`SCHED_MIN_HOURS`） |
| 指令长度 | 保存 | 最长 4000 字；超过 3000 字符走长文本通道 `ChatTexts` |
| 用户离职 / 被锁 | 每次运行 | 作业以他的身份运行会失败；SM37 可见，管理员页签显示「作业失败」 |

## 6. 相对日期

参数快照里，日期参数（`data_type = 'DATE'`）的值可以是具体日期，也可以是记号。范围参数「从」「至」各自可以是记号，多值参数逐项替换。

| 记号 | 含义（以运行当天为准） | 界面上的选项 |
|---|---|---|
| `@TODAY` | 今天 | 今天 |
| `@TODAY-N` | N 天前（N 为 1–366） | 昨天 / N 天前 |
| `@WEEK_START` | 本周一 | 本周一 |
| `@MONTH_START` / `@MONTH_END` | 本月第一天 / 最后一天 | 本月第一天 / 本月最后一天 |
| `@LMONTH_START` / `@LMONTH_END` | 上月第一天 / 最后一天 | 上月第一天 / 上月最后一天 |
| `@YEAR_START` | 今年 1 月 1 日 | 今年第一天 |

例：范围参数「过账日期」存 `@LMONTH_START,@LMONTH_END`，11 月 5 日运行时换算成 `20261001,20261031`。

- 换算放在定时任务类里（新方法 `resolve_params`），换算后的参数和手动提交的格式完全一样，`start_run` / `run` 不用改。
- 运行记录同时存换算后的参数，事后能查到这次跑的是哪天。
- 指令里的日期（如「看昨天的出货」）由灵犀按运行当天理解；系统提示里会带上当天日期。

## 8. 接口（SEGW，项目 `ZAI_CHAT`）

全部返回 `GenericResult`，参数都是 `Edm.String`。

| 函数导入 | HTTP | 参数 | 说明 |
|---|---|---|---|
| `ScheduleSave` | POST | `ScheduleJson`、`ClientRequestId` | 新建或修改（JSON 里有 `schedId` 即修改），含指令、场景、模型、触发数组、数据来源和参数；超过 3000 字符走 `ChatTexts` |
| `ScheduleList` | GET | `Scope`（空 = 自己的；`ALL` = 管理员看全部） | 列表，含触发、下次运行时间、未读 |
| `ScheduleAction` | POST | `ScheduleId`、`Action`（PAUSE / RESUME / DELETE / RUNNOW / SEEN / ADMIN_STOP）、`Note` | `RUNNOW` 建一个立即运行的一次性作业 |
| `ScheduleRuns` | GET | `ScheduleId` | 最近的运行记录 |

前端按 `$metadata` 里有没有 `ScheduleSave` 决定显示不显示「定时任务」入口和「设为定时」按钮。
