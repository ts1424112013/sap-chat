## 1. 要解决什么

现在「报表执行」场景的首页只有三个写死的示例按钮（`sceneREPORTChip1~3`：执行 ZDPMM702 / 分析一下这个结果 / 哪个工厂的 MIH 需求最大）。用户不知道系统里登记了哪些报表，只能记住 TCode 再打字。

目标：首页直接列出已登记的报表，用户点一下就开始执行流程，后面的参数卡、后台作业、结果展示全部沿用现有链路。

## 3. 方案

### 3.1 交互

| 项 | 规则 |
|---|---|
| 出现位置 | 「报表执行」场景的**空会话首页**，输入框下方，替换原来的三个示例按钮。会话发出第一条消息后，首页和目录一起消失（与场景选择条一致） |
| 选择方式 | **单选**。后台作业要排队，一次只跑一张 |
| 每行内容 | 报表名、TCode（等宽小标签）、说明（一行，超长省略）、参数个数、「后台作业」标签、「执行」按钮 |
| 未开放执行 | `exec_enabled` 为空的报表照样列出，整行变灰，标「暂未开放」，不能点；鼠标悬停提示"这张报表还没开放执行" |
| 点了之后 | 自动发出一条消息「执行 <TCode>」（等同用户自己打字），之后完全走现有链路：报表卡 + 参数卡 → 提交后台作业 → 轮询 → 结果 |
| 搜索 | 目录右上角搜索框，按报表名、TCode、说明模糊匹配（不分大小写），本地过滤 |
| 排序 | 按接口返回顺序（`list_defs` 按主键 `REPORT_ID` 排序）。以后需要时再给 `ZAI_RPT_DEF` 加排序列 |
| 底部说明 | "点一张报表会发出「执行 TCode」，确认参数后才提交后台作业" |
| 空清单 | 接口返回空：显示接口带回的说明（例如"报表读取能力未开启"），没有说明时显示"还没有登记报表" |
| 接口失败 | 显示"报表目录加载失败"和「重试」，不影响输入框正常使用 |
| 业务分类 | 一期不加（报表少，有搜索就够）。以后报表多了，给 `ZAI_RPT_DEF` 加"业务分类、关键词"两列，分类值与 Fiori 报表目录用同一套 |

### 3.2 数据映射

接口每条记录映射成目录的一行：

| 目录字段 | 来源 |
|---|---|
| `id` | `report_id` |
| `title` | `name` |
| `code` | `tcode` |
| `desc` | `description` |
| `paramCount` | `params.length` |
| `badges` | 固定 `["后台作业"]` |
| `disabled` / `disabledText` | `exec_enabled !== "X"` / "暂未开放" |
| 点击发送的文字 | `"执行 " + tcode` |

清单在**进入「报表执行」空会话首页时**取一次，缓存在控制器里；切换场景再回来不重复请求，点「重试」或刷新页面时重新取。

### 3.3 公共目录组件 `utils/ReportCatalog.js`（两个目录共用）

Fiori 报表目录也用这个组件，所以组件按"配置驱动"设计，本功能先实现单选部分，多选和分类由 Fiori 报表的 G1 补上。

**渲染方式**：生成 HTML 字符串，放进 `sap.ui.core.HTML`，用事件委托处理点击（与 `RunTracker` 的运行卡同一做法，列表长时比逐个建 UI5 控件轻）。所有动态文本先经 `Formatter.escapeHtml`。

**接口**

```js
ReportCatalog.create({
    mode: "single",            // "single" | "multi"（multi 由 Fiori G1 实现）
    items: [{ id, title, code, desc, category, paramCount, badges: [], disabled, disabledText }],
    categories: null,          // null = 不显示分类页签；Fiori 传 ["销量分析", ...]
    texts: { title, searchPh, footNote, empty, loadFail, retry },
    onPick: function (oItem) {},        // 单选：点行或「执行」
    onConfirm: function (aItems) {},    // 多选：点底部主按钮（Fiori）
    onRetry: function () {}
}) // 返回 sap.ui.core.HTML 控件
```

纯函数单独导出，方便 Node 测试：`filterItems(items, query, category)`、`rowHtml(item, opts)`。

**键盘**：↑↓ 移动焦点行，Enter 等于点击，`/` 聚焦搜索框（与 AskCard 的键盘习惯一致）。

**样式**：沿用设计稿的类名（`catalog`、`catHead`、`catList`、`catRow`、`catFoot` 等），写进 `style-gale.css` 末尾，颜色全部用现有变量（`--accent`、`--line`、`--sub` 等），深色模式自动适配。

### 3.4 不做的事

- 不改后端、不改 SEGW、不改现有报表链路（REPORT_SERVICE / EXEC_SAP / MOCK 一行不动）。
- 不做多选、不加业务分类（理由见 3.1）。
- 不在已有消息的会话里显示目录（二期可以在输入框旁加一个「报表目录」按钮）。

## 6. 验收清单

**演示模式（本地，`npm start`）与本地测试**

0. `cd test-server && npm run test:fiori` 全过（2026-10-20：82 项，含目录部分）。
1. 进「报表执行」空会话 → 输入框下方出现目录，三条报表，其中一条灰色「暂未开放」。
2. 搜索"702"或"MIH" → 只剩 ZDPMM702；搜不到时显示"没有匹配的报表"。
3. 点灰色报表 → 没有反应，悬停有提示。
4. 切到「数据分析」再切回 → 目录不重复请求（Network 里只有一次）。
5. 深色模式下目录颜色正常。

**SAP（随新功能一起部署后）**

6. 目录列出 `ZAI_RPT_DEF` 里 `ACTIVE='X'` 的报表，数量、名称、TCode 与 SE16 一致。
7. 点 ZDPMM702 → 对话里出现用户消息「执行 ZDPMM702」，随后出现与手工输入完全相同的参数卡；提交后运行卡、结果展示与现有流程一致。
8. 把某报表 `EXEC_ENABLED` 清空 → 刷新后该行变灰、不能点。
9. SM30 关掉 `REPORT_READ_ENABLED` → 目录显示后端带回的说明，输入框照常可用；恢复开关后重新打开。
10. 发出第一条消息后目录消失；新建会话后再次出现。

## 7. 依赖与注意

- **与 bug 修复的关系**：本功能只用 GET（`ReportDefinitions`），不受改进清单 FE-01（CSRF 重试拼两遍查询串）影响；但测试依赖 PROC-03 先建前端 Node 测试。
- **部署**：纯前端，随三项新功能的前端 dist 一起发布；与 Fiori 报表的场景调整（新增「Fiori 报表」、隐藏「库存查询」）同一版前端上线。
- **踩坑清单 §3.A**：ES5 语法、动态文本 escapeHtml、构建后 grep `dist/Component-preload.js` 里 `ReportCatalog` 特征名。
