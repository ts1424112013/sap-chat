# 事务码权限自助申请 —— 方案与开发计划

版本：V1.0
编写日期：2026-10-15（Asia/Shanghai）
状态：方案初稿，待小风审阅；开发未开始。§7 的 4 个问题确认后再动手。

## 1. 要解决什么

现在每天有几封邮件要 IT 给账号加事务码权限（如 ZDPMM051、ZDPMM052）。IT 的做法是：打开邮件 → 进 SAP → SE16N 往自建权限表里加一行。所有申请目前都会通过。

目标：用户在 Gale-SAP 里自己提交申请，系统校验后直接写权限表；IT 不再开邮件、不再进 SE16N。少数高风险情况（如申请"全部工厂"）留给 IT 在系统里一键批准。

## 2. 已确认的现状

| 项 | 现状 | 来源 |
|---|---|---|
| 权限存放 | 自建表 `ZIDPPP009`，一行 = 事务码 + SAP 账号 + 工厂；工厂填 `ALL` 表示全部工厂 | `ZRMM_IDP_0702` FORM delete：`SELECT SINGLE werks FROM zidppp009 WHERE tcode = 'ZDPMM702' AND fir_account = sy-uname AND werks IN ( werks1_i, 'ALL' )` |
| 已知字段 | `TCODE`、`FIR_ACCOUNT`（= SU01 用户名，即 `sy-uname`）、`WERKS` | 同上；其余字段与主键**待确认**（§7 Q2） |
| 维护方式 | IT 在生产机 SE16N 直接加，不走传输 | 小风 10-15 |
| 审批 | 所有事务码的申请目前都会通过 | 小风 10-15 |
| 一期范围 | ZDPMM051、ZDPMM052 | 小风 10-15 |
| GRC / CUA | 没有 | 小风 10-15 |
| 后端身份 | OData 以登录用户本人的 SAP 账号运行（`sy-uname` 即申请人）；Gale-SAP 登录另需 `ZAI_CHAT_USER` 开通 | `ZCL_AI_CHAT_SERVICE` `v8_login` / `v8_get_role` |

## 3. 方案

### 3.1 流程

1. **申请**：用户选事务码（只列可申请清单）、填工厂（可多个）、写原因，提交。
2. **系统判断**（后端，按顺序）：
   - 事务码不在可申请清单或已停用 → 拒绝，提示联系 IT。
   - 工厂不存在（对照 `T001W`）→ 拒绝。
   - 已有权限（表里已有 本工厂 或 `ALL` 的行）→ 直接告诉用户"已有"。
   - 申请 `ALL` 且该事务码不允许自助 `ALL` → 进入"待审批"。
   - 其余 → **自动通过**，立即写表。
3. **IT 审批**（只针对待审批）：设置 → 权限申请，批准即写表，驳回需填原因。
4. **留痕**：每次申请、通过、驳回、撤销都记一条，谁、何时、为什么。

### 3.2 两个入口

| 入口 | 谁用 | 做什么 |
|---|---|---|
| 申请权限（用户） | 已开通 Gale-SAP 的用户 | 只能给**自己**申请（目标账号 = `sy-uname`，后端取，不信任前端传值） |
| 权限申请管理（IT） | `ZAI_CHAT_USER.ROLE = ADMIN` | 记录查询、审批/驳回、撤销；**批量代加**（粘贴账号列表 + 事务码 + 工厂）——过渡期邮件里的申请也在这里一次处理完 |

二期可加 Agent 入口：用户说"我要 ZDPMM051 的 1000 工厂权限"或贴无权限报错，Agent 识别后弹出同一张确认卡（复用 AskCard），后端调用同一个服务。

### 3.3 为什么直接写表是可以的，以及要守住什么

直接用 Open SQL 写 `ZIDPPP009` 不经过 SAP 权限检查——和现在 SE16N 加的效果一样，但**控制全部落在程序里**。必须守住：

1. **可申请清单是唯一入口**：只有清单里的事务码能写。`ZIDPPP009` 还被其他程序用作权限判断（例如 0702 用 `TCODE='ZDPMM702'` 控制删除），清单外的事务码一律不能经本功能写入。
2. **只能给自己申请**：申请人与目标账号都取 `sy-uname`；代他人只能由 ADMIN 的批量代加完成。
3. **`ALL` 默认要审批**：`ALL` 等于所有工厂，按事务码配置是否允许自助。
4. **只有一个方法写表**：`grant_row` / `revoke_row` 是唯一读写 `ZIDPPP009` 的地方，便于审查。
5. **全量留痕**：比现在 SE16N（无记录）更可审计。另建议对 `ZIDPPP009` 开 SE13 数据变更日志，把手工 SE16N 的修改也记下来（可选，需 Basis 确认参数 `rec/client`）。

## 4. 对象清单

### 4.1 SE11 新建两张表（交付类 A，均含 `MANDT`）

**ZAI_AUTH_CAT —— 可申请清单**

| 字段 | 类型 | 键 | 说明 |
|---|---|---|---|
| TCODE | CHAR 20 | X | 事务码 |
| DESCR | CHAR 60 | | 显示说明（如"MIH 需求报表"） |
| AUTO_APPROVE | CHAR 1 | | `X` = 单工厂申请自动通过；空 = 一律待审批 |
| ALLOW_ALL | CHAR 1 | | `X` = 允许自助申请 `ALL` |
| ACTIVE | CHAR 1 | | `X` = 可申请 |

一期数据：ZDPMM051、ZDPMM052，`AUTO_APPROVE='X'`，`ALLOW_ALL=''`，`ACTIVE='X'`。

**ZAI_AUTH_REQ —— 申请与日志**

| 字段 | 类型 | 键 | 说明 |
|---|---|---|---|
| REQ_ID | CHAR 32 | X | GUID |
| REQUESTER | CHAR 12 | | 申请人（`sy-uname`） |
| TARGET_USER | CHAR 12 | | 目标账号（自助 = 申请人；批量代加 = 列表中的账号） |
| TCODE | CHAR 20 | | |
| WERKS | CHAR 4 | | 工厂或 `ALL` |
| REASON | CHAR 255 | | 申请原因 |
| CHANNEL | CHAR 10 | | `SELF` / `ADMIN` |
| STATUS | CHAR 10 | | `PENDING` / `DONE` / `EXISTS` / `REJECTED` / `FAILED` / `REVOKED` |
| DECIDED_BY | CHAR 12 | | 审批 / 撤销人（自动通过记 `AUTO`） |
| MESSAGE | CHAR 255 | | 驳回原因 / 失败原因 |
| CREATED_AT | DEC 15 (TIMESTAMP) | | |
| DECIDED_AT | DEC 15 (TIMESTAMP) | | |

### 4.2 SE24 新类 `ZCL_AI_AUTH_SERVICE`

| 方法 | 可见性 | 说明 |
|---|---|---|
| `get_catalog` | PUBLIC | 可申请清单（`ACTIVE='X'`） |
| `submit` | PUBLIC | 自助申请：按 §3.1 判断，自动通过时调 `grant_row` |
| `admin_batch_add` | PUBLIC | ADMIN 批量代加：逐账号校验（`USR02` 存在且未锁）后写表 |
| `decide` | PUBLIC | ADMIN 批准 / 驳回待审批 |
| `revoke` | PUBLIC | ADMIN 撤销某条已通过的申请（删对应行） |
| `list_requests` | PUBLIC | 用户看自己的；ADMIN 看全部（筛选状态 / 事务码 / 账号，分页） |
| `grant_row` / `revoke_row` | PRIVATE | 唯一写 `ZIDPPP009` 的地方；`INSERT` 遇重复（subrc=4）按"已有"处理 |

ADMIN 校验复用 `ZCL_AI_CHAT_SERVICE=>v8_require_admin` 的口径（`ZAI_CHAT_USER.ROLE='ADMIN'`）。

### 4.3 SEGW / DPC_EXT

新增 Function Import：`AuthCatalog`（GET）、`AuthSubmit`、`AuthBatchAdd`、`AuthDecide`、`AuthRevoke`（POST）、`AuthList`（GET）；`ZCL_ZAI_CHAT_DPC_EXT` 的 execute_action 加对应 WHEN 分支。

POST 参数位置沿用已在 SAP 上验证可用的 `StartReportRun` 通道（参数放 URL）。改进清单 T-07（`_v8Call` form 正文的写操作是否生效）尚未实测，不在新功能上冒险。

### 4.4 前端

- 侧栏用户菜单加"申请权限"：对话框（事务码下拉 + 工厂多值输入 + 原因）+ "我的申请"列表。
- 设置里加"权限申请"页（仅 ADMIN）：记录表格、待审批批准/驳回、撤销、批量代加。
- 文案全部走 i18n（改进清单红线 9）。

## 6. 验收清单

1. 自助申请 ZDPMM051 / 1000 → 立即 `DONE`；SE16N 看 `ZIDPPP009` 新增一行；用户能进 ZDPMM051。
2. 再申请同一组合 → `EXISTS`，表里不重复。已有 `ALL` 时申请单工厂 → `EXISTS`。
3. 申请 ZDPMM051 / `ALL` → `PENDING`；IT 批准后 `DONE` 并写表；驳回后 `REJECTED` 且不写表。
4. 申请清单外事务码（如 ZDPMM702）→ 被拒绝，表里无变化。
5. 前端篡改目标账号为他人 → 后端仍按 `sy-uname` 处理。
6. 非 ADMIN 调用批量代加 / 审批 / 撤销 → 被拒绝。
7. 批量代加含不存在或已锁账号 → 逐条报告，其余正常写入。
8. 撤销 → 对应行删除，记录 `REVOKED`。
9. 每个操作在 `ZAI_AUTH_REQ` 都有记录。
