版本：V1.1；编写日期：2026-11-02（Asia/Shanghai）。**代码已写完，还没上 SAP**，部署见《04-数据分析调用函数部署清单》。前置：《01-方案与开发计划》V1.1 的 RFC 函数执行（f14e6be）。

## 1. 要解决的事

在 Agent「数据分析」场景里，模型分析时能直接调用**已登记的函数**，拿到结果后接着分析。用法和它现在用 `run_sql` 查表一样。

不做（本期）：

- 调用没登记的函数。模型只能从登记清单里挑，函数名不来自模型的自由发挥。
- 写入类函数。登记时已经拦截（《01》§3.4），调用后照样 `ROLLBACK WORK`。
- 结构类型的输入参数。和登记一样，一期只支持单值、复选框和范围表。
- 很耗时的函数。同步调用在网关请求里跑，这类函数请走「报表执行」的后台作业（§9）。

## 2. 用起来的样子

> 用户（数据分析）：1000 工厂上个月哪些供应商的未清采购单最多？

1. 模型从工具说明里看到已登记函数 `Z_AI_DEMO_PO_OPEN`（未清采购订单：工厂*、供应商、凭证日期、只看未清）。
2. 模型调用 `call_function`，传入工厂 1000，凭证日期为上月第一天到最后一天。
3. 后端同步调用函数，结果表进入数据集：前端照常显示表格、图表、CSV，模型读到前 200 行。
4. 需要时，模型可以再用 `describe_table` / `run_sql` 补查（例如供应商名称），然后作答。

步骤条显示「调用函数：未清采购订单（Z_AI_DEMO_PO_OPEN），共 N 行」。

## 3. 总体做法

```
模型输出 call_function(function = 调用名, params = {...})
 → ZCL_AI_AGENT_GUARD：工具在白名单、参数对象取出来（同 sap_data_analysis 的做法）
 → ZCL_AI_AGENT_SERVICE：次数上限 → 查登记（FUNC + 活动 + 开放执行 + 报表授权）
   → ZCL_AI_REPORT_SERVICE=>validate_params（和参数卡同一套校验，缺必填直接告诉模型缺什么）
   → CALL FUNCTION 'Z_AI_RFC_RUN' DESTINATION 'NONE'（新会话）
       └ ZCL_AI_RFC_EXEC=>run_direct：S_RFC → 绑定 → COMMIT → 调用 → ROLLBACK → 结果转数据集
   → 数据集进 lt_datasets（前端表格 / 图表 / CSV），前 200 行回填给模型
```

报表执行那条路（后台作业 + 轮询）不变。两条路共用登记、参数校验、绑定和写入兜底，只是入口不同。

## 4. 哪些函数可以在数据分析里用

- 条件：`ZAI_RPT_DEF` 里 `REPORT_KIND = FUNC`、`ACTIVE = X`、`EXEC_ENABLED = X`，且当前用户有报表授权（`ZCL_AI_ACCESS=>report_ok`，`RPT_ACL_ENABLED` 不开时就是全部）。（E1）
- 总开关：`ZAI_CHAT_CFG` 键 `RFC_IN_DATA`。不维护 = 开，填 `N` = 数据分析里不带这个工具。
- 场景：跟着「数据分析」走。「自动」里本来就按数据分析是否开放来决定带不带数据工具（用户权限方案 §2.1），`call_function` 也一样。
- 没有可用函数时不注入这个工具，模型也看不到它。

## 5. 同步通道 `Z_AI_RFC_RUN`（新函数模块）

为什么不在网关会话里直接调：函数 dump 会把这次 Agent 请求整个打断（HTTP 500），之前查到的结果也一起丢掉。用 `DESTINATION 'NONE'` 在新会话里跑，dump 只会变成 `SYSTEM_FAILURE`，Agent 能接住，告诉模型调用失败。做法和 Fiori 取数的 `Z_AI_ODATA_GET` 一样。

| 项 | 内容 |
|---|---|
| 函数组 | `ZAI_ODATA`（和 `Z_AI_ODATA_GET` 放一起，S_RFC 授权可以共用）；也可以新建 `ZAI_RFC` |
| 处理类型 | 远程启用模块（必选，否则 `DESTINATION 'NONE'` 调不了） |
| 导入（全部值传递） | `IV_REPORT_ID` TYPE STRING；`IV_PARAMS_JSON` TYPE STRING（已校验的规范化快照）；`IV_MAX_ROWS` TYPE I |
| 导出（全部值传递） | `EV_RESULT` TYPE STRING（数据集 JSON，§6.2）；`EV_ERROR` TYPE STRING |
| 内容 | 只有一行：`zcl_ai_rfc_exec=>run_direct( … )` |

调用方（AGENT）要注意：

- `EXCEPTIONS system_failure = 1 MESSAGE lv_msg communication_failure = 2 MESSAGE lv_msg OTHERS = 3`，然后 `RFC_CONNECTION_CLOSE`，和 `ZCL_AI_ODATA_CLIENT` 同一套写法。
- 同步 RFC 会让调用方隐式提交一次数据库。Agent 在这一步前面没有未提交的写操作（审计和进度表各自提交），和 Fiori 取数的情况一样。
- 新会话的 `sy-uname` 是同一个用户，函数自己的权限检查照常生效。

## 6. `ZCL_AI_RFC_EXEC` V1.1

### 6.1 新入口 `run_direct`

- 入参：报表编号、规范化参数快照、最大行数。不依赖运行记录（`ZAI_RPT_RUN`）。
- 步骤和 `run` 一样：复核登记（FUNC + 活动 + 开放执行）→ 报表授权 → S_RFC → 绑定 → `COMMIT WORK` → 调用 → `ROLLBACK WORK` → 主结果 → RETURN 消息。
- `build_bindings` 拆成两层：外层按运行号取登记参数（原 `run` 用），内层吃「登记参数行 + 参数快照」（`run_direct` 用）。`run` 的行为不变。

### 6.2 结果转成数据分析的数据集

数据分析的数据集是「列（名称、标题、是否数值）+ 每行一组字符串单元格」（`ZCL_AI_DATA_ANALYSIS_SERVICE=>ty_dataset`）。`run_direct` 在新会话里直接转好：

- 列：主结果行结构的平层字段，标题取字典文字（同 `table_to_rows`）；数值类型（I / P / F / INT8 / DECFLOAT）标 `numeric`。
- 单元格：日期写成 `YYYY-MM-DD`，时间写成 `HH:MM:SS`，数字不带千分位、负号在前，字符去掉首尾空格，带转换例程的字段走 `_OUTPUT`（料号去前导零，和 SAP 界面一样）。
- 序列化成 JSON：`{"name","columns":[{name,label,numeric}],"rows":[["…","…"],…],"total_rows","truncated","note"}`，经 `EV_RESULT` 带回。AGENT 用 `/ui2/cl_json=>deserialize` 还原成 `ty_dataset`（嵌套数组反序列化要在第 1 批先实测，不行就改成手工拆）。
- 行数上限：`IV_MAX_ROWS` 默认 2000（前端数据集），回填给模型的仍是前 200 行（`zcl_ai_sql_executor=>gc_llm_rows`）。超出的写 `truncated` 和 `note`。

RFC_EXEC 不引用 DATA_ANALYSIS_SERVICE 的类型，只输出 JSON，免得两个类互相依赖。

## 7. 工具 `call_function`

### 7.1 注册（`ZCL_AI_TOOL_REGISTRY`）

- DATA 模块白名单加 `call_function`，并满足 §4 的条件：开关开着，且当前用户至少有一个可用函数。
- 工具说明里列出可用函数（最多 30 个，按调用名排序），每个一行：

  `ZF_PO_ITEMS 未清采购订单项目：IV_WERKS 工厂*(CHAR4)、IT_LIFNR 供应商(多值)、IT_BEDAT 凭证日期(日期范围 low,high)、IV_OPEN 只看未清(X/空)`

  超过 30 个时只列前 30 个，并写明「还有 N 个，用调用名直接调用也可以」。参数说明来自 `get_params`，和参数卡一致。
- args：`{"function":"<调用名>","purpose":"<一句话，作为结果标题>","params":{"<参数编号>":"<值>",…}}`。多值用逗号分隔，范围写 `low,high`，复选框写 `X` 或空。

### 7.2 守卫（`ZCL_AI_AGENT_GUARD`）

- `function` / `purpose` 是普通 TEXT 参数，走现有的强类型校验。
- `params` 是嵌套对象：照 `sap_data_analysis` 的做法，用 `extract_args_object` 先把 args 原文取出来，再取 `params` 子对象，交给 `ZCL_AI_REPORT_SERVICE=>parse_flat_kv`（只认扁平键值，嵌套的直接拒绝）。
- 守卫只管格式；参数值由 `validate_params` 按登记校验（§3）。

### 7.3 执行（`ZCL_AI_AGENT_SERVICE`）

- 次数上限：每次提问最多调用 `RFC_MAX_EXEC` 次（默认 3，最多 10，失败也算）。到上限后回「已达函数调用次数上限，请基于已有结果回答」。（E2）
- 调用名查不到 / 不是函数 / 停用 / 没授权：回给模型一句可读的原因，不调用。
- `validate_params` 报缺必填或格式错：把具体哪一项、为什么回给模型，让它改了再调。不算一次真实调用，但计入次数上限，防止反复空转。
- 成功：数据集进 `lt_datasets`，名称 = `purpose`（空就用函数名称），来源 = `FUNC:<调用名>`；回填副本只留前 200 行，开头写「共 N 行 / 回填前 M 行」，和 `run_sql` 一样。
- 步骤条：`调用函数：<名称>（<调用名>），共 N 行`；失败 `status = ERROR` 并带原因。审计 `ZAI_AGENT_STEP` 的 TOOL_ID = `call_function`。

### 7.4 领域卡（`ZCL_AI_DOMAIN_CARDS` DATA 域）

加一条：「工具说明里有现成函数能直接回答的，优先调函数，不要用 SQL 重新拼它的逻辑；函数结果不够时再用 run_sql 补查。函数参数按说明里的编号和格式填，必填项（带 *）缺了先问用户。」

## 8. 失败怎么显示（给模型 / 步骤条）

| 情况 | 回给模型 |
|---|---|
| 开关关了 / 没有可用函数 | 工具不出现，不会被调用 |
| 调用名不在可用清单 | 「函数 X 未登记或你没有使用权限，可用的函数见工具说明」 |
| 参数缺必填 / 格式错 | 「参数 IV_WERKS（工厂）必填」「IT_BEDAT 日期要 YYYYMMDD」 |
| 函数例外 / `MESSAGE TYPE 'E'` | 「函数返回例外 NOT_FOUND：<消息>」 |
| RETURN 里有 E / A，且没有数据 | 「函数返回错误消息：<第一条>」 |
| 函数 dump（`SYSTEM_FAILURE`） | 「函数调用中断：<短文本>，请换条件或改用报表执行」 |
| 没有 S_RFC | 「没有函数 X 的调用权限（S_RFC）」 |
| 0 行 | 正常结果，0 行是有效事实 |

## 9. 和报表执行怎么选

| | 数据分析 `call_function` | 报表执行（后台作业） |
|---|---|---|
| 谁填参数 | 模型按对话填，缺了会问 | 用户在参数卡里填 |
| 结果之后 | 模型马上接着分析，还能再查表 | 结果卡；可以「交给模型分析」 / 组合分析 |
| 适合 | 秒级出数的查询函数 | 跑得久、数据量大的函数 |
| 超时 | 受网关请求时长限制 | 不受限制，作业慢慢跑 |

同步调用没法中途掐断，跑得久的函数会把这次提问拖到网关超时。所以登记的函数如果平时要跑几十秒，建议只用报表执行。可选做法：用 `ZAI_RPT_DEF.EXEC_MODE` 标记，标成 `JOB` 的函数不进数据分析清单（E3）。

## 10. 安全底线

1. 函数名只来自登记表；模型给的调用名只是候选，用之前核对登记、开关和授权。
2. 参数先过 `validate_params`（和参数卡同一套规则），再经绑定按字典转换；不拼任何代码或 SQL。
3. S_RFC、报表授权、函数自身的权限检查照常；调用后一律 `ROLLBACK WORK`。
4. 函数在新会话里跑，出错不打断 Agent 请求。
5. 次数上限防空转；结果回填给模型有行数和字数上限。

## 13. 需要你定的事

| # | 问题 | 建议 |
|---|---|---|
| E1 | 哪些函数能在数据分析里用 | **已定**：所有已登记、开放执行、用户有授权的函数，不再单独勾选；`RFC_IN_DATA = N` 整体关掉 |

| E3 | 跑得久的函数要不要排除 | **已定：要**。函数登记的 `EXEC_MODE` 默认 `SYNC`（SCANNER V1.1a）；跑得久的函数在 SE16 改成 `JOB`，只走报表执行 |

> E3 注意：现在扫描登记写入的 `EXEC_MODE` 恒为 `JOB`。按 E3 做的话，第 2 批要改 SCANNER（函数登记默认写 `SYNC`）；已经登记过的函数在 SE16 改一下 `EXEC_MODE`。报表执行不看这一列，两种值都能跑。

**进度（V1.1）**：三批代码都已写完（第 3 批是现场验证）。本地已验证：ABAP 静态 238 项（新增数据分析调用 13 项）、`test:rfcscan` 30 项（含本地 mock 的 `call_function` 6 项）、其余套件全部通过。**未验证**：ABAP 没在 SAP 上激活；`/ui2/cl_json` 还原嵌套数组、新会话 dump、真实模型会不会优先用函数，要按《04》§4 现场验证。

## 14. 风险

| 风险 | 处置 |
|---|---|
| 同步调用超时（函数慢） | §9 / E3：慢函数只走报表执行；工具说明里写「秒级查询函数」 |
| 模型填错参数格式 | `validate_params` 回具体原因，模型改了再调；次数上限兜底 |
| `/ui2/cl_json` 反序列化嵌套数组 | 第 1 批先实测，不行就改成手工拆 |
| 函数清单太长占上下文 | 最多列 30 个；参数说明压成一行 |
| 新会话隐式提交 | 调用前 Agent 没有未提交写操作；和 Fiori 取数同样处理 |
