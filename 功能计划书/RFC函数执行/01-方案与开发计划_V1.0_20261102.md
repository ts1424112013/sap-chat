# RFC 函数执行：方案与开发计划

版本：V1.0；编写日期：2026-11-02（Asia/Shanghai）。方案阶段，**还没写代码**。§10 的几件事定下来后再开工。

## 1. 要解决的事

| # | 需求 | 做法 |
|---|---|---|
| 1 | 在灵犀里选一个登记过的函数模块（Z 函数、RFC、只读 BAPI），填参数、执行，结果出表格，再交给模型分析 / 组合分析 | 函数当作一种「报表」登记，复用报表执行整条链路（§2） |
| 2 | Agent 代码分析能直接按函数名读源码和接口 | `ZCL_AI_CODE_PROVIDER` 认函数模块名（§5） |

不做（本期）：

- 写入类函数（创建 / 修改 / 过账 / 删除）。登记时拦截，执行时再兜底撤回（§3.4、§4.2）。
- 调用其他系统（SM59 远程目的地）。只在本系统调用。
- 结构参数、嵌套参数。一期只支持单值和范围表输入（§3.2）。
- 同步执行。一期只走后台作业（§4.4）。

## 2. 总体做法：函数作为一种「报表」登记

| 环节 | 报表（现有） | 函数（新） |
|---|---|---|
| 登记 | `ZAI_RPT_REG` 扫选择屏 | 同一个程序新增「函数」模式，读函数接口 |
| 登记表 | `ZAI_RPT_DEF`，`REPORT_KIND = ALV` | 同一张表，`REPORT_KIND = FUNC`，`PROGNAME` = 函数名，`TCODE` = 调用名，`RESULT_REF` = 主结果参数名 |
| 参数 | `ZAI_RPT_PARAM` | 同一张表，结构不变 |
| 目录 / 参数卡 / 报表授权 | 现有 | 不改；目录行换成「函数」标记 |
| 执行 | `SUBMIT ZAI_RPT_RUNNER VIA JOB` → ALV 采集 | 同一个作业；运行器按 `REPORT_KIND` 分支 → `ZCL_AI_RFC_EXEC` 调函数 |
| 结果 | `ZAI_RPT_RESULT`（第 0 行元数据 + 数据行） | 同一格式 |
| 展示 / 图表 / 组合分析 / 交给模型分析 / 重开恢复 | 现有 | 不改 |

这样做的好处：

- 不加表、不加列、不改 SEGW。
- 报表授权（`ZAI_RPT_ACL`，SRC_TYPE = REPORT）直接生效。
- Agent 里说「执行 ZXXX」、目录点选、参数卡提交，都不用改。

## 3. 登记

### 3.1 调用名（存在 `TCODE` 列）

- 函数名不超过 20 位且以 Z 开头：直接用函数名，例如 `Z_AI_ODATA_GET`。
- 否则由管理员起别名，要求 Z 开头、不超过 20 位，例如 `BAPI_PO_GETITEMS` → `ZF_PO_ITEMS`。
- 原因有两个：`TCODE` 是 CHAR 20 且唯一；Agent 从问题里认调用名的规则是「Z 开头、4–20 位」（`ZCL_AI_INTENT_ROUTER=>extract_tcode_token`）。Y 开头认不出来，所以别名不能用 Y 开头。

### 3.2 接口 → 参数草稿

接口来自 `FUPARAREF`（`R3STATE = 'A'`），参数说明来自 `FUNCT` 短文本。两张表的列名按印象写，**待 SE11 实测确认**。

| 函数接口 | 登记成 | 说明 |
|---|---|---|
| IMPORTING 单值（字符 / 数字 / 日期） | `SEL_KIND = P` | 类型、长度按字典；`OPTIONAL` → 选填；`DEFAULTVAL` 字面量 → STATIC 默认，`SY-DATUM` → TODAY |
| IMPORTING 单字符标记（ABAP_BOOL / XFELD / FLAG） | `SEL_KIND = C` 复选框 | |
| TABLES 或 IMPORTING 的范围表（行结构是 SIGN / OPTION / LOW / HIGH） | `SEL_KIND = S` 多值 / 范围 | 和选择屏 SELECT-OPTIONS 同一套写法 |
| IMPORTING 扁平结构 | 一期不登记，写明原因 | 二期按「参数-字段」展开 |
| 通用类型（没写类型 / TYPE ANY / TYPE TABLE） | 必填的：整个函数不能登记；选填的：跳过 | 运行时无法建出数据对象 |
| EXPORTING / CHANGING / 非范围的 TABLES | 不进参数卡 | 主结果候选（§3.3） |
| EXCEPTIONS | 记录 | 执行时映射成失败原因（§4.3） |

参数标签取值顺序：参数说明（FUNCT）→ 字典字段文本 → 参数名。

### 3.3 主结果（存在 `RESULT_REF` 列）

- 默认取第一个「行类型是结构」的 TABLES 或 EXPORTING 内表，名字是 `RETURN` 的跳过。
- 管理员可以在登记程序里改选（`P_RESULT`）。
- 函数没有表输出时，把 EXPORTING 的单值和扁平结构字段合成一行作为结果。

### 3.4 写入类拦截（登记时）

| 检查 | 命中条件 | 处置 |
|---|---|---|
| 函数名 | 含 CREATE / CHANGE / DELETE / POST / SAVE / UPDATE / CANCEL / RELEASE / SEND | 判危险；管理员勾 `P_FORCE` 并在弹窗确认后才能写入（名字误判常见，例如 `Z_GET_LAST_UPDATE`） |
| 源码：提交 | `COMMIT WORK`、`BAPI_TRANSACTION_COMMIT` | 不能登记（D3） |
| 源码：异步写入 | `IN UPDATE TASK`、`IN BACKGROUND TASK`、`STARTING NEW TASK` | 不能登记（D3） |
| 源码：写库 | 对透明表（`DD02L-TABCLASS = TRANSP`）的 `INSERT / UPDATE / MODIFY / DELETE` | 不能登记（D3）；内表操作不算 |
| 源码：跳出 | `SUBMIT`、`CALL TRANSACTION`、`CALL SCREEN`、`POPUP_*` | 警告，可以登记；后台作业里弹窗会中止 |

- 只扫函数本体，扫不到它再调用的函数。所以「管理员登记」本身就是责任确认，执行时还有 §4.2 第 6 步兜底。
- 只有 `ZAI_CHAT_USER` 角色 ADMIN 能写入，和报表登记一样。
- 登记结果里显示函数是不是「远程启用」（`TFDIR-FMODE = 'R'`），只是提示，不作限制（D5）。

## 4. 执行

### 4.1 流程

```
前端 StartReportRun（不变）
 → ZCL_AI_REPORT_SERVICE=>start_run：登记 / 授权 / 参数校验（不变）
 → ZCL_AI_REPORT_EXEC_SAP=>submit：FUNC 不做选择屏预检，改做参数绑定预检
 → 后台作业 ZAI_RPT_RUNNER（不变）
 → run_captured：读到 REPORT_KIND = FUNC → ZCL_AI_RFC_EXEC=>run
 → 写 ZAI_RPT_RESULT（不变）→ poll / 结果读取 / 登记结果索引（不变）
```

### 4.2 `ZCL_AI_RFC_EXEC=>run` 的步骤

1. 复核：函数在 `TFDIR` 里存在；登记活动、开放执行、函数名和运行记录一致；运行属于作业用户（后两项 `run_captured` 已有）。
2. 权限：`S_RFC`（RFC_TYPE = FUNC 按函数名，或 FUGR 按函数组，ACTVT = 16），任一通过即可。本地调用 SAP 不会自动查这个权限，这里主动查（D2）。
3. 建参数：按 `FUPARAREF-STRUCTURE` 用 `CREATE DATA … TYPE (名称)` 建数据对象，TABLES 用 `TYPE STANDARD TABLE OF (名称)`。输入值按字典转换：日期、数字，以及转换例程（料号、订单号这类 ALPHA 补前导零，否则会查不到）。范围表按 `build_seltab` 同一口径：逗号多值 → EQ，范围 → BT，含 `*` → CP。
4. `COMMIT WORK`：先把运行器自己的写入提交掉，第 6 步只撤回函数的改动。
5. `CALL FUNCTION lv_fm PARAMETER-TABLE lt_ptab EXCEPTION-TABLE lt_etab`。例外表 = 登记的例外 + `ERROR_MESSAGE` + `OTHERS`，外面包 `TRY … CATCH cx_sy_dyn_call_error`。
   - 注意：参数表是调用方视角，函数的 IMPORTING 要用 `abap_func_exporting` 传，EXPORTING 用 `abap_func_importing` 取，容易写反。
6. **`ROLLBACK WORK`**：立刻撤回函数里没提交的数据库改动，以及它登记的更新任务。标准 BAPI 自己不提交，写入要等 COMMIT 才落库，所以即使误登记了写入 BAPI，这一步也能让它写不进去。函数内部自己 `COMMIT WORK` 的撤不回，这就是 §3.4 要在登记时拦的原因。
7. 取主结果：列 = 行结构的平层字段，标题取字典字段文本（`get_ddic_field_list`，登录语言），取不到用字段名；行 = `/ui2/cl_json=>serialize( compress = abap_false )`，和 ALV 采集同一口径，最多存 20000 行。其他输出（单值、结构、RETURN 消息）放进元数据行的 `outputs` 和 `note`。
8. RETURN（BAPIRET2 / BAPIRETURN 类）里有 E / A 消息：主结果为空 → FAILED，原因取第一条消息；有数据 → READY，`note` 里写明有错误消息。
9. 写 `ZAI_RPT_RESULT` 并 `COMMIT WORK AND WAIT`，记一步 `ZAI_RPT_STEP`（PHASE = CALL）。

### 4.3 失败怎么显示

| 情况 | 结果 | 前端步骤条看到的话 |
|---|---|---|
| 函数抛例外（sy-subrc ≠ 0） | FAILED | 「函数返回例外 NOT_FOUND」+ 消息文本（如果有） |
| 函数里 `MESSAGE TYPE 'E'` | FAILED | 消息原文（`ERROR_MESSAGE` 接住） |
| 参数类型对不上（`CX_SY_DYN_CALL_*`） | FAILED | 「参数 X 和函数接口不一致，函数接口可能改过，请重新登记」 |
| 函数 dump | 作业取消 → FAILED | 现有 `abort_reason` 读作业日志第一条 A / E 消息 |
| 没有 S_RFC 权限 | FAILED | 「没有函数 X 的调用权限（S_RFC）」 |
| 0 行 | READY | 和报表一样，0 行是有效结果 |

### 4.4 为什么走后台作业，不同步调用

- 轮询、超时、中止原因、步骤条都是现成的。
- 函数跑得久也不会卡住网关请求；函数 dump 只中止作业，不连累网关会话。
- 能用报表执行的用户本来就有作业释放权限。
- 代价是多一个作业调度周期，通常几秒。
- 以后要更快时，再加同步模式（`EXEC_MODE = SYNC`）：做一个远程启用的通用函数 `Z_AI_RFC_RUN`，用 `DESTINATION 'NONE'` 在新会话里跑，做法和 `Z_AI_ODATA_GET` 一样。

## 5. 代码分析：按函数名读源码和接口

- `ZCL_AI_CODE_PROVIDER`：`detect_objtype` 先查 `TFDIR`，命中就当函数模块处理。由 `TFDIR-PNAME` / `INCLUDE` 拼出 `L<函数组>U<nn>`，只返回这一个函数。输出 = 接口摘要（参数、类型、选填 / 必填、默认值、例外）+ 函数本体源码。
- `ZCL_AI_AGENT_SERVICE`：`read_program_source` 的说明里写上「也可以给函数模块名」；名字合法性检查不变。Z / Y 开头的限制保留（D4）。
- 这一块和执行没有依赖，可以先上（§8 第 1 批）。

- 参数卡、运行卡、结果表、图表、组合分析：不改。

每批改 ABAP 前后跑 `npm run test:abap`。

## 9. 安全底线

1. 只能调用登记过、活动、开放执行的函数；函数名只来自登记表，不来自用户或模型。
2. 只有管理员能登记；写入类函数登记时拦截（§3.4）。
3. 报表授权（`ZAI_RPT_ACL`）照常生效；`S_RFC` 按当前用户检查（D2）；函数自己的权限检查照常生效。
4. 调用后立刻 `ROLLBACK WORK`，撤回函数没提交的改动（§4.2 第 6 步）。
5. 在后台作业里跑，函数出错不影响网关会话。

## 10. 需要你定的事

| # | 问题 | 建议 |
|---|---|---|
| D1 | 第一个要接的函数是哪个？ | 选一个只读、带表输出的函数做验证样例（Z 函数或 `BAPI_*_GETLIST` / `GETDETAIL` 类） |
| D2 | 是否检查 `S_RFC` | 检查，做成开关 `RFC_AUTH_CHECK`（默认开）。符合「助手里能做的不能比 SAP 里多」；但普通用户可能没有 Z 函数组的 S_RFC，要补角色时可以先关 |
| D3 | 源码命中「提交 / 写库 / 异步写入」时，管理员能否强制登记 | 不能。只有函数名误判可以强制 |
| D4 | 代码分析要不要放开读 SAP 标准函数源码（只读） | 暂不放开，保持只读 Z / Y |
| D5 | 是否只允许远程启用（RFC）的函数 | 不限制。接口不支持的，扫描时会拦下 |

## 11. 风险

| 风险 | 处置 |
|---|---|
| `FUPARAREF` / `FUNCT` 列名按印象写 | 第 2 批开工前先在 SE11 核对，回填本文 |
| 输入值不转换会查不到（料号前导零等） | §4.2 第 3 步按字典转换例程处理；第 2 批验证时专门测 |
| 函数接口改了，旧登记失效 | 执行时报「请重新登记」（§4.3）；重新登记 = 换新配置版本，可回滚 |
| 写入类检查有漏网（只扫函数本体） | 管理员确认 + 调用后 `ROLLBACK WORK` 两道兜底 |
| 结果很大 | 和报表一样最多存 20000 行，超出的在 `note` 里说明 |
