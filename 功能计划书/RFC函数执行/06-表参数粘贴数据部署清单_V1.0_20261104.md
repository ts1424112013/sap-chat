## 3. 手工改法（前几批没上时）

- **REPORT_SERVICE**：
  1. 把 `METHOD parse_flat_kv. … ENDMETHOD.` 整段换成仓库版。
  2. `validate_params` 里 `DATA(lv_val) = COND string( … ).` 后面插入仓库版 `" V1.0.17: 函数表参数` 那一段（`IF ls_p-sel_kind = 'T'.` 到对应 `ENDIF.`，约 30 行）。
  3. 其余不动。
- **DPC_EXT**：在 `WHEN 'STARTREPORTRUN'.` 里，把 `iv_params_json = v8_param( … 'ParamsJson' )` 换成先取到 `lv_srun_pj`、`@@ZAI_TEXT:` 开头时 `resolve_text`，再传 `iv_params_json = lv_srun_pj`（仓库版 4 行）。

## 4. 激活 / 运行时可能遇到的

| 现象 | 原因 / 处置 |
|---|---|
| `get_included_view` / `included_view` 不认识 | 7.50 的 `CL_ABAP_STRUCTDESCR` 有这个方法；真报错告诉我，改成 `get_components` 手工展开 include |
| `cl_abap_conv_in_ce=>uccp` 报类型不符 | 改成先赋给 `c LENGTH 4` 变量（仓库版已是）；仍报错告诉我 |
| 表参数登记不上，预览写「结构 / 表里有嵌套表等复杂字段」 | 行结构里有表、引用或字符串以外的深类型，一期不支持 |
| TABLES 表没出现在参数卡 | TABLES 表默认当输出：名字不是 `IT_` / `I_` / `IN_` / `INPUT_` / `T_IN` 开头的，在 `ZAI_RPT_REG`「当输入的TABLES表」里点名后重新登记 |
| 提交后步骤条写「函数调用预检失败: 参数 … 第 n 行 …」 | 某一格转换不了（日期格式、数字、长度）。按提示改数据重新粘贴 |
| 粘贴很多行提交时报「内容太长…后端还没有部署长文本通道（ChatTexts）」 | 长文本通道没上（10.21 那批），或 DPC 没加 §3 的 4 行 |

## 5. 现场验证

找一个有表参数（或必填结构）的只读 Z 函数。

| # | 操作 | 预期 |
|---|---|---|
| 1 | `ZAI_RPT_REG` 扫描预览这个函数 | 表参数一行写「表参数（N 列），参数卡粘贴数据」；结构写「粘贴一行」 |
| 2 | 写入登记，报表执行里执行它 | 参数卡上是粘贴框，上方列出「列：物料 MATNR、工厂 WERKS…」 |
| 3 | 从 Excel 复制带标题（中文或字段名都行，顺序随意）的几行粘进去 | 下方预览表对上字段，「共 N 行」；没对上的列标出来不提交 |
| 4 | 不带标题粘贴 | 按列顺序对应，预览写「按列顺序对应」 |
| 5 | 提交执行 | 作业跑完，结果和在 SE37 里手工填表的一样；物料号自动补前导零 |
| 6 | 故意粘一个错的日期 / 数字 | 步骤条写「第 n 行 字段: 原因」，不进后台作业 |
| 7 | 粘 500 行以上提交 | 能提交（走长文本通道），结果正确 |
| 8 | 数据分析里问这个函数能答的问题 | 有必填表参数的函数不在可调用清单里（一期限制）；只有选填表参数的照常可调，表参数不传 |
| 9 | 之前登记的、没有表参数的函数 / 报表执行一次 | 行为不变（参数快照解析换了实现，结果口径相同） |
