# Agent「边跑边看」—— 接口约定与后端改造 V0.2（20261028）

> V0.1：接口约定 + 前端 / 演示；V0.2：后端代码完成（第 5 节）+ 部署步骤（第 7 节），均未部署 SAP

## 1. 目标

Agent 回复返回之前，思考卡里一步步显示真实过程，而不是每 3 秒轮换的固定文案（「正在理解问题 → 正在规划…」）：

- 模型调工具前的一句话（协议里本来就有的 `summary`）
- 工具名、关键参数、结果行数与耗时
- 前几行结果预览、已校验的 SQL（可展开）
- 被拒后自动修正的原因

## 2. 现状与原因

- `ZCL_AI_AGENT_SERVICE=>analyze_agent` 是同步循环：一个 HTTP 请求里最多跑 `AGENT_MAX_ROUNDS` 轮；每一步先追加到内存表 `lt_trace`，全部跑完才 `save_audit` 写 `ZAI_AGENT_RUN / ZAI_AGENT_STEP` 并 `COMMIT WORK`，前端等待期间拿不到任何步骤。
- 模型每轮的 `summary` 目前只在最终回答时用作 COMPOSING 的标签，调工具前的那句没有记下来。

## 4. 接口约定：函数导入 `AgentProgress`

- HTTP 方法：GET；返回类型：现有 GenericResult（`Success / Message / ResultJson`）
- 参数：`ClientRequestId`（Edm.String，32 位，前端本轮发送 `AnalyzeTask` 时带的同一个值）
- 只返回本人发起的运行（按 `UNAME` 过滤），别人的编号一律 `NONE`
- `ResultJson`：

```json
{
  "status": "RUNNING | DONE | NONE",
  "steps": [
    {
      "seq": 1,
      "phase": "UNDERSTANDING | SKILL | PLANNING | TOOL_DECISION | NOTE | EXECUTING | COMPOSING",
      "label": "按物料类型统计",
      "toolLabel": "数据分析查询",
      "tool": "sap_data_analysis",
      "args": [["表", "MARA"], ["分组", "物料类型"]],
      "status": "RUNNING | OK | REJECTED | ERROR | DENIED",
      "elapsedMs": 640,
      "rows": 5,
      "detail": "SELECT …（仅 run_sql / 数据分析的已校验语句）",
      "preview": { "columns": ["物料类型", "数量"], "rows": [["FERT", 128], ["ROH", 86], ["HALB", 52]] }
    }
  ]
}
```

- `NOTE`：模型调工具前的一句话（`summary`，经 `ZCL_AI_AGENT_GUARD=>sanitize_summary` 清洗），`status` 恒为 OK
- `TOOL_DECISION` 前端不显示，可以照写
- `preview` 最多 3 行、5 列；只放本人有权限查到的数据；不放思维链、Prompt、密钥

## 5. 后端改造（代码已完成，未部署）

| 对象 | 版本 | 改动 |
|---|---|---|
| `ZAI_AGENT_PROG`（新表） | — | 进度表，见 7.1 |
| `ZCL_AI_AGENT_PROGRESS`（新类） | V1.0 | `start / sync / finish / read`；写全部走独立连接 `R/3*AI_PROG` + `COMMIT CONNECTION`，包在 `TRY … CATCH cx_root`，失败只关掉本次进度；`read` 只返回 `UNAME = sy-uname` 的行；`plan_running / kv_running / preview_of` 生成占位与预览；`ZAI_CHAT_CFG-AGENT_PROGRESS = OFF` 时不记 |
| `ZCL_AI_AGENT_SERVICE` | V15.6 | `analyze_agent` 新增可选参数 `iv_request_id`；挂点 `start` 1 / `sync` 7 / `finish` 2（见下）；Trace、审计、回答口径不变 |
| `ZCL_ZAI_CHAT_DPC_EXT` | V15.9 | `ANALYZETASK` 把 `ClientRequestId` 传给 `iv_request_id`；新增 `WHEN 'AGENTPROGRESS'` → GenericResult |

**挂点（`analyze_agent`）**

1. 技能解析之后：`start( iv_request_id )`（写运行头 `SEQ = 0 = RUNNING`，顺手删 2 天前的行）
2. 每轮 `lv_round + 1` 之后、调模型之前：`sync`（已走完的 Trace + 本轮占位「规划步骤 / 根据结果决定下一步」）
3. 数据分析：`execute_plan` 前 `sync`（模型那句话 `NOTE` + 查询占位，表作参数小标签）；查询完 `sync`（每条查询一步，带前 3 行 × 5 列预览）
4. 扁平参数工具：参数校验通过后 `sync`（`NOTE` + 工具占位，校验后的参数作小标签；`sql / purpose` 不放）
5. 结构化分析调用前：`sync`（占位「生成结构化分析」）
6. 收口（序列化 `trace_json` 前）：`sync` + `finish`（收掉占位，运行头置 `DONE`）
7. `finish_det`（报表选择 / 参数卡等确定性应答）：`sync` + `finish`

**占位规则**：占位写成 `RUNNING`；下一次 `sync` 时第一条新 Trace 行原地接替（同一 `SEQ`，工具行保留占位的参数小标签）；没有新行就按完成收口（耗时 = 占位开始到现在）。

**静态检查**：`npm run test:abap` 第 [8] 组 16 项（只用独立连接写、不碰主事务、TRY 包裹、只读本人、挂点数量与位置、DPC 参数名与前端一致）。

## 6. 风险与核对

- 独立连接提交：755 支持 `CONNECTION` 子句；核对 Gateway 请求内使用不报错、主事务回滚时进度行仍在（预期如此，进度只用于展示）。
- 轮询负载：每个进行中的 Agent 请求每秒 1 次轻量 SELECT；同一用户的轮询与主请求并发，各占一个对话进程（主请求本来就占着）。
- 部署前：`npm run test:abap`；部署后核对：发一个数据分析问题，回复返回前思考卡出现步骤；后端没部署 `AgentProgress` 时页面表现与现在一致。

## 7. 部署步骤

### 7.1 SE11 建表 `ZAI_AGENT_PROG`

| 字段 | 键 | 类型 | 说明 |
|---|---|---|---|
| `MANDT` | ✓ | `MANDT` | 集团 |
| `RUN_ID` | ✓ | `CHAR 32`（可用数据元素 `SYSUUID_C32`） | = 前端 ClientRequestId |
| `SEQ` | ✓ | `INT4` | 0 = 运行头，其余一步一行 |
| `UNAME` |  | `SYUNAME` | 发起人（`read` 只返回本人） |
| `STEP_JSON` |  | `STRING` | 单步 JSON；运行头存 `RUNNING / DONE` |
| `CHANGED_AT` |  | `TIMESTAMP` | 清理用（保留 2 天） |

交付类 A；技术设置：数据类 APPL1、大小类 0、不缓冲。激活。

5. 重贴 `ZCL_ZAI_CHAT_DPC_EXT`（V15.9），核对 ★ 标记：有 `WHEN 'AGENTPROGRESS'` 与 `iv_request_id = lv_at_rid`

### 7.3 验收

1. 浏览器打开 `…/ZAI_CHAT_SRV/$metadata`，能搜到 `AgentProgress`
2. 数据分析场景问「统计一下物料类型分布」：回复返回前思考卡里依次出现 规划步骤 → 模型那句话 → 数据分析查询（进行中 → N 行，带预览）→ 整理回答；完成后点「已完成」能展开同一份步骤
3. 同时 SE16 看 `ZAI_AGENT_PROG`：本次 `RUN_ID` 有 `SEQ = 0` 的 `DONE` 行和若干步骤行
4. 换一个用户用同一个 ClientRequestId 调 `AgentProgress`：返回 `NONE`
5. `ZAI_CHAT_CFG` 加 `AGENT_PROGRESS = OFF`：表里不再写，页面退回阶段文案，回答不受影响
