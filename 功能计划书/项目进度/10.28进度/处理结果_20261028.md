## 二、原因

- 前 4 轮每轮都只要 1~2 秒，第 5 轮却用了 109.7 秒，说明模型在写很长的输出，基本可以判断它在写最终回答。
- 当时代码分析场景的规则要求按「功能概述 → 数据结构 → 业务逻辑 → 问题与建议」四段来写，还要附修改示例。这样写出来的回答很容易超过模型单次输出上限：`ZAI_MODEL_CFG` 里 `MAX_TOKENS` 没维护的话，默认是 4096。
- 超过上限，回答就会被截断，回答外层的 JSON 结构不完整，系统于是报「缺少 action 字段」。
- 修复轮只提示了「格式不对」，模型重写时还是同样的长度，第二次又失败，系统就终止了。已经写出来的回答被整段丢掉。
- 另外，模型是从第 1 行开始每次读 400 行、一段段往下翻的。报错文案在第 1290 行，读到第 4 段才看到，这时已经有 1600 行源码堆在上下文里。

这次没法 100% 确定，因为模型的原始输出没有记录下来。改动之后，每次格式出错都会把原因、是否被截断、输出的开头 160 字记成一个步骤，下次可以直接看到。

## 五、顺带回答记录里的业务问题

报错写在 `FORM post_document` 第 1290 行，触发过程是：
1. 创建工单确认（带 101 收货）之后，程序循环等收货凭证号，默认 25 次，每秒一次。
2. 等到最后还没有凭证号，并且该工厂 `ZIDPMMCTRLVALUE` 的 `CWO_NO_COGI` 开着，就调 `BAPI_PRODORDCONF_CANCEL` 把确认取消。
3. 取消成功后，写入这句报错。

所以这句报错的意思是：收货没在 25 秒内生成凭证，程序已经自动撤销了确认。

收货为什么没生成，这支程序没有记下来：它只看凭证号，没有读 `BAPI_PRODORDCONF_GETDETAIL` 返回的 `failedgmoves`。确认又已经被撤销，COGI 里多半也查不到了。可以这样查：
- 对同一张工单手工做一次收货（CO11N 或 MIGO 101），看具体报什么错；
- 查 SM13 有没有更新失败；
- 如果只是过账慢、超过了 25 秒，重新做一次通常就能成功。

## 六、记录 #02：用技能做工单分析，SQL 几乎都执行失败（2026-10-28 晚）

**现象**：在公司电脑用技能分析工单（例如「工单 131002 目前的在制数量」），模型写的 SQL 几乎都执行不了；查简单的表却正常。

**原因**

1. **主因：超过 200 个字符的 SQL 会被截掉一段。** 执行器把模型的 SQL 放进一段临时生成的 ABAP 程序编译执行。这个程序每行最多 200 个字符，但切分 SQL 时按 230 个字符一段切，每段第 201~230 个字符被静默丢掉，编译必然失败。查单表的 SQL 短，不受影响；工单分析要连 AUFK、AFKO、AFPO、JEST、TJ02T 等多张表，很容易超过 200 字符。用一条 310 字符的「工单 + 状态」查询模拟：第一行丢掉了 ` J~INACT = ' ' LEFT OUTER JOIN`。报错只附生成程序前 200 个字符，模型看不出被截断，反复改写直到 5 次 `run_sql` 用完。`ZAI_SQL_LOG` 记的是截断前的完整 SQL，所以日志里看 SQL 本身「差不多是对的」。这个问题从 10-05 的版本就有，本地 Mock 不经过 ABAP 生成程序，所以一直没测出来。
2. 模型写 `a.aufnr`（点号）时，护栏报的是「只允许单条 SELECT（检测到语句分隔符）」，模型看不出要改成 `~`。
3. 工单号在库里是 12 位、带前导零（131002 存成 `000000131002`），`describe_table` 没提示这一点，`AUFNR = '131002'` 查出 0 行。
4. 技能要算完成率，ABAP SQL 的 `/` 不能用于数量字段；通用 SQL 的 `CURRENT_DATE`、`DATEDIFF`、`LIMIT`、`IFNULL` 等也不支持。
5. 技能没有「在制数量」口径；一张工单有多条状态，连 JEST 后再 SUM 会重复累计（不报错，但数字翻倍）。

**改了什么**：`ZCL_AI_SQL_EXECUTOR` V1.3（每行 ≤ 180 字符、只在常量外断行、报错带出错行）、`ZCL_AI_SQL_GUARD` V1.2.3（常见写法给出改法）、`ZCL_AI_DDIC_TOOLS` V1.3（标出需补前导零的字段）、`ZCL_AI_DOMAIN_CARDS` V1.4（DATA 域卡补规则），以及技能「生产工单进度」正文。本地 Mock 的 `run_sql` 同步加上同样的写法校验。

**验证**：`npm run test:abap` 157 项全过（新增第 [11] 组 10 项，用改动前的源码跑有 9 项失败）；协议测试新增场景 15 共 17 项（写法校验 14 项、断行 3 项），共 153 项全过；其余离线测试全过；断行逻辑另用 JS 模拟了 6 种边界情况。ABAP 语法与运行以 SAP 激活为准。
