## ② 建 SICF 节点 `/sap/bc/zai_agent`（5 分钟）

1. 事务码 **SICF** → 直接执行（F8）。
2. 展开 `default_host` → `sap` → `bc`，在 **bc** 上右键「新建子元素」，名字 `zai_agent`，选**独立服务**。
3. 「服务数据」页签：说明随便填（如「灵犀新引擎」）；**登录数据与灵犀 BSP 应用一致**（标准登录）。**不要填服务用户**——必须是登录用户本人，权限按 `sy-uname` 判断。
4. 「处理程序列表」页签：第一行填 `ZCL_AI_AGENT_HTTP`。
5. 保存，选传输请求。
6. 树上 `zai_agent` 右键 →「**激活服务**」。

**验证**：在 SAP 上打开的灵犀页面（已登录）按 F12，控制台执行：

```js
fetch("/sap/bc/zai_agent/run/start",{method:"POST"}).then(r=>r.text()).then(console.log)
```

- 返回「缺少 X-Lingxi-Agent 请求头」→ 通了。
- 还是 404 → 节点位置不对（不在 `/sap/bc/` 下）或没激活。
- 经 Web Dispatcher 总是 403「请求来源与本系统不一致」→ 确认 Web Dispatcher 转发了 `Host` 或 `X-Forwarded-Host`。

> 建节点只往 SAP 的 ICF 配置表里记一条服务定义，不写业务数据。新引擎每次提问会在 `ZAI_BRUN` 插 1 行、结束时写 `ZAI_BSTEP` 和会话，都是灵犀自己的 Z 表。

## ③ 维护开关 `ZAI_CHAT_CFG`

| 键 | 值 | 说明 |
|---|---|---|
| `BROWSER_AGENT_ON` | `X` | **必填**。不填会提示「浏览器 Agent 未开启」 |
| `BROWSER_AGENT_USERS` | 自己的账号，逗号分隔 | 试点名单；空 = 所有已开通用户 |
| `BROWSER_ADT_ON` | `X`（可选） | ADT 代码工具（〇-AN），默认关 |
| `BROWSER_ADT_USERS` | 账号（可选） | ADT 试点名单 |
| `BROWSER_ADT_SQL` | `X`（可选） | IT 经 ADT 自由 SQL（〇-AQ），默认关 |

其余（`BRUN_MAX_MODEL` / `BRUN_MAX_TOOL` / `BRUN_CTX_TOKENS` / `BRUN_MAX_SKILLS` 等）不填用默认值。

## ⑤ 验收

1. **新引擎能跑**：HTTPS 打开灵犀 → Agent → 问「工单相关的表有哪些」：过程里有「计划」「查表」，有回答；SE16 `ZAI_BRUN` 有一行 `STATUS = OK`。
2. **选文件夹**：选一个本地文件夹，问「这个文件夹里有什么」。
3. **读 Excel**（〇-AT）：文件夹里放一个 .xlsx（比如需求文档），问「看看 xxx.xlsx 里写了什么」：能说出内容，合并单元格、图片位置也能提到。.xls 会提示另存为 .xlsx。
4. **读 Word**：放一个 .docx，问它的要点。
5. **新建 Excel / Word**：让它「把刚才的结果整理成 Excel」「写一份 Word 报告」：先弹确认框（框里能看到内容），点应用后文件出现在文件夹里。
6. **用 Office 打开生成的文件**（★ 必做，本机没验证过）：.xlsx 用 Excel、.docx 用 Word 打开，**看有没有「修复」提示**；有的话截图带回。
7. **报表结果存 Excel**：跑一张报表后说「把结果存成 Excel」：生成 .xlsx，数量列能求和，料号前导 0 还在。
8. **撤回**：文件夹菜单里撤回上一步，新建的文件被删掉。

## 本地开发（localhost）的已知问题

SICF 建好后，`npm start` 本地访问新引擎大概率报 403「请求来源与本系统不一致」：浏览器报的来源是 `localhost:8080`，本地代理把主机名改成了开发机，SAP 的防跨站检查对不上。**SAP 上直接打开不受影响。** 修法是本地代理 `local-middleware/zui5-simple-proxy/lib/proxy.js` 加一行转发 `X-Forwarded-Host`（只影响本地，还没改，需要时说一声）。
