# 新引擎多报表联合分析方案 V1.0

> 日期：2026-11-12 ｜ 状态：首批功能已写入仓库，待 QAS 激活和联调 ｜ 适用：灵犀新引擎

首批支持同一会话里按单列或多列关联报表，默认保留主报表行，也可选择只保留匹配行。联合结果可供后续查询，也可用单字段关联 SAP 数据表，再对补充后的结果做统计。首批遇到重复键、空键或来源截断会提示调整报表条件。追加报表、查表复合键和查表结果独立留存仍是后续项。

QAS 先激活 `ZCL_AI_COMBO_SERVICE`，再激活 `ZCL_AI_RESULT_LOOKUP`、`ZCL_AI_AGENT_SERVICE` 和 `ZCL_AI_AGENT_HTTP`。沿用 `COMBO_ENABLED` 与 `TASK_CONTEXT_ENABLED`，需要筛选汇总时检查 `RESULT_QUERY_ENABLED`，需要查表补字段时检查 `RPT_TABLE_LOOKUP` 与现有 SQL 及表权限。用于联合分析的自开发报表需已登记、可执行且开启 `ANALYZE_ENABLED`。

新增报表继续用现有报表登记入口。优先维护清楚报表名称、用途、选择参数和授权。用于联合分析的报表还要确认每行代表什么、哪些字段能唯一关联，以及日期和单位口径。目录变大时，新引擎按问题相关度选取报表，点名事务码仍可直接查登记信息。

## 1. 业务范围

用户可以在一个对话里指定两份或多份已登记的自开发报表，按共同字段对比或汇总，也可以用 SAP 数据表给报表结果补字段，再按补充后的字段统计。例如，用库存报表和未清采购报表按「物料 + 工厂」核对缺口，再从物料主数据补物料组。报表仍用 SAP 程序自己的取数逻辑，执行参数由用户确认。

后端读取已保存的结果并计算，模型传结果编号、关联字段和统计口径，收到汇总、覆盖范围和少量示例。最终结果卡可继续筛选和追问。大批量下载按[查表导出方案](../查表导出/01-查表结果直接存文件方案_V1.0_20261112.md)处理，明细下载的 10 万行分流规则不用于判定汇总能否计算。

## 2. 当前可复用的能力

| 场景 | 仓库现状 | 新引擎缺口 |
|---|---|---|
| 已登记自开发报表 | `open_report` 出参数卡，`prefill_report` 可以把已有报表的一列带进下一张报表的参数，用户提交后执行 | 把多份执行结果交给同一次对话里的分析 |
| 报表 + 报表 | `ZCL_AI_COMBO_SERVICE` 支持追加和按键关联，来源可以是 SAP 报表或 Fiori 结果，默认最多 6 份，每份默认最多读取 2 万行。现有组合分析入口会打开新的组合会话 | 新引擎对话内缺少直接组合的工具。现有 `query_result` 只认 `REPORT_RESULT` 和 `FIORI_RESULT` |
| 报表 + 数据表 | `lookup_by_result` 从已保存的报表结果提取关联值，再到授权表批量查字段，默认最多 5000 个关联值。当前调用可直接筛选和汇总 | 结果未登记为可继续引用的产物。现有查表入口按单列关联，物料 + 工厂这类复合键需扩展 |
| 多份报表 + 数据表 | 组合和批量查表分别已有实现 | 让查表入口能接受联合分析结果，并把查回的结果登记给下一步用。任意 SQL 查询结果作为独立来源放到后续评估 |

以上为仓库代码核对。通用 ALV 采集当前最多存 2 万行，Fiori 等来源还受各自配置限制。组合结果默认最多保存 5 万行，组合服务可以在截断保存前做汇总，但计算范围仍受来源采集和读取上限约束。QAS 需要核对实际配置和启用状态。

## 3. 第一版怎么做

1. **选择来源。** 复用 `list_results` 读取当前会话可用结果。若报表尚未执行，继续用现有参数卡，执行完成后回到同一个会话。来源有多次运行或关联字段有歧义时，先让用户确认。
2. **组合报表。** 为新引擎加一个后端组合入口，复用现有组合服务，在当前会话登记结果。支持同口径报表追加，或按一列及多列关联。对比库存和采购时，先按物料、工厂和适用单位汇总各自的数量，再把结果对齐，避免同一物料的多笔订单把库存重复计入。现有组合实现会对非主来源重复键自动求和并取首个非空文本，第一版需先校验键和指标，遇到未明确口径的重复键应提示确认。
3. **查表补字段。** 先复用单键 `lookup_by_result`，登记查表结果，使后续追问可以复用同一份数据。需要工厂级属性时支持「物料 + 工厂」复合键，并保留未匹配记录和数量。多个匹配值按明确的业务条件处理。联合结果查询和读取沿用本人、当前会话、来源报表授权及数据表权限校验，保留来源编号、运行参数和数据时间。
4. **生成统计和结果卡。** 后端返回每份来源的总行数、已保存行数、实际参与计算的行数及匹配情况。已知有截断时，允许在用户接受后分析已保存数据，并注明覆盖范围。需要全量结论时，优先缩小业务范围或让 SAP 按正确口径先汇总，再关联汇总结果。结果卡注明明细是否完整，以及汇总是否覆盖参与计算的所有行。

## 4. 问题记录核对

| 记录 | 核对结果和处理建议 |
|---|---|
| #01 SQL 次数耗尽与 detail 校验失败 | SQL 次数按本次运行累计，默认 5、最高 10。模型收到次数用尽后应停止重试当前 SQL 通道。受控查询的 `detail` 规则要求 `dimensions` 为空，工具说明应给出合法示例。200 行是模型预览限制，批量导出和后端汇总各有自己的上限。 |
| #02 物料表关联并存本地 | 独立记录导出路径。记录中的约 9.5 万条是 ABG1 工厂范围的 MARC 口径，不能据此确认所有工厂也在 10 万行以内。全工厂应按实际关联和过滤条件计算行数。 |
| #03 新引擎 504 | 截图记录显示错误前已经有表格返回，后续哪个请求超时仍需查日志。按同一次运行的时间和请求标识核对 nginx 与上游日志，并将 504 网关的整页 HTML 转为简短提示。 |
| #04 中间表格占回答区 | 新引擎已有工具调用和数据集的对应关系，可用于在过程步骤中折叠预览。最终交付的数据集需显式指定，再放进回答区，避免探索查询的中间表跟着铺开。 |
| #05 能力目录覆盖更多表 | 仓库用 `get_capabilities` 和 `gc_allow_tables` 构建目录，现有常量仅是动态追加部分。新增表适合通过可维护的清单按需登记，执行时按表校验权限并限制可见字段。目录扩展独立评估，不作为首批已授权报表和查表场景的前置条件。 |
| #06、#07、#08 配置问题 | `SQL_MAX_EXEC` 管自由 SQL 次数。`SQL_ANALYSIS_ENABLED` 配合用户 SQL 授权控制自由 SQL 等入口。受控查询 `sap_data_analysis` 使用自己的能力目录。仓库中「当前支持 MARA」的固定报错文案应按实际目录更新。线上配置值待查。 |

来源：[20261112 问题记录](../项目进度/11.12进度/20261112问题记录.docx)。

## 5. QAS 验收顺序

1. **复用验证。** 选两张已登记的自开发报表，以及一张有权限的物料表。在现有入口验证报表组合和单键补字段，拿一组 SAP 可人工核对的数量作对照。确认登记、结果留存行数和权限实际配置。
2. **同会话联合分析。** 在新引擎跑「两份报表按物料 + 工厂核对」，随后在同一会话补物料属性并追问。核对合计、重复键、缺失匹配、前导零和单位，验证用户刷新后可继续引用，换用户不能读取来源。
3. **验证大数据边界。** 测试来源截断和来源端汇总两种情况。前者明确参与行数，后者和 SAP 汇总值一致。分别测试 10 万行和 10 万零 1 行的明细导出分流，Web GUI 可访问已由小风确认，具体报表跳转和下载仍需在 QAS 验证。
