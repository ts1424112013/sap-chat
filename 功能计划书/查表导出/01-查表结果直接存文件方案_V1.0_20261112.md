# 查表结果直接存文件 —— 方案 V1.0

> 日期：2026-11-12 ｜ 状态：**方案，未开发**；11-12 补充 §6 备选方案（Web GUI + 通用 ALV 报表） ｜ 适用：新引擎（浏览器 Agent，需用户已授权文件夹）
> 起因：11-12 测试「把 MARA + MARC 全部物料（约 9.5 万条）导出 Excel」，模型答复做不到。

---

## 1. 问题

用户的需求很直接：既然灵犀能查 SAP 表，就应该能把几张表关联起来，把结果整份存到本地。

模型答复「做不到」，原因确实存在，但都是**工具设计上的限制**，不是 SAP 的限制：

| 环节 | 现状 | 代码位置 |
|---|---|---|
| `adt_run_sql`（IT 查表） | 一次最多取 1000 行，给模型看前 200 行 | `agent-bundle/src/adt-client.js` `SQL_MAX_ROWS / SQL_LLM_ROWS` |
| `run_sql`（SAP 执行器） | 后端拼 `UP TO n ROWS`，默认 5000、硬上限 5 万（`SQL_MAX_ROWS`） | `ZCL_AI_SQL_EXECUTOR` / `ZCL_AI_SQL_GUARD=>read_max_rows` |
| `create_excel_file` | 表格内容由模型自己写进参数，9.5 万行不可能 | `agent-bundle/src/index.js` |
| `save_result_to_folder` | **SAP → 浏览器 → 文件，不经过模型**；但只认报表结果（`REPORT_RESULT / FIORI_RESULT`），默认 2 万行 | `browser_export` / `ZCL_AI_RESULT_QUERY=>load` |

结论：「不经过模型、直接落文件」的通道已经有了（`save_result_to_folder`），只是入口只开给报表结果。**缺的是一个「SQL → 文件」的入口。**

## 2. 思路

模型只负责**写 SQL**（可以多表 JOIN），**数据从 SAP 分页取回，浏览器边取边写进文件**，模型只拿到「存了多少行、几列、前几行样例」。

```
模型：export_sql_to_folder(sql, file_path)
  │
  ├─ 浏览器：确认卡（SQL 原文 + 预计行数 + 文件名）→ 用户点「导出」
  │
  ├─ 循环：POST /tools/sql_export { run_id, sql, page }  ──►  SAP
  │        SAP：运行号核对 → ZCL_AI_SQL_GUARD 校验（同 run_sql）
  │             → 执行器 ORDER BY … UP TO n ROWS OFFSET m
  │             → 返回这一页的 CSV 文本 + 是否还有下一页
  │        浏览器：追加写进文件（createWritable 流式写），进度条「35,000 / 95,000 行」
  │
  └─ 返回给模型：已保存 /导出/物料主数据.csv，95,123 行 × 48 列，前 5 行：…
```

### 2.1 为什么不「先存成结果，再用 save_result_to_folder 导出」

也可以做：SQL 结果先存成一份 `SQL_RESULT`，再复用现有导出。但：
- 9.5 万行要在 SAP 里**多存一份**（结果表），用完就成垃圾数据；
- 一次性装进 ABAP 内表，600 列 × 9.5 万行内存吃不消；
- 现有导出链路的上限是 2 万 / 10 万行，还得一起放大。

分页直出不落库、内存按页走、上限单独配，所以**推荐分页直出**。`run_sql` 原有「查 + 界面出表格」的行为不变。

### 2.2 分页怎么做

- 系统 755（ABAP Platform 2020）支持 ABAP SQL `UP TO n ROWS OFFSET m`（7.51 起），要求带 `ORDER BY`。
- 导出模式下守卫额外要求：
  - **必须有 `ORDER BY`**（提示词里教模型按主键排，如 `ORDER BY a~matnr, c~werks`），没有就拒绝并说明；
  - **不允许 `UNION`**（执行器 V1.4 起 UNION 不能带 `UP TO`，分页做不了）；
  - GROUP BY 汇总结果同样可以分页导出，不另做限制。
- 每页行数按列数自动算：`页行数 = min(SQL_EXPORT_PAGE, 50 万 ÷ 列数)`，600 列时每页约 800 行，50 列时每页 5000 行。
- 第一页前先跑一次 `SELECT COUNT(*)`（同 FROM / WHERE），用于确认卡上的「预计行数」和超上限时提前拒绝。
- 分页期间数据可能有变动（新增物料会让后面的页错一行）。导出物料、库存这类数据可以接受，确认卡和结果里注明「按导出时刻分页读取」。

### 2.3 CSV 还是 Excel

| 格式 | 做法 | 上限 |
|---|---|---|
| **CSV（默认）** | 每页追加写，浏览器内存只保留一页 | 只受 `SQL_EXPORT_ROWS` 限制 |
| **Excel（.xlsx）** | 浏览器先收齐全部页，再用现有 `buildXlsx` 生成 | **单元格数 ≤ `SQL_EXPORT_XLSX_CELLS`（默认 300 万）**，且行数 ≤ 1,048,576 |

超过 Excel 上限时**不静默截断**，直接告诉模型「请改存 .csv，或减少列」。
参考：9.5 万行 × 600 列 ≈ 5700 万单元格，只能存 CSV（估计 150 ~ 300 MB）；9.5 万行 × 30 列 ≈ 285 万单元格，可以存 Excel。

## 3. 安全

整表导出主数据属于数据外流，比「查几行看看」风险高，按更严的口径做：

1. **单独授权**：`ZCL_AI_ACCESS` 加一项「允许导出查表数据」，默认关；管理员按人开。没开的人看不到这个工具。
2. **守卫照旧**：只读单条 SELECT、敏感表黑名单、表权限（`ZCL_AI_SQL_GUARD`），每一页都校验，不信任浏览器传来的「已校验」。
3. **数据权限照旧**：SQL 以用户本人身份在 SAP 执行，和 `run_sql` 一样。
4. **行数上限**：`SQL_EXPORT_ROWS` 默认 20 万，硬上限 100 万；`COUNT(*)` 超上限直接拒绝，不导半份。
5. **审计**：每次导出在 `ZAI_SQL_LOG` 记一条（用户、SQL 全文、行数、列数、文件名、开始 / 结束时间、是否中途取消）；整次导出只算 **1 次工具调用**，分页请求凭运行号 + 导出号放行。
6. **用户确认**：写文件前确认卡显示 SQL 原文、预计行数、文件路径（和现有写文件确认同一套）。

## 4. 改动清单

### SAP（ABAP）

| 对象 | 改动 |
|---|---|
| `ZCL_AI_SQL_GUARD` | 新增导出模式校验：要求 ORDER BY、禁 UNION；新 `read_export_rows` |
| `ZCL_AI_SQL_EXECUTOR` | 新方法 `execute_page( sql, offset, page_rows )` → 列定义 + CSV 文本；新方法 `count_rows( sql )` |
| `ZCL_AI_AGENT_SERVICE` | `browser_start` 按授权下发 `export_sql_to_folder`；新 PUBLIC `browser_sql_export`（运行号核对、首页计数与上限、写 / 更新审计） |
| `ZCL_AI_AGENT_HTTP` | 新路由 `/tools/sql_export` |
| `ZCL_AI_ACCESS` | 新权限项「导出查表数据」 |
| `ZAI_SQL_LOG` | 视现有字段，补 `EXPORT_ID / ROWS / COLS / FILE_PATH / STATUS` |
| `ZAI_CHAT_CFG` | 新配置：`SQL_EXPORT_ROWS`（20 万）、`SQL_EXPORT_PAGE`（5000）、`SQL_EXPORT_XLSX_CELLS`（300 万） |

### 新引擎（agent-bundle）

| 文件 | 改动 |
|---|---|
| `src/sap-client.js` | `sqlExport({ runId, sql, exportId, page })` |
| `src/index.js` | 新工具 `export_sql_to_folder(sql, file_path, purpose)`；提示词：先用 `run_sql` / `adt_run_sql` 小样确认字段和口径，再导出；要全量明细时用它，不要自己拼表格 |
| `src/folder-backend.js` | 新 `openAppend(path)`：返回可分段写入的句柄（`createWritable` 流式写），取消时关闭并标「未完成」 |
| `src/step-summary.js` | 导出步骤显示进度和最终行列数 |

### 界面

- 确认卡：SQL 原文（可折叠）、预计行数、格式、文件路径。
- 运行过程：进度条 + 取消按钮；取消后文件保留，名字后加「_未完成」。

## 6. 备选方案：Web GUI + 通用 ALV 报表（11-12 补充）

SAP Web GUI（`/sap/bc/gui/sap/its/webgui`）可以用，所以多一条路：**灵犀只负责写 SQL 和把用户带过去，导出交给 SAP 标准 ALV。**

### 6.1 流程

1. 模型写好 JOIN SQL，调新工具 `open_sql_in_webgui(sql, purpose)`。
2. SAP 按现有 `ZCL_AI_SQL_GUARD` 校验（只读、敏感表、表权限），通过后在 `ZAI_SQL_LOG`（或新表 `ZAI_SQL_EXP`）登记，返回**导出号**。
3. 灵犀回答里出「在 Web GUI 打开」按钮：
   `/sap/bc/gui/sap/its/webgui?~transaction=*ZAI_SQLX P_ID=<导出号>;DYNP_OKCODE=ONLI`
4. 通用报表 `ZAI_SQL_EXPORT`（事务码 `ZAI_SQLX`）按导出号取 SQL，**再校验一次**（必须本人登记、未过期），执行后用 ALV 显示全部结果。
5. 用户在 ALV 里「导出 → 电子表格」，浏览器下载到本地。

### 6.2 和主方案对比

| | 主方案：分页直出到文件夹 | 备选：Web GUI + ALV |
|---|---|---|
| 开发量 | SAP 分页接口 + 引擎工具 + 流式写文件 + 进度 / 取消 | 1 个 Z 报表 + 1 个登记接口 + 1 个按钮，**少很多** |
| 导出方式 | 灵犀写文件 | SAP 标准 ALV 导出，用户熟悉 |
| 权限 | 新权限项（`ZCL_AI_ACCESS`） | 事务码 `S_TCODE` 授权即可 |
| 文件位置 | 授权文件夹，模型能接着读 | 用户下载目录，模型不知道 |
| 大数据量 | 内存按页走，600 列也能存 CSV | 全部结果一次进 ALV 内存；30 ~ 80 列可行，**600 列 × 9.5 万行可能内存溢出或 Web GUI 超时** |
| 适用引擎 | 只有新引擎 | 新旧引擎都能用 |

### 6.3 注意点

- 报表里执行 SQL 复用 `ZCL_AI_SQL_EXECUTOR` 的生成方式；行数上限单独配 `SQL_WEBGUI_ROWS`（默认 20 万）。
- 导出号只允许登记人打开，设有效期（如 24 小时），防止链接转发给别人后被打开。
- ALV 列标题用字段说明，料号等保留前导零（按文本输出）。
- SAP 会话里打开 Web GUI 一般不用再次登录（同一 SSO / Cookie）；QAS 上要确认。

### 6.4 验证（QAS，开发前）

1. `~transaction=*事务码 参数名=值;DYNP_OKCODE=ONLI` 这种写法能否带参数直接运行报表；
2. 9.5 万行 × 30 列在 Web GUI 的 ALV 显示与导出 Excel 的耗时；
3. 从灵犀页面跳 Web GUI 是否需要重新登录。

### 6.5 定位

作为**备选**：主方案开发前、或主方案不可用（未授权文件夹、旧引擎）时使用；也可以作为主方案 M0 之前的快速可用版本。
