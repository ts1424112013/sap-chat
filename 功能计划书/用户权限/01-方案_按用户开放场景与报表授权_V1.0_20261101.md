# 按用户开放场景与报表授权：方案

版本：V1.1；编写日期：2026-11-01（Asia/Shanghai）。V1.1（同日）：「自动」改为所有人可用，里面只用开放的能力（§2.1）。代码已在仓库里，**还没上 SAP**。部署步骤见《02-部署清单》。

## 1. 要解决的事

| # | 需求 | 做法 |
|---|---|---|
| 1 | 普通用户（USER）看不到「设置」和「权限审批」 | 「权限审批」原来就只给管理员。左下角齿轮改成只给管理员；普通用户那里换成「退出登录」按钮（点了先确认） |
| 2 | Agent 下四个场景按后台表开放给用户 | `ZAI_CHAT_USER` 加字段 `AGENT_SCENES`；前端只显示开放的场景，后端按会话场景拦截 |
| 3 | 报表按用户授权，没授权的看不到 | 新表 `ZAI_RPT_ACL`（一行 = 一张报表给一个用户）；开关 `RPT_ACL_ENABLED`；目录、执行、取数、模型选报表、组合分析五处后端拦截 |

## 2. 场景

- 字段：`ZAI_CHAT_USER-AGENT_SCENES`（CHAR 40），逗号分隔，取值 `REPORT` / `FIORI` / `DATA` / `CODE`。
- 规则：
  - 空 = 四个全开，现有用户不受影响。四个都勾时也存空，以后加新场景时这些用户自动拥有。
  - 管理员不看这个字段，永远全开。
  - 「自动」**所有开通的用户都能用**（V1.1），但里面只用该用户开放的能力，见 §2.1。
  - 旧的「库存查询」会话按数据分析判断。
- 前端：登录返回 `Scenes`，场景选择条只画开放的场景。新建任务默认用上次的场景；那个场景没开放时，改用第一个开放的。对话页「建议转到 Agent 某场景」也不会推荐没开放的场景。
- 后端：`ZCL_AI_AGENT_SERVICE` V15.11 在会话归属校验后、选技能和模型前做检查，返回 `DENIED` 并说明原因。绕过前端直接调接口也会被拦。

### 2.1 「自动」里的能力收窄（V1.1）

「自动」按每句话判断用什么，实际只会走到两类能力：报表执行（问题里有"执行 + TCode"）和数据分析（点名某张表、或数据类关键词，带 SQL / 库存工具）。代码分析和 Fiori 报表在「自动」里本来就走不到。

| 用户情况 | 在「自动」里 | 结果 |
|---|---|---|
| 没开报表执行 | 说"执行 ZXXX" | 回答"这个问题需要用到「报表执行」，这个能力没有开放给你，「自动」里也不能用" |
| 没开数据分析 | 点名某张表 / 某个物料 | 同上，说明「数据分析」没开放 |
| 没开数据分析 | 没点名对象的数据类问题（如"统计一下…"） | 按普通问题回答，不带 SQL / 库存工具 |
| 开了报表执行 | 说"执行 C" | 照样核报表授权，没授权就拒 |
| 任何人 | 普通问题 | 照常回答 |

后端在 `ZCL_AI_AGENT_SERVICE` V15.12 里做：选工具域时把 DATA / INVENTORY 降成 GENERAL；意图路由后按上表拦截。组合分析会话也是「自动」，现在不需要单独放行。

## 3. 报表授权

### 3.1 表 `ZAI_RPT_ACL`

| USERID | SRC_TYPE | REPORT_ID | 含义 |
|---|---|---|---|
| USER1 | REPORT | A | 1 用户能用报表执行 A |
| USER1 | REPORT | B | 1 用户能用报表执行 B |
| USER2 | REPORT | A | 2 用户能用报表执行 A |
| USER2 | REPORT | C | 2 用户能用报表执行 C |
| USER1 | FIORI | SHIPMENT | 1 用户能用 Fiori 报表 SHIPMENT |
| `*` | FIORI | WO_YIELD | 所有人都能用（公共报表） |

- `REPORT_ID` 对报表执行是 `ZAI_RPT_DEF-REPORT_ID`，对 Fiori 是 `ZAI_FRPT_DEF-REPORT_ID`。
- `REPORT_ID = *` 表示这一类报表全部可用。界面上不提供这个选项，需要时可以在 SM30 里手工加。
- 报表执行和 Fiori 的授权互不影响。

### 3.2 开关 `RPT_ACL_ENABLED`

- 不开：保持现状，所有人看全部报表。
- 开了：普通用户只看到分配给自己的报表，加上 `*` 那一行的公共报表；管理员照旧看全部。
- 现场可以先把授权配好，再打开开关。开关放在「设置 → 用户管理」顶部，也可以在 SM30 里改。

### 3.3 后端拦截点

| 位置 | 对象 | 行为 |
|---|---|---|
| 报表执行目录 | `ZCL_AI_REPORT_SERVICE=>list_defs` | 只返回有授权的。Agent 的场景说明也走这里 |
| 报表执行提交 | `ZCL_AI_REPORT_SERVICE=>start_run` | 没授权 → rejected |
| 报表执行按 TCode | `ZCL_AI_AGENT_SERVICE`（出报表卡前） | 回答"你没有报表 … 的使用权限" |
| Fiori 目录 | `ZCL_AI_FIORI_REPORT_SERVICE=>list_defs` | 只返回有授权的 |
| Fiori 取数 / 参数卡 / 重取 | `load_def` | 没授权返回错误 |
| Fiori 一句话找报表 | `find_candidates` | 没授权的不进候选 |
| 组合分析来源 | `ZCL_AI_COMBO_SERVICE` | 没授权的来源整体拒绝，并说明是哪一份 |

不过滤的地方：`get_def` / `get_def_by_tcode` 本身，以及已有结果的重读。结果按本人归属，用户以前取到的数据，收回授权后照样能看。

### 3.4 和 SAP 自身权限的关系

这张表决定的是"能不能在 Lynx 里看到、用到这张报表"。Fiori 取数最终调的是 SAP 标准 OData 服务，报表执行最终是 SUBMIT 程序，SAP 自身的权限检查照旧生效，两层都要过。

## 4. 维护界面（设置 → 用户管理）

- 顶部「按用户限制报表」开关卡（读写 `RPT_ACL_ENABLED`）。
- 表格新增「可用范围」列，显示简述，例如「场景 2/4 · 报表执行 2 · Fiori 2」。点击后打开可用范围弹窗：
  - 四个场景勾选卡，至少保留一个。
  - 「报表执行 / Fiori 报表」两个页签的报表清单，支持搜索、全选、清空，页签上显示已选和总数。
  - 开关没开时会提示"分配会先保存，打开开关后生效"。
  - 管理员行只显示说明，不能编辑。
- 表格末尾多一行「所有人（公共报表）」（USERID = `*`），只能维护公共报表。
- 保存走现有的 `SaveUser`，加了 3 个参数：`Scenes` / `Reports` / `AccessSet`。报表串超过 3000 字符时走长文本通道。
- SEGW 没加这 3 个参数时，前端从 `$metadata` 判断出来，开关卡和「可用范围」列都不显示，原有用户管理不受影响。

## 5. 侧栏

- 管理员：齿轮（设置），和原来一样。
- 普通用户：退出图标，点击后弹出确认框「退出当前账号？」，可以选取消或退出登录。主题切换在顶栏，模型选择在输入框，这两个原来就不在设置里。

## 7. 已验证 / 未验证

- 已验证（演示模式，浏览器实测）：
  - 张三（只开报表执行和 Fiori，报表 A、B，Fiori 两张）：看到两个场景加「自动」；报表执行目录 2 张；Fiori 目录 2 张加 1 张公共报表；输入「执行 C」被拒；数据分析场景被拒；「自动」里点名查表被拒、统计类问题普通回答；没授权的 Fiori 取数被拒。
  - 李四（全开，报表 A、C）：五个场景都有，含「自动」；目录是 A、C。
  - 不刷新页面切换用户，目录跟着刷新。
  - 普通用户侧栏没有设置和权限审批，退出确认可用。
  - 可用范围弹窗浅色和深色都正常。
- 自动测试：前端 151、ABAP 静态 180 全部通过，其余套件不受影响。
- 未验证：ABAP 没在 SAP 上激活；SEGW 参数要现场加；真实后端的用户列表和保存要现场试。
