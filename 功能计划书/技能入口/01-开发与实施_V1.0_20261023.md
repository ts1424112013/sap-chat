# Agent 技能入口开发与实施

创建日期：2026-10-23，最后更新：2026-10-24。版本：V1.0。状态：已编码，待 SAP 激活与真实模型验收。界面依据同目录 `设计稿/index.html` 的八张稿子。

## 1 功能范围

技能是管理员维护的做法卡，包含步骤、业务口径、自查清单和输出要求。用户选择一个具体场景后，可以再选一个技能。技能不会新增执行能力；本次可执行工具是场景白名单与技能工具子集的交集，执行前由 ABAP 再次校验。

已实现输入框技能按钮、搜索、上下键和回车选择、Esc 关闭、输入 `/` 呼出、取消、查看做法、CODE/DATA 首页前三张技能快捷卡、亮暗主题、管理员维护和按技能试跑测评。REPORT/FIORI 保留报表目录，技能只在结果进入模型分析时生效。AUTO 和旧 INVENTORY 场景禁用技能。

一次只能选一个技能。普通对话不使用技能。首版仅 ADMIN 编写，支持 PUBLIC（已开通用户可用）和 ADMIN（仅管理员）两种可见范围。工具留空表示沿用场景原有工具，REPORT/FIORI 原有工具为空。

不包含个人技能、按问题自动推荐、推荐模型自动切换或第三方 Skill 安装。<mark>内置十八个样例（10-27 新增 10 个标准业务流程的数据分析技能，见《04》〇-M）</mark>的编号与正文统一维护在 `webapp/utils/SkillCatalog.js`，SAP 管理页可以一键导入缺少的编号，不覆盖已有技能。

## 3 SE11 三张表

均建透明表，交付类 A，允许维护，保存到可传输包；数据类 APPL0。MANDT 为首键。BODY 使用 STRING，不截成固定 CHAR 或 LCHR。下面字段名须逐字一致。

### 3.1 ZAI_AGENT_SKILL

| 字段 | 类型 | 键 | 含义 |
|---|---|---|---|
| MANDT | CLNT 3 | 是 | 客户端 |
| SKILL_ID | CHAR 32 | 是 | 大写编号，首字母 A–Z，后续字母数字下划线；NONE 保留 |
| NAME | CHAR 60 | | 显示名 |
| DESCR | CHAR 200 | | 一句话说明 |
| SCENES | CHAR 100 | | CODE,DATA,REPORT,FIORI 的逗号分隔子集，不带空格 |
| TOOLS | CHAR 500 | | 工具 ID 的逗号分隔子集，大小写与注册表一致；可空 |
| BODY | STRING | | 做法正文，服务端限 3000 字 |
| PLACEHOLDER | CHAR 200 | | 输入提示 |
| VISIBILITY | CHAR 10 | | PUBLIC 或 ADMIN |
| ACTIVE | CHAR 1 | | X=启用 |
| VERSION | INT4 | | 首次保存为 1，每次保存加一 |
| MAX_ROUNDS | INT4 | | 2–10，不能提高系统预算 |
| CHANGED_BY | CHAR 12 | | 修改人 |
| CHANGED_AT | CHAR 14 | | YYYYMMDDhhmmss，SAP 服务端时间 |

### 3.2 ZAI_SKILL_CTX

| 字段 | 类型 | 键 | 含义 |
|---|---|---|---|
| MANDT | CLNT 3 | 是 | 客户端 |
| SESSION_ID | CHAR 32 | 是 | 会话 |
| TASK_ID | CHAR 32 | 是 | 任务；空值行为会话最近选择 |
| OWNER | CHAR 12 | 是 | SAP 用户 |
| SKILL_ID | CHAR 32 | | 选中技能；NONE=明确取消 |
| SKILL_VER | INT4 | | 上次使用版本 |
| CHANGED_AT | CHAR 14 | | 更新时间 |

### 3.3 ZAI_SKILL_USE

| 字段 | 类型 | 键 | 含义 |
|---|---|---|---|
| MANDT | CLNT 3 | 是 | 客户端 |
| RUN_ID | CHAR 32 | 是 | 对应 ZAI_AGENT_RUN.RUN_ID |
| SESSION_ID | CHAR 32 | | 会话 |
| TASK_ID | CHAR 32 | | 任务 |
| OWNER | CHAR 12 | | SAP 用户 |
| USER_SEQ | INT4 | | 本轮用户消息序号；助理消息为 +1 |
| SKILL_ID | CHAR 32 | | 使用的技能 |
| SKILL_VER | INT4 | | 实际加载版本 |
| SKILL_NAME | CHAR 60 | | 当时显示名 |
| BODY | STRING | | 当时完整做法正文 |
| TOOLS | CHAR 500 | | 当时配置的工具子集 |
| CREATED_AT | CHAR 14 | | 运行时间 |

建议为 USE 建非唯一二级索引 SESSION_ID + OWNER + USER_SEQ。历史查询只回传本人最近 100 个技能运行的名称、版本和序号，用于最近 200 条消息标记，不回传快照正文。审计快照保留策略与现有 ZAI_AGENT_RUN 一起管理。

## 4 SEGW 增量

不增加实体或 ComplexType，复用既有 GenericResult（Success、Message、ResultJson）。两个新 FI 的参数都为 Edm.String，参数为空也由前端发送空串，避免网关把缺参数报成 404。

| FI | 方法 | 参数 | 返回 |
|---|---|---|---|
| SkillList | GET | Scene、SessionId、TaskId、IncludeInactive | GenericResult |
| SkillSave | POST | Payload | GenericResult |
| AnalyzeTask | 既有 POST | 新增 SkillId，Edm.String，允许空值；其余既有参数保留 | 既有 AgentResult |

SkillList 的 IncludeInactive 为 X 时要求 ADMIN；管理页传空 Scene/SessionId/TaskId。普通目录传实际场景、会话和当前任务。ResultJson 返回 enabled、skills、selectedId、uses。enabled 是 SKILL_ENABLED 的实际状态。场景与工具在 JSON 里是逗号分隔字符串，前端转为数组。

SkillSave 的 Payload 为单个技能 JSON，字段为 id/name/description/scenes/tools/body/placeholder/visibility/active/version/maxRounds。首次创建 version=0，更新必须带读取到的 version；并发修改时只允许一个更新成功，另一方得到刷新提示。active 使用 JSON 布尔值。超过 URL 长度阈值时沿用 POST ChatTexts，再以 @@ZAI_TEXT:TextId 发送 Payload；正文只从本人暂存记录读取。SkillSave 不能放进 changeset 批处理。

SkillId 空串表示沿用当前任务选择；NONE 表示取消，不能成为目录中的技能编号。输入已有任务号时后端先验证本人归属。路由最终确认的任务会复制本次选择；下次请求仍重新检查技能启用状态、权限和当前版本。

旧后端没有 AnalyzeTask.SkillId 或 SkillList 时，按钮显示尚未部署说明，普通 Agent 请求继续可用；手工携带了技能的请求会明确失败，不静默回退成无技能回答。

## 5 部署顺序

1. 导入前三节所列三张表并激活，已有表结构不变。保留 SKILL_ENABLED 为空，不开放使用。
2. SE24 创建 ZCL_AI_SKILL_SERVICE，依赖既有 ZCL_AI_TASK_SERVICE、ZCL_AI_TOOL_REGISTRY 和 ZAI_CHAT_USER。
3. SE24 整类覆盖 ZCL_AI_AGENT_SERVICE V15.5。
4. SEGW 创建 SkillList/SkillSave，给 AnalyzeTask 加 SkillId，生成运行时。按现有流程清理 Gateway metadata 缓存。
5. SE24 整类覆盖 ZCL_ZAI_CHAT_DPC_EXT V15.8。它包含此前 V15.7 的 AuthRuleSave.FmapJson；不能覆盖回旧版。
6. SE38 创建 ZAI_TEST_SKILL_CORE，前台执行，末行应为 All 5 checks passed。这个程序不写表，不调用模型。
7. 前端执行本地校验并重新全量构建上传 BSP。新模块和 style-skills.css 必须在产物中。
8. ADMIN 打开设置 → 技能 → 管理技能，点击导入缺少的内置技能，目录应出现八项。关闭总开关时仍允许管理员维护。
9. ZAI_CHAT_CFG 维护 CFGKEY=SKILL_ENABLED、CFGVALUE=X；新开 CODE 任务后验收。
10. 按 SE09/STMS 的原有流程连同三表、三类、测试程序和 SEGW 工件一起传输；目标客户端须导入技能配置或在管理页重新导入内置项，并维护开关。

本功能没有提高角色权限，也不跳过 SQL、源码访问、报表审批或 Fiori 分析闸门。

## 6 验收

| 项目 | 操作 | 期望 |
|---|---|---|
| 入口 | CHAT、AUTO、CODE、DATA、REPORT、FIORI 分别打开 | CHAT 不显示；AUTO 禁用；CODE/DATA 有快捷技能；报表目录保留 |
| 选择 | 搜索“解读”，上下键选中，回车确认；Esc 关闭 | 单选，显示名称、版本，输入提示替换 |
| 斜杠 | 输入 /，选择技能，再输入问题 | 斜杠不会作为问题发送；正常问题中间的 / 不触发 |
| 取消 | 选中后点 ×，发送追问，再刷新 | 请求 SkillId=NONE，下一轮不沿用；旧消息技能标记保留 |
| 任务与会话 | 两个会话选不同技能，来回切换并刷新 | 不串会话；服务端按本人和任务保存 |
| 权限 | USER 调 SkillSave 或 IncludeInactive=X；指定 ADMIN 技能 | 服务端拒绝，不只依靠前端隐藏 |
| 停用 | 选技能后由另一管理员停用，再发送 | 明确拒绝，提示重新选择；不悄悄使用旧正文 |
| 版本 | 两个管理窗口读取同一版本，分别保存 | 第二个提示版本已变；每次模型运行有实际版本快照 |
| 执行边界 | CODE_EXPLAIN 模型尝试 describe_table 或 run_sql | 执行前拒绝；不会进入源码、SQL 或分析工具分支 |
| 报表阶段 | 选择需求结构技能后执行报表 | 执行参数/作业不变；只有分析已就绪结果时有 SKILL Trace |
| Fiori 阶段 | 选技能，取数后尚未点击交给模型分析 | 数据和技能不提前进入模型；同意分析后生效 |
| 历史 | 有技能的回答后刷新页面 | 用户和助理消息显示当时名称版本；历史读取失败不影响正文 |
| 长正文 | 保存接近 3000 字的做法 | 走 ChatTexts，不因 URL 过长而报 414 |
| 测评 | 保存并启用技能，点用测评用例试跑 | 只选适用场景，每轮携带 SkillId；报告记录选择时版本，实际版本以 Trace/快照为准 |
| 主题与窄屏 | 亮暗主题，手机宽度开弹层/管理页 | 弹层转为对话框后仍能搜索、回车选择，编辑区不横向溢出 |
| 旧后端 | 使用没有新 FI/参数的 metadata | 原有 Agent 可发消息；技能请求不静默降级 |

## 7 回滚和维护

将 SKILL_ENABLED 清空后，新的技能请求会拒绝，用户取消技能后可以继续原有 Agent；管理员仍可维护目录。要完全退回旧代码，恢复本批之前的 Agent/DPC 与前端包；三表可以保留，先不删除运行快照。开关关闭不影响已保存的历史技能标记。

技能更新时以新版本用于后续请求，既有运行快照不会跟着修改。正文通过 UI5 Text/TextArea 当普通文本显示，前端不把它作为 HTML 插入。源码、工具结果和 SQL 权限仍由既有后端护栏决定。
