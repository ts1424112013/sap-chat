## 4. SEGW

两个函数导入的公共设置：Return Type Kind = Complex Type，Return Type = `GenericResult`，Cardinality = 1。参数全部是 `Edm.String`。

| 函数导入 | HTTP Method | 参数 | 说明 |
|---|---|---|---|
| `ComboCreate` | **POST** | `SessionId`（32）、`SpecJson`（不设长度）、`ClientRequestId`（32） | 前端三个参数每次都发 |
| `ComboResult` | GET | `ArtifactId`（32） | |

- `SpecJson` 编码后超过 3000 字符时，前端会先存进 `ChatTexts`（V15.6 的长文本通道），参数里只放 `@@ZAI_TEXT:<编号>`。所以 `ChatTexts` 必须已经部署，现场早已部署。
- 前端靠 `$metadata` 里是否有 `ComboCreate` 来判断显示不显示「交给模型分析」按钮。SEGW 没建之前，按钮不出现，一期功能不受影响。

## 5. 配置（`ZAI_CHAT_CFG`）

| 键 | 建议值 | 说明 |
|---|---|---|
| `COMBO_ENABLED` | `X` | 总开关。不开时，点发送会返回"能力未开启" |
| `COMBO_SRC_MAX_ROWS` | 不写，默认 20000 | 单份来源最多读多少行（100～100000） |
| `COMBO_MAX_ROWS` | 不写，默认 50000 | 组合结果最多存多少行，统计按全部行算（1000～200000） |
| `COMBO_MAX_SOURCES` | 不写，默认 6 | 最多几份来源（2～10），跟面板上限一致 |
| `COMBO_MODEL_ROWS` | 不写，默认 200 | 组合后不超过这个行数时，把全部明细发给模型 |
| `COMBO_MODEL_GROUPS` | 不写，默认 50 | 分组汇总最多多少组，其余合并成「其他」 |
| `COMBO_MODEL_EDGE` | 不写，默认 10 | 明细举例：最大、最小各取几行 |
| `COMBO_MODEL_CHARS` | 不写，默认 30000 | 发给模型的组合上下文字符上限 |

还依赖已有开关 `TASK_CONTEXT_ENABLED = X`。组合结果要挂在任务上，任务层没开时，后端会如实提示。

所有键都不超过 20 字符，`npm run test:abap` 第 1 项会检查。

## 6. 现场验证

按顺序做，每一步都对照"应看到"一栏：

| # | 操作 | 应看到 |
|---|---|---|
| 1 | 打开右侧「组合分析」面板，加入两份**报表执行**结果，或一份报表执行 + 一份 Fiori 结果；两份都要来自开放了模型分析的报表 | 面板底部出现「交给模型分析」按钮。报表执行那份会提示"只取回 N 行样例（后端共 M 行）" |
| 2 | 选关联，确认关联列，点「交给模型分析」 | 弹出确认卡：组合方式、来源（页面行数 / 后端总行数）、汇总维度两个下拉 |
| 3 | 点「发送」 | 按钮变成"正在组合…"。几秒后切到新会话「组合分析：A × B」：第一条是组合结果卡，卡下有来源清单；接着自动发出分析问题，模型开始回答 |
| 4 | SE16 看 `ZAI_COMBO_RUN` | 有一行：`ROW_COUNT` 是**后端全量**组合后的行数，不是页面样例行数；`SUMMARY_JSON` 里有 `stats`、`group`、`edge`、`note` |
| 5 | SE16 看 `ZAI_ARTIFACT` | 多一行 `ARTIFACT_TYPE = COMBO_RESULT`，`SESSION_ID` 是新会话 |
| 6 | 在新会话里追问，例如"哪个工厂金额最大" | 照常带着组合数据回答，不会转去查表或执行报表 |
| 7 | 刷新页面，重新打开这个会话 | 组合结果卡按原位置恢复 |
| 8 | 加一份**没开放模型分析**的报表结果再发送 | 确认卡上出现黄色提示"第 N 份「…」不能使用：报表 … 未开放模型分析"，不建会话 |
| 9 | 把 `COMBO_ENABLED` 清空再发送 | 提示"能力未开启(COMBO_ENABLED)" |
| 10 | 两份各约 2 万行的结果做关联（如果现场有这么大的报表） | 记下耗时（`ZAI_COMBO_RUN-ELAPSED_MS`）。超过 30 秒就调低 `COMBO_SRC_MAX_ROWS`，并反馈过来 |

## 7. 回退

- 只关功能：清空 `COMBO_ENABLED`。前端按钮还在，点了会提示能力未开启。
- 完全回退：重贴上一版 `AGENT_SERVICE`（V15.8）和 `DPC_EXT`（V15.9），SEGW 删掉两个函数导入，然后 Generate。前端按钮会自动消失。
- 两张新表和新类可以留着，不影响别的功能。

## 8. 可能遇到的问题

| 现象 | 可能原因 | 处置 |
|---|---|---|
| 激活 COMBO 类报 `ZAI_COMBO_RUN` 未知 / 字段 `LABEL_TEXT` 不存在 | 表没激活，或字段名建成了 `LABEL` / `MODE` | 按 §2 的字段名重建 |
| 点发送提示 "Invalid Function Import Parameter 'SpecJson'" | SEGW 参数名拼错，或没 Generate | 参数名区分大小写，按 §4 核对 |
| 点发送提示"长文本 … 不存在或已失效" | 组合说明走了长文本通道，但重试时复用了旧编号 | 再点一次发送即可，前端每次都会重新暂存 |
| 新会话里模型说"要分析的组合结果当前不可读取" | 结果不属于当前会话（例如手动改过会话），或 `COMBO_ENABLED` 被关 | 回面板重新发送 |
| 组合结果行数和页面预览不一样 | **这是正常的**：后端在全部存储行上算，页面预览只用了已取回的行 | 以组合结果卡为准 |
