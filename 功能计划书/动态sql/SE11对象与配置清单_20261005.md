# 动态 SQL：SE11/SE24 对象与配置清单（激活必读）

更新：2026-10-05。代码已完成并核查；本文档是在 SAP 中落地所需的全部对象定义。

## 1. SE11 新建表：ZAI_SQL_LOG（SQL 审计）

ZCL_AI_SQL_EXECUTOR 用**动态写入**（字段按名字匹配，缺字段只跳过、不报错），
但表建成下表结构后审计才真正生效。交付环境/包：与现有 Z 对象同包。

| 字段 | 类型 | 长度 | 说明 |
|---|---|---|---|
| QUERY_ID（主键） | CHAR | 40 | `SQL`+时间戳+用户名 |
| USERNAME | CHAR | 12 | 执行人 sy-uname |
| SQL_TEXT | STRING | — | 执行的 SQL（超 4000 截断） |
| STATUS | CHAR | 10 | OK / ERROR / REJECTED |
| RESULT_ROWS | INT4 | — | 返回行数 |
| ERROR_MSG | STRING | — | 报错/拒绝原因 |
| SESSION_ID | CHAR | 40 | 所属会话 |
| CREATED_AT | CHAR | 14 | YYYYMMDDhhmmss |

技术设置：数据类 APPL0，大小分类 0，允许表维护可选（日志表建议关）。
主键仅 QUERY_ID。

## 2. SE11 可选扩展：ZAI_CHAT_USER 加 SQL_ALLOWED

- 字段：`SQL_ALLOWED`，CHAR 1。
- 不加也能运行：`ZCL_AI_SQL_GUARD=>is_active_user` 用 ASSIGN COMPONENT
  动态读取，字段不存在时视为不限制（仅校验 `userid + active='X'`）。
- 加上后：只有勾选 `X` 的用户能通过 SQL 工具的开关校验。第一阶段建议
  给你的 IT 账号勾上，其他人不勾。

注意：zai_chat_user 的登录 ID 字段是 **USERID**（sy-uname），
USERNAME 是显示姓名，二者不要混用。

## 3. ZAI_CHAT_CFG 配置键（SM30/SE16 维护）

| CFGKEY | 建议值 | 说明 |
|---|---|---|
| SQL_ANALYSIS_ENABLED | X | 动态 SQL 总开关（不开则三个 SQL 工具全部返回"未开启"） |
| SQL_MAX_ROWS | 5000 | 单条 SQL 取回行数（硬上限 50000，写在 GUARD 常量） |
| SQL_MAX_EXEC | 5 | 单次 Agent 请求最多执行 run_sql 次数（上限 10） |

已有键 AGENT_MAX_ROUNDS / AGENT_BUDGET_SEC 不用配：代码默认已改为
10 轮 / 180 秒（V14）；如配置表里有旧值（如 4 / 60）会覆盖默认值，
需要删掉或改成 10 / 180。

SEGW/OData 无需改动。前端 `npm run build` 后按现有 BSP 部署。

## 5. 激活后快速验证

1. 开关不开时：Agent 问"统计一下销售订单"→ 模型调 run_sql 应收到
   "SQL 分析功能未开启"。
2. 打开开关：`search_tables 关键词=销售订单` → 应返回 VBAK/VBAP 等。
3. `describe_table 表名=VBAK` → 字段清单。
4. `run_sql`：`SELECT VBELN, NETWR, WAERK FROM VBAK WHERE ERDAT >= '20260101'`
   → 数据集返回。
5. 故意写 `DELETE FROM VBAK WHERE VBELN = '1'` → 应被拒绝并计入审计。
6. 故意查 `SELECT * FROM USR02` → 应被"受保护表"拒绝（审计记 REJECTED）。
7. SE16 查 ZAI_SQL_LOG 应看到以上每条记录。
