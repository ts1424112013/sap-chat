# backend-abap 对象清单与部署顺序（2026-10-19，10-20 更新为合并部署版）

SAP 上目前运行的是 **2026-10-13 的代码**（10.11 的 A+B+C 三批已随它上线，见 [00_对象清单与部署顺序_20261011.md](00_对象清单与部署顺序_20261011.md)）。本文是 10-13 之后全部改动的**一次合并部署**手册（小风 10-19 决定：三项新功能写完后与 bug 修复一起部署）。照第三节的步骤从上往下做即可。

本目录仍是后端 ABAP 源码的唯一事实源；文件都是累积版本（例如 `ZCL_AI_AGENT_SERVICE.abap` 现在是 V15.4，已经包含 V15.2.1 / V15.3，只贴一次）。

## 四、配置项（`ZAI_CHAT_CFG`）

| 键 | 默认（不建这一行时） | 含义 |
|---|---|---|
| `AUTH_ENABLED` | 空 = 关 | 权限自助申请总开关；关时申请 / 代加 / 审批 / 撤销被拒，配置照常 |
| `FIORI_ENABLED` | 空 = 关 | Fiori 报表总开关；关时目录为空并给说明，取数被拒 |
| `FIORI_MAX_ROWS` | 5000 | 单次落库行数上限（登记的 `maxRows` 可再收紧） |
| `FIORI_MODEL_ROWS` | 200 | 「交给模型分析」时最多给模型的行数（另有 3 万字符上限） |
| `FIORI_TIMEOUT_SEC` | 60 | 单次 OData 调用超时（按 G0 的 T4 调整；同时受 ICM 超时约束） |
| `FIORI_MAX_BYTES` | 20971520 | 响应大小上限（20 MB） |
| `FIORI_MAX_URI` | 2000 | 拼好的 URI 长度上限 |
| `FIORI_HTTP_DEST` | 空 = 内部调用 | G0 的 T2 不通过时填 SM59 目标名 |
| `AGENT_MODELS_FIORI` | 空 = 沿用 `AGENT_MODELS` | Fiori 场景模型白名单（也可在设置 → 模型管理里选） |

bug 修复部分沿用现有键：BE-07 的兜底模型要求白名单里**至少两个启用模型**。

## 附录 SE11 表结构

全部交付类 A、首字段 `MANDT`（类型 `MANDT`，主键）；下表其余字段用"预定义类型"建即可，不用建数据元素。时间统一 `CHAR 14`（YYYYMMDDhhmmss）。技术设置：`*_DEF` / `*_PARAM` / `ZAI_AUTH_TAB` / `FMAP` / `RULE` 数据类 APPL2；`ZAI_AUTH_REQ` / `ZAI_FRPT_RUN` / `ZAI_FRPT_DATA` 数据类 APPL1。
