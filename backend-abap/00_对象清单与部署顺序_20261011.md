# backend-abap 对象清单与部署顺序（2026-10-11）

本目录是后端 ABAP 源码的**唯一事实源**。仓库其他位置的旧副本已清理（`_backup_20261004/backend-abap` 已删除；10.09 进度文件夹里的原始源码已留档在提交 `b9083f5`）。

10-11 共有三批改动，都还没上线，**一起部署**即可（文件是累积版本，C 批已包含 A/B 批的内容）：

- **A 批（10.09 遗留问题修复）**：作业自动启动、对话式结果分析、CSRF 重试、结果表缺列、参数校验等
- **B 批（会话场景 / 对话页纯对话 / Agent 模型白名单）**：Agent 按场景（报表执行 / 数据分析 / 库存查询 / 代码分析 / 自动）收窄意图和工具；对话页不再读 SAP，读源码迁入 Agent「代码分析」；管理员可限制哪些模型能用于 Agent
- **C 批（改进清单 P2 小修）**：工具参数支持 JSON 转义（BE-02）；角色/提示词保存的入参校验与提示词表清理、重命名不再清掉置顶（BE-08）；会话列表分页 + 服务端标题搜索（BE-09）；Agent 工具清单里的参数附格式要求（BE-12）。前端另有：删除当前 Agent 会话后界面复位（FE-05）、死代码清理（FE-07）

## 二、部署步骤（按顺序）

1. **SE24**：`ZCL_AI_REPORT_SERVICE` 和 `ZCL_AI_REPORT_EXEC_SAP` 互相引用 → 两个都贴好后**一起批量激活**。
2. **SE24**：`ZCL_AI_CHAT_SERVICE` → 激活（AGENT_SERVICE 要用它新公开的两个方法；DPC_EXT 要用 `get_sessions` 的新参数）。
   `ZCL_AI_AGENT_GUARD`（C 批）只加了私有方法、公共接口不变，任何时候单独激活都行。
3. **SE24**：`ZCL_AI_DOMAIN_CARDS` → `ZCL_AI_TOOL_REGISTRY` → `ZCL_AI_INTENT_ROUTER` → 依次激活。
4. **SE24**：`ZCL_AI_AGENT_SERVICE` → 激活。
5. **SEGW**（项目 ZAI_CHAT）：函数导入 `AnalyzeTask` → 参数里**新增 `Scene`**（Edm.String，Nullable，与 `FocusedArtifactId` 同样配置）→ Generate Runtime Objects。
6. **SE24**：`ZCL_ZAI_CHAT_DPC_EXT` → 激活（必须在第 4、5 步之后）。
7. **SE38**：`ZRMM_IDP_0702` → 激活（独立，任何时候都行）。
8. 每个对象重贴后，先按文件头的 `★ 重贴后核对标记` 检查一遍再激活。
9. **前端**：`npm run build` → 把 dist 部署到 SAP。

**不需要**：SE11 建表/加字段、新增必填配置。

> 第 5 步没做时也能运行：前端读 metadata 发现没有 `Scene` 参数就不发送，新建的 Agent 会话一律按"自动"处理（和现在一样），只是场景功能不生效。

## 三、配置项（ZAI_CHAT_CFG，全部可选）

| 键 | 作用 | 默认（不配置） |
|---|---|---|
| `AGENT_MODELS` | 全部场景允许用于 Agent 的模型 ID，逗号分隔 | 不限制 |
| `AGENT_MODELS_RPT` / `_DATA` / `_INV` / `_CODE` | 报表执行 / 数据分析 / 库存查询 / 代码分析各自的白名单，配置了就覆盖全局 | 沿用 `AGENT_MODELS` |
| `CHAT_SAP_ACCESS` | `X` = 对话页恢复读取 SAP 对象的旧行为（回退开关） | 对话页不读 SAP |

模型白名单不用进 SM30，管理员在前端「设置 → 模型管理 → Agent 可用模型」里选择保存即可。后端同口径强制校验：手动选了不在白名单里的模型会被明确拒绝，"智能路由"只会在白名单里挑。

## 六、上线后验证

**先跑测评做对比**：前端「设置 → 测评 → 打开 Agent 测评」（仅管理员可见）。**部署前**在现在的线上版本跑一遍"全部"作为基线（这时场景用例会自动跳过），**部署后**再跑一遍，两份「导出报告(MD)」对比通过率、平均轮数和耗时。题库可以「导出题库」后改成你们的真实问题再「导入题库」。

**A 批**
1. 执行 ZDPMM702 → 填参数提交：SM37 里作业**自动**变为已释放/运行中（不用手工释放）；步骤条显示"第 N/100 次查询"；结果表 9 列齐全。
2. 结果出来后说"分析一下这个结果"：过程摘要显示"理解问题(引用报表结果 …)"，回答里的数字来自结果行；不会新建 DATA 任务。追问"哪个工厂 MIH 需求最大"也基于同一份结果。
3. CSRF：激活任意一个类后不刷新页面直接提交报表 → 自动换令牌重试成功。
4. 配置提醒：ZAI_RPT_PARAM 里 ZDPMM702 的 `WERKS_I` 应设 `REQUIRED='X'`；`MODEL_I` 的 `SEL_KIND='S'`，需要多选时设 `MULTI_VALUE='X'`。

**B 批**
5. Agent → 新建任务：输入框上方出现场景选择（默认上次用的）；选「报表执行」后说"执行 ZDPMM702" → 参数卡；说"分析表 ZIDPMM455" → 提示"查表属于「数据分析」场景"，不会执行。
6. 「数据分析」场景：说"分析 ZIDPMM455 的数据分布" → 按表名查（不再当 TCode）；说"执行 ZDPMM702" → 提示去「报表执行」场景。
7. 「代码分析」场景：说"解释 ZDPMM702 的程序逻辑" → 过程摘要出现"读取源码: ZRMM_IDP_0702 第 1-xxx 行"，回答引用行号。用户角色 + 模型勾了"USER 禁看源码"时只给用途说明。
8. 对话页问"ZDPMM702 这个报表是做什么的"：回答不读系统，下方出现"转到 Agent · 代码分析"卡片，点确认 → 新建代码分析会话并自动带上原问题。
9. 设置 → 模型管理 → Agent 可用模型：只勾一个模型保存 → Agent 下拉只剩"智能路由"+该模型；在 SE16 里把 `AGENT_MODELS` 改成别的模型后再用原模型提问 → 后端提示"未开放用于 Agent"。
10. 旧 Agent 会话（场景为空/GENERAL）照常可用，行为和以前一样（"自动"）。

**C 批**
11. 「数据分析」让模型写多行 SQL（例如"按工厂统计 ZIDPMM455，SQL 分多行写"）：过程摘要里展开 SQL，看不到字面 `\n`；`ZAI_SQL_LOG` 里的语句是正常空格。
12. 设置 → 角色管理：删一个角色 → 刷新页面仍是删后的列表，其余角色没有被停用；SE16 看 `ZAI_CHAT_PROMPT`：管理员连续加两次快捷指令后，表里的行数 = 当前快捷指令数（不再每次多出一整套停用行）。
    Gateway 客户端：`POST /SaveRoles?Roles='abc'`（非数组）→ `Success` 空、`Message`"入参不是 JSON 数组…"，`ZAI_CHAT_ROLE` 不变。
13. 置顶一个会话 → 重命名它 → 仍是置顶；取消置顶照常。
    ⚠ 如果 12、13 在 SAP 上**完全不生效**（重命名后标题不变、SE16 里没变化、F12 看到响应 Message 是"会话ID为空"），不是 C 批的问题：前端 `_v8Call` 把这类写操作的参数放在 POST 正文，而网关函数导入可能只读 URL 参数。见改进清单 §4.2 T-07 / FE-08。
14. 会话列表：两种模式各显示最近 50 条，超过时列表末尾出现"加载更早的会话"；搜索框输入关键字能搜到列表里还没加载出来的旧会话。
    Gateway 客户端：`GET /Sessions?$top=2&$skip=1&$filter=Mode eq 'AGENT'&search=zdp` 只返回本人 Agent 会话里标题含 zdp（不分大小写）的第 2、3 条。
15. 「库存查询」场景：说"查一下物料 <料号> 在工厂 <工厂> 10 月 13 日的收发" → 过程摘要里 `get_daily_movement` 一次通过，没有"参数被拒"（REJECTED）行；测评 INVENTORY 的平均轮数不高于部署前（BE-12）。

> C 批前后端兼容：新前端配旧后端时，会话列表退回"前 100 条里按模式/关键字过滤"（和现在一样），重命名仍会清掉置顶；旧前端配新后端时一切照旧，重命名不再清掉置顶。
