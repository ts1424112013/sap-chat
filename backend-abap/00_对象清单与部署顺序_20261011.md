本目录是后端 ABAP 源码的**唯一事实源**。仓库其他位置的旧副本已清理（`_backup_20261004/backend-abap` 已删除；10.09 进度文件夹里的原始源码已留档在提交 `b9083f5`）。

| 顺序 | 对象 | 事务 | 新版本 | 修了什么 |

**激活顺序**

1. 1 和 2 互相引用（EXEC_SAP 用 REPORT_SERVICE 的常量；REPORT_SERVICE 调用 EXEC_SAP）：两个都贴好（都处于未激活状态）后，**一起批量激活**。
2. 然后激活 `ZCL_AI_INTENT_ROUTER` → `ZCL_AI_AGENT_SERVICE` → `ZCL_ZAI_CHAT_DPC_EXT`（AGENT_SERVICE 新增的是可选参数，DPC 必须在它之后激活）。
3. `ZRMM_IDP_0702` 独立，任意时间激活。
4. 每个对象重贴后，按文件头 `★ 重贴后核对标记` 检查一遍再激活。

**本批不需要**：SE11 建表/加字段、SEGW 修改、新增 ZAI_CHAT_CFG 配置项。

**前端**：`webapp/service/ChatService.js`、`webapp/controller/App.controller.js` 有改动 → `npm run build` → 把 dist 部署到 SAP。前端与后端谁先上线都不影响（新字段为空时后端按旧逻辑处理）。

## 四、上线后验证

1. 执行 ZDPMM702 → 填参数提交：SM37 里作业**自动**变为已释放/运行中（不用手工释放）；步骤条显示"第 N/100 次查询"；结果表 9 列齐全（MIH、日期为 0/空的行也有列）。
2. 结果出来后说"分析一下这个结果"：过程摘要显示"理解问题(引用报表结果 …)"，回答里的数字来自那 11 行；不会新建 DATA 任务。
3. 继续追问"哪个工厂 MIH 需求最大"：直接基于同一份结果回答。
4. "执行报表 ZDPMM702" → 出报表参数卡（不再是表分析）；"ZIDPPP099表数据"、"表ZIDPPP099的数据" → 都走表分析。
5. CSRF：激活任意一个类后不刷新页面直接提交报表 → 自动换令牌重试成功。
6. 配置提醒：ZAI_RPT_PARAM 里 ZDPMM702 的 `WERKS_I` 应设 `REQUIRED='X'`（否则不填工厂时程序只提示不查询，结果为 0 行，看起来像"有效空结果"）；`MODEL_I` 的 `SEL_KIND='S'`，需要多选时设 `MULTI_VALUE='X'`。
